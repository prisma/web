## Working conventions that cost time when missed

- prisma/orm worktrees live under `/Users/wmadden/Projects/prisma/orm/.claude/worktrees/`. Make your own. The bot remote there is `bot`. Never rebase or force-push; merge `origin/main` in. After merging main, rebuild the packages whose source changed (for example `pnpm build` in `packages/1-framework/3-tooling/migration`) before typechecking the CLI, or the typecheck reports missing exports.
- `gh pr edit` fails for the bot with a permission error. Use `gh api -X PATCH repos/<owner>/<repo>/pulls/<n> -F body=@<file>`.
- prisma/orm has a merge queue, and a queued branch rejects pushes. The queue runs the integration suites. On prisma/orm#31174 I marked the pull request ready while its checks were still running; end-to-end tests that asserted changed message text failed only in the queue. When a change alters CLI message text, grep `test/integration` for the old text and run those files by name before marking the pull request ready.
- An implementer's claim that "no end-to-end test asserts this text" was wrong once. Check it yourself with grep.
- The review bot (CodeRabbit) posts a new batch of comments after every push. Most of its claims on these two pull requests were true; a few were false and it withdrew them when answered. Verify each against the code; do not apply its suggested fix unread.
- On prisma/orm#31174, six rounds went by in which a fix for one message broke another, because about twenty messages each built their own command. If you change `migrationPlanArguments`, `migrationsToTarget` or `printedWayToTarget`, trace every caller and say which text changed.
- The orchestrating session cannot turn on Auto-fix for a pull request the bot opened; Will does that. Auto-merge can be turned on with `mcp__ccd_pr__set_auto_merge`. Converting a pull request to a draft turns auto-merge off; turn it on again afterwards.
