# Conventions for the orm/data-modeling pages (in addition to conventions.md)

- These are explanation pages, not reference pages: Overview (models, primary keys, scalar fields, relations), Relational data modeling, MongoDB data modeling. Each one answers "how do I describe my data and why this way". Keep the heading order. Do not renumber, rename, or reorder headings; if a heading must change because it contains a banned term, pin the old anchor with `[#old-anchor]`.
- No commentary about the docs inside the docs. Cut sentences such as "This page introduces", "This page shows", "it is what this page focuses on", "the guides cover that in depth". Write the thing itself.
- Never interleave PostgreSQL and MongoDB sentence by sentence. Where both databases matter, give PostgreSQL its own sentences or block and then MongoDB its own. Tabs already on a page stay.
- The word "contract" is the subject of the contract-authoring section, not this one. On first use on a page: "your contract, the `contract.prisma` file that replaced `schema.prisma`". After that, "contract" alone. Do not use "schema" for the contract; "schema" alone means the PostgreSQL schema (`public`).
- "Join table": the model that holds one record per connected pair is "the model for the join table" on first use and "the join model" after. Never "junction", "junction model", "junction table", "junction record".
- Relation fields: "a relation field, typed as the other model" and "the field that stores the other record's primary key" (the foreign key column on SQL, the field holding the `_id` on MongoDB). "Back-relation" and "virtual" only with the plain meaning beside them ("stores nothing in the database").
- `prisma contract emit` is the command that checks the contract. Say "`npx prisma contract emit` rejects it with an error whose `code` is `X`". Never "emit rejects", "the schema compiler", "the emitter lowers", "lowered". Referential actions: "become the foreign key's `ON DELETE` and `ON UPDATE` clauses".
- Banned on these pages in addition to the list: gate / gated; capability in prose; codec; canonical; deterministic; pure; "source of truth"; "escape hatch"; "purpose-built"; "first-class"; "wiring" / "wired"; "hangs off"; "consult"; "authoritative"; "physical" (write "in the database"); "idiomatic" (write "the usual choice" or "what MongoDB expects"); "denormalize" only with its meaning beside it ("keep a small copy of the fields a read needs"); "hot paths" (write "reads that run often"); "opaque"; "polymorphism" as a bare noun (write "a base model with variants"); "lifecycle"; "injected" (write "filled in for you"); "narrow" as a verb for `.variant()` only with "limit the query to one variant" beside it; "at the storage level" (write "in the table"); "rides along"; "lives on" / "lives inside" (write "is on", "is stored inside").
- Types: the scalar table names Prisma types (`String`, `Int`, ...) and says what PostgreSQL column each becomes only where it matters (`Decimal`, `Bytes`, `Json`, `Jsonb`). Type ids such as `pg/text@1` do not belong on these pages. Version references to a pre-release ("before 0.17") do not belong on these pages; say what the type is now.
- Query examples on these pages are short and use the page's own models. The ORM client is `db.orm.public.User` on PostgreSQL and `db.orm.users` on MongoDB (see conventions.md). Link to `/orm/fundamentals/relations-and-joins` for querying; do not restate it.
- "Prompt your coding agent" sections: keep, but the first sentence reads "Projects created with `npm create prisma@latest` include the Prisma ORM skills for your coding agent. In an existing project, run `npx prisma skills sync`." Keep the example prompts.
- The source of truth is prisma/orm at 8.0.0-rc.10 (`cfccb09be2`), exported at `wip/prisma-src/`. rc.11 changed nothing in the contract language, so rc.10 facts hold for rc.11.
- The contract-authoring pages under `/orm/contract-authoring/` (PSL syntax, TypeScript builder, the artifacts) and the CLI pages under `/cli/` are out of scope; link to them, do not restate attribute lists or flags.
