# Slice: the two error references name each other

_(Parent project: the Prisma ORM 8 docs audit, `docs/orm-docs-audit/`; plan in `restructure-plan.md`. Item A8 of `changes.md`.)_

## At a glance

`/orm/reference/error-reference` and `/cli/error-reference` each say they list every code, neither names the other, and both have a `CLI` namespace with different codes in it. A reader who lands on the wrong page from a search result concludes the code is undocumented. Both pages are generated by `apps/docs/scripts/generate-error-reference.mjs` from a canonical file in `prisma/orm` and `prisma/prisma-cli`, and the sync workflow overwrites them daily, so the fix goes in the generator: each page opens by saying which commands it covers, lists its namespaces, and links the other page, and the shared `CLI` namespace is explained on both.

## Chosen design

### The generator (`apps/docs/scripts/generate-error-reference.mjs`)

For each target, the generator already replaces one sentence of the source intro with `hostedIntro`. Extend that:

1. **Scope sentence.** Replace the source sentence "This page lists every published code." on both pages with a target-specific sentence. ORM: "This page lists the codes from the Prisma ORM commands (`contract`, `db`, `migration`, `orm`) and from the runtime and its extensions. The platform commands (`auth`, `project`, `postgres`, `deploy`, and the others) have their own page, [CLI error reference](/cli/error-reference)." CLI: "This page lists the codes from the platform commands (`auth`, `project`, `postgres`, `deploy`, and the others). The Prisma ORM commands (`contract`, `db`, `migration`, `orm`), the runtime, and the extensions have their own page, [Prisma ORM error reference](/orm/reference/error-reference)." If the source sentence is missing, the generator inserts the scope sentence after the first paragraph and prints a warning, so the page never loses the cross-link when upstream rewords its intro.
2. **Namespace list.** After the intro, a line "Namespaces on this page:" followed by the `##` headings of the source, derived at generation time, each linked to its section. The CLI source already carries a "Namespaces:" list; the generator's list replaces it so both pages have the same shape.
3. **The `CLI` namespace.** On both pages, one sentence after the namespace list: "Both pages have a `CLI` namespace. The codes in them are different, and a `CLI.*` code appears on the page of the commands that raise it." Emit it only when the source has a `## CLI` heading.
4. **Frontmatter.** `description` and `metaDescription` for the ORM target say "the Prisma ORM commands, runtime, and extensions"; for the CLI target "the platform commands". Neither says "every".
5. `transform()` stays a pure function of `(target, markdown)`, and `assertMdxSafe` still runs on the source before any insertion.

### The generated pages

Regenerate both pages locally with `--source` pointing at a fresh checkout of each repository's `main` (or `curl` of the raw file), commit the regenerated `.mdx` files with the generator change, and check that `list-error-codes.mjs --verify` from each source repository still passes on the regenerated page, the way `.github/workflows/sync-error-reference-docs.yml` runs it.

### Redirects

`next.config.mjs` redirects `…/error-reference/<CODE>` to `…/error-reference#<CODE>` per page. Nothing changes there.

## Coherence rationale

One generator produces both pages; changing it once fixes both pages and every future sync.

## Scope

**In:** the generator, the two regenerated pages, and a test for `transform()` if the docs app's test runner can load an `.mjs` module (`node --test` with `--import tsx` runs `src/**/*.test.ts`; put the test at `src/lib/generate-error-reference.test.ts` importing the script, or document why not).

**Out:** the canonical files in `prisma/orm` and `prisma/prisma-cli`; merging the pages (the `CLI` namespace collision rules it out, see `prisma-error-reference-sync` in memory and A8); the anchors and redirects.

## Pre-investigated edge cases

| Edge case | Disposition | Notes |
| --- | --- | --- |
| Upstream rewords "This page lists every published code." | Insert the scope sentence after the first paragraph and warn | The cross-link must survive a sync |
| The source has no `## CLI` heading | Omit the collision sentence | Namespaces are read from the source at generation time |
| Regenerated pages differ beyond the intro | Expected when upstream moved since the last sync | Commit what the generator produces from `main`; the daily sync would anyway |

## Slice-specific done conditions

- [ ] Each page's first screen names which commands it covers, links the other page, lists its namespaces, and explains the shared `CLI` namespace.
- [ ] `--verify` from both source repositories passes on the regenerated pages; `lint:links`, `lint:versions`, and `test` pass in `apps/docs`.
- [ ] The intro of each page passes the docs reader review scripts and one cold reader round (the only new prose is the intro).
