# Conventions for the orm/reference pages other than orm-client (in addition to conventions.md)

- These are reference pages. Keep the per-method layout (Remarks, Options, Return type, Examples, PostgreSQL/MongoDB tabs where present). No tutorial prose; a "how do I" question gets one sentence and a link to the fundamentals page, unless the answer is a fact about the method.
- The finished orm-client page (`apps/docs/content/docs/orm/reference/orm-client.mdx` on main) is the model for tone and structure. Reuse its wording for shared ideas: "collection" (the query object you chain on), "the built query" instead of "plan", "an error whose `code` is `X`", "does not exist on MongoDB" instead of "throws TypeError", "TypeScript rejects it, nothing checks at run time".
- Do not renumber, rename, or reorder headings. If a heading must change because it contains a banned term, pin the old anchor with `[#old-anchor]`.
- Banned on these pages in addition to the list: terminal (write "the call that runs the query", or name it: `.build()`, `.all()`), capability-gated / "the adapter reports the X capability" (say "PostgreSQL only" or "available on PostgreSQL; not on SQLite"), codec (say "how the value is stored and read", or name the type id such as `pg/int4@1`), codec inferer, facet, factory, "wired to", execution context, envelope (say "the driver's own result object"), materialize, surface, "source-read from an internal design document" (say "planned, not shipped"), namespace-qualified (show `db.sql.public.user`, and say `public` is the PostgreSQL schema), "auto-parameterized" (say "sent as a query parameter, never pasted into the SQL"), field accessor (say "the `f` argument, one property per column").
- `db.sql.public.user` is keyed by table name (the model name with a lowercase first letter unless `@@map`), which differs from `db.orm.public.User`. Say this once per page where `db.sql` first appears.
- `db.runtime()` is synchronous on PostgreSQL and returns a promise on MongoDB: `(await db.runtime()).query(built)`. State this where `runtime()` first appears on a page.
- Every raw or builder query ends with `.build()` and is then passed to `runtime.query(...)` for rows or `runtime.execute(...)` for a count.
- Type ids such as `pg/int4@1`: "the PostgreSQL type plus a version, always `@1` today". Prefer taking the type from the table: `db.sql.public.user.columns.id`.
- The source of truth is prisma/orm at 8.0.0-rc.10 (`cfccb09be2`), checked out at `wip/prisma-src/`. Where the page names an rc.9 behaviour that rc.10 changed, rc.10 wins.
- The error-reference page is generated from prisma/orm by `apps/docs/scripts/generate-error-reference.mjs` and is out of scope; its wording is fixed upstream.
