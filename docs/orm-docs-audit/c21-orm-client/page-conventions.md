# Conventions for the orm-client reference page (in addition to conventions.md)

- This is a reference page. Keep the per-method layout (Remarks, Options, Return, Examples, PostgreSQL/MongoDB tabs). Do not add tutorial prose; one sentence and a link to the fundamentals page is the most a "how do I" question gets, unless the answer is a fact about the method (an argument, a return value, what happens on no match).
- The page is edited in four slices by four agents at once. Edit only your slice file. Do not renumber or rename headings; if you must rename a heading, pin the old anchor with `[#old-anchor]`.
- Terms defined once, in part 1 (Example schema / Setting up the client), and used bare elsewhere: contract ("your contract, the `contract.prisma` file that replaced `schema.prisma`; `npx prisma contract emit` writes `contract.json` and `contract.d.ts` from it"); `db.orm.public.User` (models by model name; `public` is the PostgreSQL schema); `db.orm.users` (on MongoDB the accessor is the collection name from `@@map`, or the model name with a lowercase first letter); variant ("a model declared with `@@base`, stored with its base model; `variant("Bug")` narrows a collection to that model; the name is the model name"). Parts 2 to 4 may say "see [Example schema](#example-schema)" but must not redefine these.
- Banned on this page in addition to the list: terminal, facet, root name(s), roots map, aggregate map, emitted contract, type-only guard, consumption mode, child-owned/parent-owned (say "the side that holds the foreign key"), filter surface, relation refinement (say "relation filter"), AST node, textual-trait, adapter-registered, "unverified on the current test contract" (say "not tested; try it on a real field before relying on it", or state the fact if the source shows it), "vacuously true", materializing, `float8` as a JavaScript type (say `number`), `$set`/`$setOnInsert`/`$lookup`/`RETURNING`/`LIMIT 1` when the sentence is about what the reader gets rather than how to write a query.
- Every example's ids: declare them once at the top of the Examples block of the section (`const aliceId = "..."`) or replace with a literal. A page that claims examples are transcribed from tests must have examples that run as printed.
- Error codes: "throws an error whose `code` is `X`". Give one string, not two.
- Facts the readers asked for that you must look up in the rc.9 source before writing (do not guess; mark `Q` if not found): whether `create` requires an explicit id or nullable fields; what `conflictOn` takes and whether the value must match `create`; whether PostgreSQL `upsert` needs `where()`; whether `.eq()` on an enum takes the member name or the mapped value; whether `variant()` takes the model name or the discriminator value; whether `some()` takes an object as well as a callback; whether `MongoOrExpr` has `.and()`; `groupBy` with several fields; `orderBy`/`limit` on a grouped collection; `having` by alias; `in([])` behaviour; the full list of MongoDB field operations and the signatures of `push`/`pull`/`addToSet`/`pop`; whether nested `create`/`connect` work on MongoDB; whether `update()` returning `null` can also mean a wrong argument shape (if so, say so plainly); native vs text-backed enums (define both in one sentence each, with the contract syntax).
