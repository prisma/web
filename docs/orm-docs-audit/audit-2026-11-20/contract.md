## Breaks copy-paste

- `orm/contract-authoring/editor-support.mdx:29` — gives `@@index([createdAt(sort: Desc)])` as the MongoDB index form the editor completes — that form was removed in 8.0.0-rc.17; MongoDB PSL now writes `@@index([sort(createdAt, Desc)])`, and `psl-syntax.mdx:713` says so — evidence: `docs/releases/v8.0.0-rc.17.md:88`; `prisma contract emit` on a MongoDB model with `@@index([email(sort: Desc)])` prints `PSL_INVALID_ATTRIBUTE_SYNTAX: Expected one of: field name | wildcard() | sort()`.
- `orm/contract-authoring/editor-support.mdx:11` (also the code block title at 19) — says the contract path in the config `orm init` writes is `prisma/contract.prisma` — `orm init` writes `contract: "./src/prisma/contract.prisma"`, as every other page in this area says — evidence: `npx prisma orm init --yes --target postgres --authoring psl` in an empty folder wrote `src/prisma/contract.prisma` and a config naming it; `packages/1-framework/3-tooling/cli/src/commands/init/templates/code-templates.ts` (`defaultSchemaPath` uses `DEFAULT_CONTRACT_SOURCE_DIR`).

## Misleading

- `orm/data-modeling/index.mdx:150` — "`contract emit` needs its own `Temporal` when such a field has a fixed default, as Default values explains" — the opposite is true, and the linked section says the opposite (`psl-syntax.mdx:305`: "The CLI checks these defaults on Node.js 24 too, which has no built-in `Temporal`"). The control plane loads `temporal-polyfill` itself — evidence: on Node.js 24.13.0 (`node -p "typeof Temporal"` prints `undefined`), a contract with ``DateTime(as: temporal) @default(timestamptz`2024-01-01T00:00:00Z`)`` and ``Date(as: temporal) @default(date`2024-01-01`)`` emits with no polyfill import; `skills/prisma-8/references/contract.md` ("`prisma contract emit`, `prisma db init` and the other commands need no global `Temporal`").
- `orm/contract-authoring/typescript-schema-builder.mdx:536` — "Parity with PSL: TypeScript and PSL authoring produce the same `contract.json` ... so you can move between the two forms" (and line 13: TypeScript is for "the cases PSL does not cover") — the PostgreSQL TypeScript builder cannot write a value object (PSL `type Address {}`) or a base model with variants (`@@discriminator` / `@@base`); its `ContractInput` has no `valueObjects` key and no discriminator or base option, and `@prisma/orm-postgres/contract-builder` exports no `valueObject`. The page's own "complete contract" swaps the PSL `address Address?` for `field.column(type.Jsonb())`. A PSL contract that uses either feature cannot move to TypeScript — evidence: `packages/2-sql-family/2-authoring/contract-ts/src/contract-dsl.ts:2184-2240` (`ContractInput`), `packages/3-targets/postgres/9-facade/src/exports/contract-builder.ts` (export list). The MongoDB builder does have `valueObject` and `discriminator`/`base`.
- `orm/contract-authoring/psl-syntax.mdx:128` — "`npx prisma orm init` writes a config like this", above a config that imports `definePrismaConfig` from `"prisma/config"` — `orm init` writes `import { definePrismaConfig } from '@prisma/cli-engine';` (and `the-contract-artifact.mdx:120-127` shows a `db.ts` importing `./contract.d`, while `orm init` writes `./contract.d.js`). Both config imports work with `npx prisma`, but the file a reader opens does not match the page; `create-prisma` 0.14.8 does write `prisma/config` — evidence: scaffold output of `npx prisma orm init --yes --target postgres --authoring psl`; `packages/1-framework/3-tooling/cli/src/commands/init/templates/code-templates.ts` (`configFile`, `dbFile`); `create-prisma/templates/create/_shared/prisma.config.ts.hbs`.
- `orm/contract-authoring/the-contract-artifact.mdx:37` — "`storageHash` covers the storage layout: tables, columns, primary keys, uniques, indexes, foreign keys, and the allowed values of each enum" — since 8.0.0-rc.22 value objects are storage entries, so changing one changes the storage hash (as `psl-syntax.mdx:562` says), and check constraints, RLS policies, roles and declared extensions are in `storage` too — evidence: `docs/releases/v8.0.0-rc.22.md` ("Value objects are storage entities ... changing a value object changes the storage hash"); emitted `contract.json` for the PSL page's complete contract has `storage.namespaces.public.entries` keys `table`, `valueObject`, `valueSet`.
- `orm/data-modeling/index.mdx:17` — "Prisma ORM 8 supports PostgreSQL and MongoDB today, and Supported databases lists the ones that are coming" — the linked page lists SQLite (experimental), MySQL and MariaDB (early preview) as available now, and `psl-syntax.mdx:274` and `relational-databases.mdx:178` document SQLite syntax — evidence: `orm/supported-databases.mdx:11-21`; `docs/releases/v8.0.0-rc.21.md` (MySQL packages), `v8.0.0-rc.24.md` (MariaDB).
- `orm/contract-authoring/typescript-schema-builder.mdx:150` and `orm/supported-databases.mdx:39` disagree — this page says extension packs work on MongoDB (`defineContract({ ..., extensions })`, `mongo({ contract, url, extensions: [myPack] })`), the supported-databases table says MongoDB extensions are "Not yet". The source supports packs on MongoDB since rc.23 — evidence: `docs/releases/v8.0.0-rc.23.md` ("`mongo()` and `mongoStatic()` ... take an `extensions` option").
- `cli/contract-emit.mdx:35` — "for each extension pack ... its files under `migrations/<pack>/`: its contract, its head ref and its migrations" — the pack's contract snapshot is written to `migrations/snapshots/<hash>/` (`contract.json`, `contract.d.ts`); only the head ref and migrations go under `migrations/<pack>/` — evidence: `prisma contract emit` with `extensions: [pgvector]` printed `space pgvector: .../migrations/snapshots/e4ab7d43.../` and `.../migrations/pgvector/refs/head.json` plus five migration folders.
- `cli/contract-emit.mdx:108-132` — the `--json` result is shown as the full line ("formatted for reading"), but it leaves out `executionHash` and `pinnedFiles`, which every result carries — evidence: `npx prisma contract emit --json` result has keys `ok, storageHash, executionHash, profileHash, outDir, files, pinnedFiles, timings`.
- `cli/contract-infer.mdx:32` — example writes `--output ./prisma/contract.prisma`; every other page and the command's own help use `./src/prisma/contract.prisma` — evidence: `npx prisma contract infer --help` (example `--output ./src/prisma/contract.prisma`).
- `orm/contract-authoring/psl-syntax.mdx:9` — "The five biggest additions are listed here", followed by six bullets (mixins, named types, enums, value objects, base models and variants, extension types).

## Missing

- `contract infer` on MongoDB — it refuses with `CONTRACT.INFER_UNSUPPORTED`; only the PostgreSQL target implements inference. The page never says it is PostgreSQL-only (the September audit listed this; C3 left it open, and it is still absent) — evidence: `packages/1-framework/3-tooling/cli/src/orm/contract/infer.ts:139-150`; `inferPslContract` is implemented only in `packages/3-targets/postgres/1-target/src/exports/control.ts` — belongs on `cli/contract-infer.mdx`.
- Where `contract infer` writes when `--output` is left out: `contract.prisma` beside the emitted `contract.json`, which in a standard project is the configured contract source itself, so a second run overwrites the reader's edited contract (with only a warning) — evidence: `packages/1-framework/3-tooling/cli/src/orm/contract/paths.ts:5-26`; running it with `contract: "./src/prisma/contract.prisma"` wrote `src/prisma/contract.prisma` — belongs on `cli/contract-infer.mdx` (Options, `--output`).
- A TypeScript contract needs the project to be an ES module: with `"type": "commonjs"` in `package.json`, which `npm init -y` writes and `orm init` keeps, `prisma contract emit` fails with `CONTRACT.SOURCE_LOAD_FAILED` "Cannot use import statement outside a module" — evidence: `npm init -y`, then `npx prisma orm init --yes --target postgres --authoring typescript`, then `npx prisma contract emit` in `/Users/wmadden/Projects/prisma/scratch/audit-contract/pgts/` — belongs on `orm/contract-authoring/typescript-schema-builder.mdx` (Point the config at the contract file), linking `cli/orm-init.mdx#in-a-commonjs-project`.
- The execution hash: `contract emit` prints `executionHash`, `contract.d.ts` exports `ExecutionHash`, and release notes tell readers that a change which moves "only the execution hash" needs no migration and no `db sign`; no page in this area says what it covers (generated values and defaults the client fills) or that `db sign` does not record it — evidence: emit output; `packages/3-targets/postgres/1-target/src/contract-free/control-bootstrap.ts:8-9` (marker stores `core_hash` and `profile_hash` only); `docs/releases/v8.0.0-rc.21.md` ("only the execution hash changes, so no migration and no `db sign` is needed") — belongs on `orm/contract-authoring/the-contract-artifact.mdx` (The content hashes).
- `map:` on `@id`, `@unique` and `@relation` (the database name of a primary key, unique constraint or foreign key) — `contract infer` writes `@id(map: "User_pkey")`, `@unique(map: "User_email_key")` and `@relation(..., map: "user_profile_user_id_fkey")`, and `contract print` writes `@relation(..., map: ...)`, but `psl-syntax.mdx` documents `map:` only on `@@index`, `@@check` and MongoDB indexes — evidence: `contract infer` output against a PostgreSQL 17 database; `contract print` of a TypeScript contract with `.sql({ fk: { name } })` — belongs on `orm/contract-authoring/psl-syntax.mdx` (Models and fields, Relations).
- MongoDB `Vector` and `Vector(length)` in PSL (since 8.0.0-rc.24) — the field types table on the MongoDB page omits it, though the TypeScript page lists `type.Vector()` — evidence: `docs/releases/v8.0.0-rc.24.md` ("MongoDB PSL gains `Vector` and `Vector(length)`"); a MongoDB model with `v Vector(3)` and `w Vector?` emits — belongs on `orm/data-modeling/mongodb.mdx` (Field types).
- Converting a TypeScript contract to PSL: `contract print` loads a `contract.ts` and prints it as PSL with the same hashes. The TypeScript page's "Parity with PSL" says only that nothing converts PSL to TypeScript — evidence: `npx prisma contract print` with `contract: "./ts/c1-complete.ts"` printed the PSL — belongs on `orm/contract-authoring/typescript-schema-builder.mdx` (Parity with PSL).
- Editor features the language server has that the page leaves out: rename, and that **Format Document** follows the `formatter` setting in `prisma.config.ts`, the same layout `prisma contract format` writes — evidence: `packages/1-framework/3-tooling/language-server/README.md` ("diagnostics, formatting, code completion, attribute signature help, hover, go-to-definition, find references, and rename"); `cli/configuration.mdx:279` — belongs on `orm/contract-authoring/editor-support.mdx` (What the editor does).
