## Misleading

- `orm/reference/sql-query-builder.mdx:1069` (also `orm/reference/raw-queries.mdx:22` and `:50`) — "`.returns()` only tells TypeScript what type to expect. It does not convert the value", and on the raw page "A fragment's `.returns(...)` does not convert anything … A date column gets no conversion by Prisma ORM, so you get the `pg` package's own value" — a fragment in a `select()` is decoded with the codec `.returns()` names, whenever that codec needs no type parameters (int4, text, bool, uuid, numeric, timestamptz-date and the other common ids). `db.raw.sql\`now()\`.returns('pg/timestamptz-date@1')` selected through the builder comes back as a JavaScript `Date`. Since rc.15 the driver returns every column as text, so without this decoding an `int4` fragment would arrive as a string; the page's own example at line 246 shows `emailLength: 17`, a number — evidence: `packages/2-sql-family/4-lanes/sql-builder/src/runtime/builder-base.ts:352-355,395,413` (`codecRefOf` attaches the codec to the projection), `packages/2-sql-family/4-lanes/sql-builder/src/runtime/sql.ts:17-25`, `test/integration/test/sql-builder/raw-sql.integration.test.ts:170-176`; run: `now() date: 2026-11-20T07:50:28.534Z object true`, `LENGTH int4: [{"id":1,"emailLength":17}] number` (`scratch/audit-builders/sqlb/check.ts`).
- `orm/reference/sql-query-builder.mdx:672` — "`.returns('pg/int4@1')` would type it `number` and still hand you a string" for `EXTRACT(YEAR FROM ...)` — it hands you a number. Only the `pg/numeric@1` form gives a string, because the numeric codec reads as a string — evidence: run of the page's query with both ids: `EXTRACT int4: 2026 number`, `EXTRACT numeric: 2026 string`.
- `orm/middleware/built-in-lints.mdx:29`, `orm/middleware/built-in-budgets.mdx:34`, `orm/middleware/authoring-custom-middleware.mdx:86` — "The `db.ts` that `create-prisma` generates has more in it, including a `connectDatabase` export that the generated `seed.ts` imports" — `create-prisma` 0.14.8 generates no `connectDatabase`; `db.ts` exports `contract` and `db`, and `seed.ts` imports `db`. Also `orm/middleware/how-middleware-works.mdx:44` and the same three pages say the generated file builds its client "only when the app is started with `DATABASE_URL` exported"; without the variable it still calls `postgres({ contract })` — evidence: `create-prisma/templates/create/_shared/src/prisma/db.ts.hbs` (the non-Deno PostgreSQL branch), `templates/create/_shared/src/prisma/seed.ts.hbs:1`, `grep -rn connectDatabase templates src` (no match).
- `orm/middleware/built-in-cache.mdx:41` (and the catalog row at `orm/middleware/how-middleware-works.mdx:287` and `orm/extensions/index.mdx:23`, "PostgreSQL, MongoDB") — "The cache works on PostgreSQL and on MongoDB. You register it on MongoDB the same way" — it registers, but a MongoDB read has no way to carry `cacheAnnotation`: the pipeline builder and the MongoDB ORM have no `annotate` and no `meta` callback, so nothing is cached unless you copy the built plan and set `meta.annotations.cache` by hand, as the ORM's own MongoDB test does. The page never says how to opt a MongoDB read in — evidence: `grep -rln annotate packages/2-mongo-family` (no match outside tests), `examples/mongo-demo/test/cache-middleware.test.ts:52-65` (`withCacheAnnotation` spreads `plan.meta`), `packages/3-extensions/middleware-cache/README.md:348` ("The Mongo ORM's write methods take no annotations").
- `orm/extensions/postgis.mdx:23`, `orm/extensions/paradedb.mdx:29`, `orm/extensions/arktype-json.mdx:27` — "Keep the rest of each file as it is; the full files look like this", followed by a `prisma.config.ts` with only an `orm` section — the pages assume a project from the quickstart, whose `prisma.config.ts` also has a `skills` section and a `composer` section (and whose `db.ts` loads its client from Composer first). A reader who takes the shown file as the full file drops both sections — evidence: `create-prisma/templates/create/_shared/prisma.config.ts.hbs` (non-Deno branch), `templates/create/_shared/src/prisma/db.ts.hbs`.

## Missing

- `invalidateAnnotation`: annotate a write (ORM write, or SQL builder insert, update or delete) with the keys or `meta` to invalidate, and the cache invalidates once the write's effects are final, after the enclosing transaction commits and not after a rollback. The cache page tells readers to call `cache.invalidate` by hand after the commit and never names it; only the error reference mentions it in passing — evidence it exists: `packages/3-extensions/middleware-cache/src/exports/index.ts` (`invalidateAnnotation`), `src/cache-annotation.ts` (`InvalidateAnnotationHandle`, `applicableTo: ['write']`), `src/cache-middleware.ts:137`, `README.md:330-349` — where on the site it belongs: `orm/middleware/built-in-cache.mdx`, "Remove entries after a write".
- ParadeDB's other search operations: `paradeDbFuzzy`, `paradeDbBoost`, `paradeDbConst`, `paradeDbSlop` and `paradeDbProximity`. The page lists only match, match any, match all, phrase, term and score, while the catalog row on two pages promises "fuzzy, phrase, and proximity queries" — evidence it exists: `packages/3-extensions/paradedb/src/types/operation-types.ts`, `src/core/proximity-chain.ts` — where on the site it belongs: `orm/extensions/paradedb.mdx`, "Search".
- A row lock cannot be combined with `distinct()`, `distinctOn()`, `groupBy()`, `having()`, an aggregate in the projection, or use as a subquery. The call type-checks and `build()` throws `ORM.LOCK_INCOMPATIBLE` — evidence it exists: `packages/2-sql-family/4-lanes/sql-builder/src/runtime/builder-base.ts:175-204`, `packages/2-sql-family/4-lanes/relational-core/src/ast/locking.ts:4-19`; run: `select('id').distinct().forUpdate().build()` throws `ORM.LOCK_INCOMPATIBLE A locking clause cannot be combined with distinct` (`scratch/audit-builders/sqlb/lock.ts`) — where on the site it belongs: `orm/reference/sql-query-builder.mdx`, "Row locking", Remarks.
- `.annotate(...)` on a SQL builder query (reads take read annotations such as `cacheAnnotation`, writes take write annotations such as `invalidateAnnotation`). The reference documents every other chain method but not this one; only the cache page shows it — evidence it exists: `packages/2-sql-family/4-lanes/sql-builder/src/types/select-query.ts` (`annotate`), `src/types/grouped-query.ts` (`annotate`), `docs/releases/v8.0.0-rc.15.md:93-100` — where on the site it belongs: `orm/reference/sql-query-builder.mdx`, under SELECT queries and Mutations.
- Preparing a pipeline with `db.prepare(declaration, callback)` on MongoDB, including `$skip` and `$limit` counts, added in rc.24. The pipeline builder reference says to run every built query with `runtime.query(...)` and does not mention it; `orm/reference/transactions-and-runtime.mdx:755` has the only example — evidence it exists: `docs/releases/v8.0.0-rc.24.md` ("MongoDB clients can prepare a query once"), `packages/3-targets/mongo/9-facade/src/runtime/mongo.ts` (`MongoClient extends MongoPrepareMember`) — where on the site it belongs: `orm/reference/pipeline-builder.mdx`, "Building and executing a pipeline", as a link.
