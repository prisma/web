- `guides/frameworks/react-router-7.mdx:25` — Prerequisites say Node.js 22.18 or newer on the 22 line — the guide scaffolds with `npx create-react-router@latest`, which installs React Router 8, and `react-router@8.5.2` and `create-react-router@8.5.2` declare `engines: { node: '>=22.22.0' }`; a reader on Node.js 22.18 to 22.21 is below the framework's floor. ## Missing

- Running the scaffold locally with `npm run dev:composer`, which starts a local Prisma Postgres and applies the committed migrations with no `DATABASE_URL` to export. It is the first step the scaffold itself prints ("Next steps: `npm run dev:composer`"); every `create-prisma` framework page instead requires exporting a connection string — evidence it exists: `create-prisma/src/tasks/install.ts:64-72`, `create-prisma/templates/create/_shared/README.md.hbs:80-87`, scratch run output — where on the site it belongs: the "Initialize the database" or "Run and verify" step of `nextjs`, `astro`, `nuxt`, `tanstack-start`, `nestjs`, `hono`, `elysia`, `runtimes/bun`
- The baseline migration the scaffold commits and the `migration:plan`, `migrate`, `migration:status` and `db:verify` scripts it adds. A reader who changes the contract and redeploys needs `npm run migration:plan` before `npm run build` and `npx prisma deploy` — evidence it exists: `create-prisma/src/tasks/setup-prisma.ts:136-143`, `create-prisma/src/tasks/install.ts:51-60` — where on the site it belongs: "Next steps" on the five pages that deploy and list a schema-change step
- The Vite plugin for automatic `contract emit` on the Astro, Nuxt and SvelteKit pages. All three templates run on Vite (`vite` in their `devDependencies`), but only TanStack Start, React Router and SolidStart mention the plugin — evidence it exists: `orm/packages/9-public/@prisma/orm-postgres/package.json:206` (`./vite-plugin-contract-emit`), `skills/prisma-8/references/build.md:8-12` — where on the site it belongs: "Next steps" on `astro.mdx`, `nuxt.mdx`, `sveltekit.mdx`
- MongoDB with the framework templates. Every template accepts `--provider mongo`, and the generated `module.ts` then asks for a `MONGODB_URL` secret at deploy time instead of provisioning a database; no framework or runtime guide mentions MongoDB — evidence it exists: `create-prisma/src/types.ts:3-4`, `create-prisma/templates/create/_shared/module.ts.hbs` (mongo branch), `(index)/prisma-orm/create-prisma.mdx:83` ("Every template supports PostgreSQL and MongoDB") — where on the site it belongs: one note per `create-prisma` framework guide, or one section on the guides index
