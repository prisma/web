# Audit: cli

Pages read: `cli/index.mdx`, `cli/global-flags.mdx`, `cli/configuration.mdx`, `cli/environment-variables.mdx`, `cli/init.mdx`, `cli/orm-init.mdx`, `cli/skills.mdx`, `cli/dev.mdx`, `cli/emulator.mdx`, `cli/git.mdx`, `cli/telemetry.mdx`, `cli/feedback.mdx`, `ai/tools/skills.mdx`, `cli/error-reference.mdx`, `orm/reference/error-reference.mdx`.

Checked against `prisma` 8.0.0-rc.34 source and its installed build (with `@prisma/orm-postgres` 8.0.0-rc.24, `@prisma/cli-engine` 0.10.0, `@prisma/composer-cli` 0.39.0) in `/Users/wmadden/Projects/prisma/scratch/audit-cli/`, including a real `orm init` run in `orminit-pg/`. Error codes were compared by extracting every quoted `NAMESPACE.CODE` string from the tagged sources (tests excluded) and from the installed Composer build, against the `###` headings of both pages.

## Breaks copy-paste

- `cli/index.mdx:83` — "Adopt an existing database" runs `contract infer --output ./prisma/contract.prisma`, then `contract emit` and `db sign` — the config that `orm init` writes (the only config the page shows how to create, line 73) reads `./src/prisma/contract.prisma`, so `contract emit` ignores the inferred file, emits the starter contract, and `db sign` then compares the database against the wrong contract. Without `--output`, `contract infer` writes next to the configured contract, which is the right place — evidence: `orminit-pg/prisma.config.ts` written by `npx prisma orm init --yes --target postgres --authoring psl` (`contract: "./src/prisma/contract.prisma"`); `packages/1-framework/3-tooling/cli/src/orm/contract/paths.ts:13-26`; the command's own example in `orm/contract/infer.ts:88` uses `./src/prisma/contract.prisma`.
- `cli/configuration.mdx:283` — "every command that reads the config fails with `CLI.CONFIG_FIELD_INVALID`", and line 343 tells scripts to branch on `envelope.error.code` — `envelope.error.code` is `CLI.CONFIG_SECTION_INVALID`; `CLI.CONFIG_FIELD_INVALID` arrives only as an entry in `envelope.diagnostics`, so a script that matches the documented code on `error.code` never matches — evidence: `npx prisma contract format --json` with `formatter: { indent: 0 }` prints `"error":{"code":"CLI.CONFIG_SECTION_INVALID",...},"diagnostics":[{"code":"CLI.CONFIG_FIELD_INVALID","summary":"In the 'orm' section, formatter.indent must be at least 1 (was 0)",...}]`.

## Misleading

- `orm/reference/error-reference.mdx:9` — the page is generated from `prisma/orm` `main`, not from the released tag, so it documents 11 codes and one flag that no release raises or accepts — `v8.0.0-rc.24` raises none of `CLI.INIT_AUTHORING_UNSUPPORTED` (line 125), `CLI.INIT_CONTRIBUTION_UNAVAILABLE` (133), `CLI.INIT_TARGET_PACKAGE_NOT_INSTALLED` (219), `CONFIG.CONTRACT_TYPES_MODULE_MISSING` (51), `CONFIG.MIGRATION_MODULE_MISSING` (75), `CONTRACT.FOREIGN_KEY_CONFLICT_ON_STI_VARIANT` (477), `CONTRACT.UNSCOPED_INDEX_ON_STI_VARIANT` (699), `RUNTIME.TRANSACTION_SUSPENDED` (1517), `MIGRATION.CHANGE_POLICY_FORBIDS` (1567), `MIGRATION.DATA_PROTECTION_FORBIDS` (1687), `MIGRATION.POLICY_MISMATCH` (1877); and lines 235, 1569 and 1689 describe a `--permit-policy-change` flag on `db migrate` and `db update` that `prisma` 8.0.0-rc.34 does not have — evidence: `grep` of each code over `packages/` at `v8.0.0-rc.24` finds nothing (also none in the installed `@prisma/orm-*` 8.0.0-rc.24 builds); none of them is in `docs/reference/error-reference.md` at the tag; `npx prisma db migrate --help` and `npx prisma db update --help` list no `--permit-policy-change`. The four codes the release does raise and the page lacks are under Missing.
- `orm/reference/error-reference.mdx:205` — `CLI.INIT_REINIT_NEEDS_FORCE` is described as live ("Maps to init exit code 2") — nothing raises it; a second `orm init` asks for consent through the engine and fails with `CLI.CONSENT_REQUIRED`, which is what `cli/orm-init.mdx:178` says, so the two pages disagree. Two more entries describe codes nothing raises and are not marked retired: `RUNTIME.EXECUTION_RESULT_MISSING` (line 1368) and `RUNTIME.MIDDLEWARE_RESULT_MISMATCH` (line 1392) — evidence: no match for any of the three in `packages/` at `v8.0.0-rc.24`; `orm/init-inputs.ts:388-398` (`prompt.consent(..., { token: consentToken(cwd) })`).
- `cli/error-reference.mdx:13` and `orm/reference/error-reference.mdx:13` — both say "When an error prints a `docsUrl`, that link opens the code's entry on this page" — an engine `CLI.*` code raised under a Prisma ORM command carries the ORM family's docs URL, which lands on the ORM page, where the code has no entry. The CLI page's own example, `CLI.CONFIG_SECTION_INVALID` from a Prisma ORM command, is one such code — evidence: `npx prisma contract format --json` with an invalid `formatter` prints `"docsUrl":"https://docs.prisma.io/docs/orm/v8/reference/error-reference/CLI.CONFIG_SECTION_INVALID"` (and the same for `CLI.CONFIG_FIELD_INVALID`), which `next.config.mjs:154-155,236-237` redirects to `/orm/reference/error-reference#CLI.CONFIG_SECTION_INVALID`; neither code is a heading on that page. The same error from a platform command links to `/cli/error-reference/...`.
- `cli/skills.mdx:43` — "Only packages you deliberately installed are sources" — sync resolves the allowlisted names with ordinary module resolution, so a package that is only a dependency of `prisma` counts. With npm, `@prisma/composer` is hoisted from `prisma` → `@prisma/composer-cli`, so a Prisma ORM project that never installed Composer gets `prisma-composer-core-concepts` synced, and the out-of-date notice reports it. `ai/tools/skills.mdx:124` ("After you install the package, copy the skill") gives the same wrong picture — evidence: scratch project with only `prisma` and `@prisma/orm-postgres` in `package.json`; `npm ls @prisma/composer` shows `prisma@8.0.0-rc.34 → @prisma/composer-cli@0.39.0 → @prisma/composer@0.39.0`; `npx prisma skills list` lists `prisma-composer-core-concepts  @prisma/composer  0.39.0` for all four directories; `packages/cli/src/lib/skills/resolve.ts` (`createRequire(...).resolve`).
- `ai/tools/skills.mdx:110` — `prisma init` "sets up the skill for every agent runtime the installer supports (Claude Code, Cursor, Codex, Windsurf)" — the agents are `claude`, `cursor`, `agents` and `devin` (`.claude/skills`, `.cursor/skills`, `.agents/skills`, `.devin/skills`); Windsurf was deliberately left out, and `cli/skills.mdx:47-54` and `cli/init.mdx:33` give the correct list. This settles the open question in `changes.md` about which list is current — evidence: `packages/cli/src/lib/skills/allowlist.ts` (`AGENT_SKILL_DIRS`, and the comment "The same page documents .windsurf/skills, which was deliberately not added"); `npx prisma init --skills=windsurf` fails with `CLI.INVALID_ARGUMENTS ... The known agents are claude, cursor, agents, devin.`
- `ai/tools/skills.mdx:114` — the `prisma-8` skill helps with "reading `PN-*` structured errors" — Prisma ORM 8 codes are dotted `NAMESPACE.SUBCODE` since 0.16; the skill's router lists those first and mentions `PN-*` only as legacy — evidence: `skills/prisma-8/SKILL.md:73` at `v8.0.0-rc.24`; `orm/reference/error-reference.mdx:25`.
- `cli/init.mdx:18` — `init` "never prompts, always exits 0" — an invalid `--skills` value exits 2 with `CLI.INVALID_ARGUMENTS` — evidence: `prisma init --skills=windsurf` in an empty folder prints `[CLI.INVALID_ARGUMENTS]` and exits 2; `packages/cli/src/commands/init.ts:756-812`.
- `cli/init.mdx:11-16` — "`init` does four things" — in a directory that another `prisma.config.ts` higher up already governs (a monorepo package), `init` writes only the `prisma.config.ts` scaffold and skips the `postinstall` hook, the `prisma` dev dependency and the sync unless `--postinstall` or `--skills` is passed. The page never says so, so a reader running it in a workspace member sees steps skipped with no explanation — evidence: `npx prisma init --help`; `packages/cli/src/commands/init.ts:700-737` (`governedByAncestorConfig`, "Skipped the postinstall hook and the prisma dev dependency: another prisma.config.ts already governs this directory").
- `cli/global-flags.mdx:72` — `contract emit` data lines are "the paths of `contract.json` and `contract.d.ts`" — when the config lists extensions that ship migrations, it also prints one line per file it writes for each extension's contract space — evidence: `packages/1-framework/3-tooling/cli/src/orm/contract/emit.ts:72-78` (`...document.pinnedFiles.map(...)`), `control-api/operations/contract-emit.ts:178-191`.

## Missing

- What CLI telemetry collects, that CI runs never send, and the one-time notice — the first-run notice says "What's collected and why: https://www.prisma.io/docs/cli", and `prisma telemetry --help` says "see https://www.prisma.io/docs/cli for what is collected and why", but neither `/cli` nor `cli/telemetry.mdx` lists the fields. `changes.md` marks C20 (which included "the event fields") as landed, but the page's history (#8262, #8280, #8278, #8312) never added them. Each event carries the installation id, CLI version, command path, the names (not values) of the flags typed, runtime name and version, OS, architecture, package manager, TypeScript version, the detected AI agent, and extensions — evidence: `packages/cli-telemetry/src/payload.ts` (`TelemetryEvent`), `packages/cli-engine/src/telemetry/payload.ts` (`sanitizeCommandSnapshot`), `report.ts:55-62` (`firstRunNotice`), `gating.ts:57-82` (CI disables first) — belongs on `cli/telemetry.mdx`.
- Four codes `v8.0.0-rc.24` raises that `orm/reference/error-reference.mdx` lacks: `CLI.PROJECT_MANIFEST_INVALID`, `CLI.PROJECT_MANIFEST_UNREADABLE`, `ORM.RELATION_MUTATION_INVALID`, `ORM.RELATION_MUTATION_UNSUPPORTED` — evidence: present in `docs/reference/error-reference.md` at `v8.0.0-rc.24` and raised in `packages/3-extensions/sql-orm-client/src/relation-mutations.ts:91,182` and `mutation-graph/nested-mutations.ts:164`; absent from the site page because it is generated from `main` — belongs on `orm/reference/error-reference.mdx` (fix in the generator's source choice).
- Thirteen Composer codes that `prisma` 8.0.0-rc.34 can print are not on `cli/error-reference.mdx`: `CONFIG.SECTION_MISSING`, `DEV.ATTACH_FAILED`, `DEV.CONTAINER_FAILED`, `DEV.CONVERGE_FAILED`, `DEV.DEV_SERVER_UNAVAILABLE`, `DEV.DEV_SERVER_UNSUPPORTED`, `DEV.ENVIRONMENT_NAME_MISMATCH`, `DEV.PLATFORM_UNSUPPORTED`, `DEV.PREFLIGHT_FAILED`, `DEV.SERVICE_START_FAILED`, `DEV.STACK_WRITE_FAILED`, `DEV.TARGET_UNSUPPORTED`, `DEV.TEARDOWN_FAILED`. `cli/dev.mdx:81` tells readers about `DEV.ENVIRONMENT_NAME_MISMATCH`, which then has no entry. Every other code on the page matches the `prisma-cli` source and its `docs/reference/error-reference.md` exactly (172 entries) — evidence: `prisma@8.0.0-rc.34` depends on `@prisma/composer-cli` 0.39.0; e.g. `new CliStructuredError("DEV.ENVIRONMENT_NAME_MISMATCH", ...)` and `new CliStructuredError("DEV.PLATFORM_UNSUPPORTED", "local dev is not supported on Windows yet.")` in `node_modules/@prisma/composer-cli/dist` — belongs on `cli/error-reference.mdx` (the page says these family entries are kept current by hand).
- The update notice and `NO_UPDATE_NOTIFIER` — the CLI checks npm for a newer `prisma` in the background and prints a notice on stderr; `NO_UPDATE_NOTIFIER` turns it off (read since 8.0.0-rc.1). No page mentions either — evidence: `packages/cli/src/update-check.ts:170-185`; `docs/product/output-conventions.md` "Automatic Update Notifications"; first tag containing the variable is `v8.0.0-rc.1` — belongs in the table on `cli/environment-variables.mdx`.
- Files and changes `orm init` makes that `cli/orm-init.mdx:41-52` does not list: `.gitignore` and `.gitattributes` (marking the emitted contract and migration files as generated), a `contract:emit` script in `package.json`, and a minimal `package.json` when the folder has none — evidence: the data lines of the `orminit-pg` run list `.gitignore`, `.gitattributes` and `package.json`, and the written `package.json` has `"contract:emit": "prisma contract emit"`; `orm/init-scaffold.ts:181` and its warning "No package.json found in the target directory; created a minimal one" — belongs on `cli/orm-init.mdx` "What it creates".
- What `prisma feedback` sends besides the message: the CLI version, Node.js version, and OS platform and architecture, and nothing else — evidence: `npx prisma feedback --help` — belongs on `cli/feedback.mdx`.

## Out of scope

- `cli/dev.mdx` — Prisma Composer's local runner, a platform command. Noted in passing: lines 9 and 11 say `dev` runs the built output, while `npx prisma dev --help` says a service whose build adapter declares a dev server (such as `next dev`) runs that instead; the page does not say local dev refuses to run on Windows (`DEV.PLATFORM_UNSUPPORTED`); `dev stop` also takes `--entry` and `--name`.
- `cli/emulator.mdx` — Prisma Composer's local emulators, a platform command.
- `cli/git.mdx` — the GitHub connection for Prisma Compute deploys, a platform command. Noted in passing: line 17 says the command needs an interactive terminal, but `git connect` only needs one when the GitHub App install is still required (`packages/cli/src/commands/git/connect.ts:202-207`), and both `git connect` and `git disconnect` take `--project <id-or-name>`, which the page omits.
