## Breaks copy-paste

- `orm/migrations/editing-a-migration.mdx:256` — says you would enable `pgcrypto` "with `createExtension('pgcrypto')` from the same module", meaning `@prisma/orm-postgres/migration` — that free function was removed in 8.0.0-rc.24, so the import fails with "does not provide an export named"; the call is `this.createExtension({ extension: 'pgcrypto' })`. `orm/reference/migration-api.mdx:315` already says this, so the two pages disagree — evidence: `packages/3-targets/postgres/1-target/src/exports/migration.ts` (exports `MigrationCLI`, `placeholder`, `sql`, the column and constraint helpers, `rawSql`, `Migration`; no `createExtension`), `docs/releases/v8.0.0-rc.24.md:53`

- `orm/reference/migration-api.mdx:3,6,490` — the description says it lists "Every method and helper a migration.ts can use", and the MongoDB section says "everything comes from one module" and shows an import line with 11 names — it leaves out 8 methods of the PostgreSQL `Migration` class and 7 MongoDB factories, and `migration plan` writes several of them into `migration.ts` (details under Missing) — evidence: `packages/3-targets/postgres/1-target/src/core/migrations/postgres-migration.ts`, `op-factory-call.ts:1169,1258`, `packages/3-targets/mongo/1-target/src/exports/migration.ts`
- `orm/contract-authoring/editor-support.mdx:17-23` — says the extension and `contract emit` only accept files whose first line is `// use prisma-8`, and that `contract emit` skips any other file — the older header `// use prisma-next` is still accepted by both, and the language server rewrites it to `// use prisma-8` when it formats the file. A reader who started on an early release candidate is told their files are skipped when they are not — evidence: `packages/1-framework/2-authoring/psl-parser/src/schema-directive.ts:1` (`/^(\s*\/\/ *use +)(prisma-8|prisma-next)( *)(?!\S)/`), `docs/releases/v8.0.0-rc.10.md` (Features, first bullet)

The planner writes `addColumnWithTemporaryDefault` and `addRequiredColumnToEmptyTable` into `migration.ts`, and the three `*StoredKey` methods carry out `--rename GeoPoint.lat:GeoPoint.latitude`, `--delete` and `--backfill` for value object fields (rc.23), so a reader can open a planned migration and find calls the reference does not explain — evidence: `packages/3-targets/postgres/1-target/src/core/migrations/postgres-migration.ts:381,402,421,445,522,544,991,1001`, `op-factory-call.ts:1169,1258` — belongs on `orm/reference/migration-api.mdx` under Columns, Data, and Extensions
- Seven MongoDB migration factories that `orm/reference/migration-api.mdx` does not list: `castField` (casts a field to a BSON type with `$convert`), `fillField` (sets a missing or null field, as a new required field is filled), `renameField`, `unsetField`, `renameCollection`, `rawUpdateMany`, `rawAggregate`. `migration plan` writes `renameCollection` and `renameField` for `--rename` (rc.18), and `castField` and `fillField` for type changes and new required fields (rc.24) — evidence: `packages/3-targets/mongo/1-target/src/exports/migration.ts`, `src/core/migrations/migration-factories.ts:123,136,271,306,408,468,806`, `op-factory-call.ts:392-396` — belongs on `orm/reference/migration-api.mdx#mongodb-operations`
