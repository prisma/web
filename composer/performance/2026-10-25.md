# Why Compute + Cloudflare was not an unqualified performance win

This follows [the regional baseline](2026-10-24.md). The custom domain uses one
hostname-wide Cloudflare rule: eligible, origin cache headers authoritative,
bypass absent, browser TTL respected, raw Vary and full query key. No additional
Cloudflare rules, credentials, production resources or production traffic changed.

## Separate three problems

1. **Application startup work.** A decorative texture was converted at request
   time, full variable Inter files were fetched for small Latin pages, hidden
   legacy `<i>` icons requested an otherwise unnecessary italic font, and the
   closed docs Ask AI panel initialized its SDK/CAPTCHA. An autoplay video near
   the bottom of the homepage downloaded despite `preload=metadata`. These are
   fixable application costs on either host.
2. **Cache misses and fragmentation.** Compute is in EWR. A global edge miss,
   expiry, cold image conversion or uncached RSC navigation pays origin distance.
   HTML freshness is deliberately 60 seconds plus 300 seconds SWR because this
   independent cache has no deployment purge/atomic version promotion. Complete
   query keys and raw User-Agent/Accept variation are safe but fragment entries.
3. **CDN network paths.** Some Singapore ASNs had slow Cloudflare HITs and slow
   Cloudflare-managed `/cdn-cgi/trace` responses that never reach Compute. Other
   Singapore networks were fast. This cannot be repaired by a Next.js/proxy
   optimization or inferred solely from the country or processing-colo code.

## New measurements before this optimization

Seven fresh Globalping probes, repeated paired HTTP/2 HEADs, same hosts and
paths, 25 October. This measures public delivery, not browser LCP or an isolated
same-build comparison. Six initial Cloudflare docs requests were EXPIRED, one
MISS: 1.139–2.218 seconds. On repetition all seven were HIT:

| Probe | Cloudflare HIT, ms | Vercel HIT, ms |
| --- | ---: | ---: |
| Buffalo | 110 | 177 |
| Los Angeles | 56 | 120 |
| Germany | 87 | 116 |
| Singapore (LeaseWeb AS59253) | 83 | 78 |
| Brazil | 36 | 76 |
| South Africa | 48 | 168 |
| Australia | 28 | 130 |

Times include DNS/TCP/TLS plus first byte. Raw responses are retained locally in
`output/playwright/performance-2026-10-25/before-optimize-*.json`. This does not
revoke the prior slow Singapore Oracle/MyRepublic measurements: it is a different
network sample and illustrates why country-level medians conceal poor paths.

Reused HTTP/2 connections from Bangkok isolate handshake overhead. Direct EWR
gateway health: 284/284 ms TTFB; gateway docs: 317/311 ms; direct docs app:
308/313 ms. The warm proxy hop is small in this sample. Cloudflare health, which
bypasses cache and performs no Next render, took 1,018/1,089 ms on reused client
connections (BKK processing colo). New connections also pay DNS/TCP/TLS; an
approximately one-second first request must not be labeled one second of app CPU.
A separate fresh-connection check returned Cloudflare trace in 54 ms,
Cloudflare health in 1,238 ms, and the same custom-domain origin reached
directly in 847 ms (including 579 ms for DNS/TCP/TLS). This narrows the extra
latency to the miss/bypass delivery path; it does not identify which hop adds
it. Origin connection pooling/TLS reuse needs platform telemetry.

Per-response `Server-Timing: gateway` now measures the gateway through upstream
headers without buffering. HITs retain their cache-fill timing, not current work.

## Changes to verify

- Bake the full existing grain composition to AVIF (34,457 bytes), with JPEG
  fallback (127,616 bytes), and selected decorative art to WebP. Import through
  Next so both Vercel and Compute serve content-hashed immutable files. Keep
  original URLs and the legacy optimizer working. No runtime encoding on these
  critical decorative paths, and no new production dependency/build step.
- Subset the vendored Inter files by Unicode range. Keep every original Unicode
  point, variable axis, advance width, OpenType feature and license metadata.
  Normal Latin is 137,960 bytes instead of 352,240. Download italic/non-Latin
  faces only when needed. The original files remain available. Do not replace
  Inter with a system font or drop language coverage.
- Load the protected Ask AI panels/SDK on first open, retaining one provider
  after closing, across desktop/mobile, with the existing CAPTCHA and query
  behavior. The initial page does not need a chat SDK or CAPTCHA frame.
- Withhold the closing video's source until near the viewport; retain its static
  background for reduced motion and while loading. Keep autoplay/loop when used.
- Enforce source/output digest and size budgets for the checked-in media/fonts.

Regeneration commands and limitations are documented in
[the asset notes](../../packages/ui/scripts/README.performance-assets.md).

## What Compute's CDN should provide

**First: deployment-integrated static delivery.** Extract Next public/static
files into object storage outside the service's 1 GB filesystem; publish a
content-addressed release manifest; retain old chunks while old HTML can refer
to them. Promote gateway, apps, HTML/RSC caches and asset manifests atomically,
with deploy invalidation/rollback. Long-lived edge HTML without invalidation is
not a safe substitute. Supply correct content validators, HEAD/206/304 lengths,
streaming, cancellation, compression, ranges and origin no-transform handling.

**Next-aware representation keys.** Cache public HTML, Markdown and eligible
RSC/prefetch by deployment, zone, route, representation and actual framework
inputs. Keep auth, Server Actions, private/dynamic responses and Set-Cookie safe.
Normalize equivalent Accept/User-Agent values at a trusted edge adapter rather
than storing every raw browser string. Audit tracking parameters per route;
never ignore every query parameter. Next's deploymentId identifies skew; by
itself it does not route requests to old versions or retain their assets.

**Shared fills and persistent image variants.** Provide shield/tiered caching,
request coalescing, SWR and persistent transformed images independent of VM
restarts. Prepublish predictable critical variants. This reduces repeat
misses; it does not eliminate first-ever SSR or latency on an already-cached HIT.
Keep cache state out of the constrained VM and make its hit/fill status visible.

**A network and latency contract.** Report edge/shield/origin/gateway/app and
scheduling/startup timings, cache key/reason/age/version and request IDs. Measure
cold, warm, post-expiry, campaign URLs and real client navigation by region,
ASN and device; use field p75 LCP/INP/CLS before claiming all-user parity. Prefer
HTTP/3-capable measurements with applied throttling to comparing only Lantern
simulation: the prior HTTP/3 trace inferred 0 ms origin RTT and a much higher
server-latency estimate for Cloudflare despite faster observed paint.

A Compute CDN using the same Cloudflare network with the same routing does not
automatically repair the observed slow HIT/trace paths. That needs provider/ISP
path investigation (and potentially alternate delivery/peering). Conversely,
fast HITs in six of seven fresh probes show that Compute + Cloudflare is not
intrinsically incapable of beating this Vercel sample. The present setup cannot
promise a win for every user: misses and framework navigation still reach EWR,
cache keys/invalidation are not deployment-aware, and network quality varies by
ASN. These are concrete product gaps, not grounds to cache private responses or
remove functionality for a better score.

## Verification and after measurements

Local builds for all five apps and the full Composer smoke pass, including
both baked image formats, legacy optimizers, original media, redirects, Markdown,
stream lengths and byte ranges. Largest RSS sample is docs at 550.0 MB; largest
artifact is blog at 850.4 MB expanded / 686.3 MB compressed. Proxy/Composer tests
(40 + 40), site/blog/docs/Eclipse/shared UI tests (272/85/90/9/101), relevant app
and UI type checks, formatting and 729-file docs links passed. Native font
browser checks cover five language samples, normal/italic and three weights
with identical measured widths (30 combinations). Desktop chat opens, initializes
CAPTCHA and retains its unsent draft after close/reopen; no question was sent.

The final browser and exact preview checks are still being completed. Live
results and deployment identity are recorded in the final 25 October section of
[COMPOSER_FINDINGS.md](../../COMPOSER_FINDINGS.md), which supersedes this staging
note. No all-user parity claim is made.
