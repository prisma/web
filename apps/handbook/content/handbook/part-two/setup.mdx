Have your problem sentence, first useful flow, and rough screen sketch nearby. These are the instructions for what you're about to build. Keeping them together helps you give the AI consistent context when you start making changes.

The aim of setup is modest: a project you can open, a way to ask the AI to change it, and a preview where you can see the result. Get that working before adding your product's behaviour.

We'll use the browser versions of these tools. The AI runs the development tools on a cloud computer, so you can give instructions and review the result without installing Node.js or Bun, or opening a terminal on your own computer.

## Create your Prisma account

We'll use Prisma to create and host the application, with Prisma Postgres for its database and Prisma Compute to run it. Its [Free plan](https://www.prisma.io/pricing) includes both, with usage limits and no credit card required.

1. Open [Prisma Console](https://console.prisma.io/login). Create an account if you don't have one.
2. Sign in with your email and password, Google, or GitHub. Choose whichever you prefer.
3. Prisma creates a default workspace for you. A workspace groups your projects and their billing. Use this personal workspace for the handbook and keep it on the Free plan.

You should now be able to open your workspace in the Console. You can leave it empty for now; we'll connect the AI before creating the product's database. The [Prisma account setup guide](https://www.prisma.io/docs/console/getting-started) has more detail if you get stuck.

## Put the brief in one place

A useful starting brief describes the person, the task, and the boundary of this version. Include what should happen when the task is complete. Add your sketch if the tool supports it, or describe the screen in words.

For our hypothetical example, the brief could be:

```text title="First-version brief"
We're building a way for a freelance designer to ask a client
for a decision on a design draft.

The designer creates a request with a draft URL and a question.
The client opens the request and submits a written response.
The designer can read the saved response later.

Start with the request page using clearly labelled sample content.
We'll connect the complete flow to saved data afterwards.

Keep the layout simple and usable on a phone. Explain what the
client is responding to and confirm when a response is saved.

Leave out payments, automated reminders, file uploads, analytics,
and team management for this version.
```

Change the brief to match your own product. The excluded features help the AI understand where to stop. Keep a copy with the project so you can refer to the same decisions later.

## Connect Prisma

The plugin or connector lets your AI tool work with your Prisma account. Connect the workspace you just set up.

<ToolInstructions>
  <ToolContent tool="chatgpt">
    Open [ChatGPT's plugin directory](https://chatgpt.com/plugins) and find Prisma. Add it, connect your Prisma account, and select your workspace. The [Prisma setup guide for ChatGPT](https://www.prisma.io/docs/ai/tools/chatgpt) also describes a manual connection through the browser settings if the directory entry isn't available.

    Start a Work chat for the product and select Prisma with an `@` mention. Keep your brief and the building work in that chat so you can return to them together.

  </ToolContent>
  <ToolContent tool="claude">
    Open [Claude's connectors](https://claude.ai/customize/connectors), find Prisma, and connect your Prisma account. Select your workspace and complete the authorization.

    Claude makes these [connected services available to Claude Code](https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claudeai), including cloud sessions. Return to your Claude Code tab and use the connection check below as your first message. If Prisma asks you to sign in again, return to the connectors page to reconnect it.

  </ToolContent>
</ToolInstructions>

From the session you'll use to build, ask:

```text title="Check the Prisma connection"
Use the Prisma connection to tell me which workspace I'm connected
to and list its databases. Don't create or change anything yet.
```

An empty list is fine for a new workspace. If the connection fails, resolve it before asking the AI to create resources.

## Know what each piece does

Your AI tool helps turn instructions into changes to the application. The application is the software the user interacts with. Its code describes the screens and the behaviour behind them.

A database keeps information the application needs to retrieve later. [Prisma Postgres](https://www.prisma.io/docs/postgres) is a managed PostgreSQL database. Prisma ORM is a way for application code to work with that data; the [Prisma ORM quickstart](https://www.prisma.io/docs/prisma-postgres/quickstart/prisma-orm) shows the connection between the two.

Hosting runs the application somewhere your friend can reach it. We'll use [Prisma Compute](https://www.prisma.io/docs/compute) for this, including the early preview. [Prisma Composer](https://www.prisma.io/docs/composer) describes the application's services and database connections so Prisma can deploy them together.

These roles help you understand what you're looking at when something goes wrong. A page can load while its database connection is broken. A working preview can also be available only inside your development environment.

## Get a starter you can run

Give the AI your brief and the prompt below. It should follow [Prisma's application setup guide](https://www.prisma.io/docs/full-stack-tutorial), run the build in its cloud session, and deploy the starter to your Prisma workspace.

<ToolInstructions>
  <ToolContent tool="chatgpt">
    Return to the Work chat where you connected Prisma. Ask ChatGPT to create
    the project files there and tell you where they're saved. Keep building in
    that chat so it can update and redeploy the same Prisma application.
  </ToolContent>
  <ToolContent tool="claude">
    Use the Claude Code session where you checked Prisma. Ask it to create the
    project in your selected GitHub repository, save the changes there, and
    deploy that version to Prisma Compute.
  </ToolContent>
</ToolInstructions>

```text title="Create the starter with Prisma"
Read https://www.prisma.io/docs/full-stack-tutorial and use the
current Prisma setup instructions to create a web application
for my brief. Choose a supported template with a user interface.
Use Prisma Composer, Prisma Postgres, and Prisma Compute.

Start with the request page and clearly labelled sample content.
Keep the database setup from the starter; we'll connect the
product's complete flow to saved data later.

Run the setup, build, and checks in your cloud environment.
Keep my steps in the browser, with no local software installs
or terminal commands. Explain any browser authorization steps
needed to deploy to my Prisma workspace. Keep credentials out
of chat and source files, and ask before adding a paid service.

Deploy the starter to Prisma Compute. Give me the application URL
and its project in Prisma Console, and verify that the page loads.
Tell me where the code is saved and how we'll update this same app.
```

The Prisma connection lets the AI manage resources in your account. The build tools may also need authorization to upload the application. Have the AI explain the supported browser or cloud-secret setup if that step is missing.

Open the Prisma-hosted URL yourself. Ask for one small change, such as changing the heading to “Review the latest draft,” and have the AI redeploy it. Check that the change appears. This early deployment gives you a preview to work with; [Get a live URL](./live-url.mdx) covers checking the finished flow before sharing it with a friend.

If you're working in a project with code files, ask the AI to orient you:

```text title="Understand the starter"
Inspect the project before making changes. Explain where the main
screen lives, how to start the preview, and how to run the checks
already included in the project. Identify any data connection that
is already configured without showing secret values.

Tell me which parts of our brief are already supported and which
still need implementation.
```

You don't need to understand every file. You should know where your work is saved and how to tell whether the latest change is visible in the preview. If an instruction assumes software or an account you don't have, resolve that prerequisite before continuing.

## Keep a way back

Use the project's version history to save the working starter. In a code repository, this is usually a Git commit: a recorded version you can return to. Some building tools expose their own history instead. Find the recovery method available in the tool you're using.

Give the checkpoint a useful description, such as “starter runs before feedback flow.” Then make a small visible change and check it in the preview. That confirms you can give an instruction, see the result, and recover the earlier version before [building the first flow](./first-flow.mdx).
