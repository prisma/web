You can now run production apps on Prisma Compute, with published pricing and a Free plan. This release also adds Deploy Buttons, so anyone can launch your app from a README in one click, and makes Prisma 8 the default when you run `npm install prisma@latest`.

## Prisma Compute is ready for production

[Prisma Compute](https://www.prisma.io/docs/compute) runs your TypeScript app next to your [Prisma Postgres](https://www.prisma.io/docs/postgres) database. Every Git branch gets its own environment, and apps scale to zero when nobody is using them, so you only pay for traffic you actually serve.

Leaving beta means you can rely on it for real workloads. The [limitations page](https://www.prisma.io/docs/compute/limitations) now lists the current limits rather than a beta caveat, and [pricing](https://www.prisma.io/docs/compute/pricing) is published and in effect from today:

- The Free plan includes 1 million requests, 360 GB-hours of memory, 4 vCPU-hours, and 10 GB of outbound bandwidth each month. It never bills for usage. If a Free workspace goes past a limit, its apps pause until the next cycle or an upgrade.
- Paid plans include 5, 20, or 100 million requests a month. Beyond that you pay `$1` per million requests, `$0.006` per GB-hour of memory, `$0.064` per vCPU-hour, and `$0.025` per GB sent.

You can see where your usage goes on the [Console](https://console.prisma.io) Usage page, which breaks requests, memory, CPU, and bandwidth down by day, by app, and by response status. The Workspace Overview shows Compute requests alongside your Prisma Postgres operations, so one screen tells you what the month will cost.

## Let anyone deploy your app in one click

A Deploy Button turns a public repository into a running app. Put it in your README or a blog post, and whoever clicks it picks a workspace and a GitHub account. Prisma copies the repository, adds a deploy workflow, provisions whatever the app needs (such as a Prisma Postgres database), and deploys it. From then on, every push to the copy deploys again. Nobody has to clone anything or write configuration.

The button is a link to the Console with your repository URL:

```text
https://console.prisma.io/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fowner%2Frepo
```

The [Deploy Button page](https://www.prisma.io/docs/compute/deploy-button) generates the badge for you and explains what the repository needs: a [Prisma Composer](https://www.prisma.io/docs/composer) config at the root, a build script, and one lockfile.

![The Deploy Button generator in the Prisma docs: a repository URL field, optional destination name and attribution source, and the generated Deploy with Prisma badge.](/changelog/2026-08-28-deploy-button-generator.png)

If you want a starting point rather than a blank project, the new [Prisma apps directory](https://www.prisma.io/apps) collects open-source TypeScript starters that deploy the same way. The same catalog is the first option on the Console's New project page.

![The Prisma apps directory listing open-source starters, each with a Use this app button and a link to the source.](/changelog/2026-08-28-prisma-apps-directory.png)

## Prisma 8 is now `prisma@latest`

Running `npm install prisma@latest` now gives you Prisma 8, the release previously announced as Prisma Next. It ships as the `8.0.0` release candidate line. Prisma 7 stays fully supported as `prisma@prev`, with its docs at [/docs/orm/v7](https://www.prisma.io/docs/orm/v7).

Getting started is simpler than it was in Early Access. Your app depends on one ORM package for its database, `@prisma/orm-postgres` or `@prisma/orm-mongo`, plus the `prisma` CLI. There is no separate `prisma-next` binary anymore: one `prisma` command handles ORM work like `contract emit` and `migrate` as well as platform work like `deploy`, and everything reads a single `prisma.config.ts`.

```ts title="prisma.config.ts"
import "dotenv/config";
import { defineConfig } from "@prisma/cli-engine";
import { defineConfig as ormConfig } from "@prisma/orm-postgres/config";

export default defineConfig({
  orm: ormConfig({
    contract: "./src/prisma/contract.prisma",
    db: { connection: process.env["DATABASE_URL"]! },
  }),
});
```

Start with the [Prisma 8 overview](https://www.prisma.io/docs/orm) and the [core concepts](https://www.prisma.io/docs/orm/core-concepts) page. If you are on Prisma 7, the [incremental upgrade guide](https://www.prisma.io/docs/guides/upgrade-prisma-orm/postgresql) lets you run both versions against the same database and move one module at a time.

## What you need to do

- **On an earlier Prisma 8 release candidate:** install `prisma@latest`, replace `prisma-next` with `prisma` in your scripts, move your config into `prisma.config.ts` as shown above, rename `.take()` and `.skip()` to `.limit()` and `.offset()`, and rename `db.sql.raw` to `db.raw.sql`.
- **CI that runs `db verify`, `db sign`, or `migration check`:** these commands now exit `4` when they find something, not `1`. Update the check or your pipeline will read findings as crashes.
- **Calling `/v1/apps` in the REST API:** the routes still work but are deprecated. Switch to the identical `/v1/services` routes.
- **Prisma Compute projects that build on the platform when you push:** this flow is being replaced by deploys from your own GitHub Actions. Affected projects show a notice in the Console with a one-click switch that opens a setup pull request. Merge it before the cutoff date in the notice.
- **On Prisma 7:** nothing changes. If you install with a `latest` tag anywhere, pin `prisma@prev` or `prisma@7.10.0`.

## Breaking changes

All of these are in Prisma 8, on the release candidate line.

- `.take(n)` and `.skip(n)` are now `.limit(n)` and `.offset(n)` on every collection type, including relation refinements, grouped collections, and MongoDB collections. Behavior is unchanged. ([prisma/orm#30112](https://github.com/prisma/orm/pull/30112))
- The `prisma-next` CLI is no longer published. Install `prisma@latest`, rename `prisma-next.config.ts` to `prisma.config.ts` wrapped in `defineConfig({ orm: … })`, and run the same commands under `prisma`. ([prisma/orm#30005](https://github.com/prisma/orm/pull/30005), [prisma/orm#30058](https://github.com/prisma/orm/pull/30058))
- Whole-query raw SQL moves from `db.sql.raw` to `db.raw.sql`. You can now name a storage namespace `raw`. ([prisma/orm#30045](https://github.com/prisma/orm/pull/30045))
- `db verify`, `db sign`, and `migration check` exit `4` on findings and `2` when they cannot run. Exit `1` now means a CLI bug. ([prisma/orm#29984](https://github.com/prisma/orm/pull/29984))
- `.aggregate()` and `.groupBy()` now honor `limit`, `offset`, `cursor`, and `distinct` set earlier in the chain. These used to be dropped silently, so a chain that combines them returns a different, and now correct, number. Chains without a row scope are unaffected. ([prisma/orm#30067](https://github.com/prisma/orm/pull/30067), [prisma/orm#30092](https://github.com/prisma/orm/pull/30092))

## Deprecations

- **REST API:** `/v1/apps` routes are deprecated in favor of `/v1/services`, which behave identically with `serviceId` in place of `appId`. Both work during the migration period.
- **Prisma Compute:** platform builds triggered by a GitHub push (the classic import flow) are deprecated in favor of [deploy on push](https://www.prisma.io/docs/compute/deploy-on-push) from GitHub Actions.

## Prisma Compute

Deploys now run inside your own repository's GitHub Actions, through `prisma/cloud-deploy-action`. This gives you a preview environment for every branch without any extra setup: a push to the default branch updates production, any other branch gets its own isolated environment, and deleting the branch removes it. You do not need to store a secret, because the workflow trades its GitHub OIDC token for a Prisma workspace token that expires after 30 minutes. The [deploy on push guide](https://www.prisma.io/docs/compute/deploy-on-push) covers setup, and the [GitHub page](https://www.prisma.io/docs/compute/github) explains what connecting a repository does.

Setting this up from the Console takes one pull request. Pick a repository on the New project page and the Console opens a PR that adds the deploy workflow and Composer configuration; merge it and your first push deploys. If the repository already has both, you get a "Connect repository" action instead. Before touching your repository, the Console checks that the app is within the supported framework boundary, on Prisma 8 or newer, and that the GitHub App has the permissions it needs, with a link to fix it if not.

![The Console's Set up your project page: start from a template, or set up manually with a project name, a region, and a repository to deploy from GitHub.](/changelog/2026-08-28-console-new-project.png)

Elsewhere in the Console:

- Creating a project is a single screen: name, region, then an app from the catalog, a GitHub repository, or an empty project. After you connect a repository, the project card tells you what happens next.
- Builds are listed per workspace and per project, and each build's page names the deployment and database it touched. A build that never reports back is labeled "Never reported" after thirty minutes instead of sitting in pending forever.
- Apps run as an unprivileged user with a read-only bundle. When an app binds only to `localhost` or listens on the wrong port, the runtime says so at boot. Those are the two most common reasons a fresh deploy is unreachable, and they used to be silent.

## Prisma Composer

[Prisma Composer](https://www.prisma.io/docs/composer), in Early Access, is what powers the Deploy Button and the apps directory. You can also use it directly to deploy an app made of several services with one command.

You describe your application in TypeScript: each service and what it depends on, whether that is other services, Prisma Postgres databases, [Object Store buckets](https://www.prisma.io/docs/storage), scheduled jobs, or secrets. `npx prisma@latest deploy module.ts` provisions everything on Prisma Compute and Prisma Postgres and wires up the authenticated connections between them. Run it again and only the difference is applied. `npx prisma@latest dev module.ts` runs the whole app on your machine against stand-in databases and buckets ([local development](https://www.prisma.io/docs/local-development)).

```ts title="src/storefront/service.ts"
import nextjs from "@prisma/composer/nextjs";
import { rpc } from "@prisma/composer/service-rpc";
import { compute } from "@prisma/composer-prisma-cloud";
import { catalogContract } from "../catalog/contract.ts";

export default compute({
  name: "storefront",
  deps: { catalog: rpc(catalogContract) },
  build: nextjs({ module: import.meta.url, appDir: ".." }),
});
```

The [core concepts](https://www.prisma.io/docs/composer/core-concepts) page explains apps, services, resources, contracts, and modules. To bring an existing Node.js, Bun, or Next.js app across, the [porting guide](https://www.prisma.io/docs/composer/porting-an-app) wraps the server code you already have and includes a prompt you can hand to a coding agent.

The Free plan now includes 200,000 operations per month, twice the previous limit. The [pricing page](https://www.prisma.io/pricing) lists every plan.

## REST API

The Management API is now called the [REST API](https://www.prisma.io/docs/rest-api); old links redirect. New this release:

- You can create, list, and revoke workspace service tokens with `POST`, `GET`, and `DELETE /v1/workspaces/{workspaceId}/service-tokens`. The token value is returned once, at creation. Previously the Console was the only way to manage them.
- `POST /v1/auth/github-actions/token` exchanges a GitHub Actions OIDC token for a workspace token that expires after 30 minutes, so CI never needs a long-lived secret.
- `POST /v1/builds` and `PATCH /v1/builds/{buildId}` let any deploy tool report a build and the resources it created, so it shows up in the Console like a platform build.
- `GET /v1/deployments/{deploymentId}/logs` returns a page of logs as newline-delimited JSON with a cursor for the next page. The WebSocket tail is unchanged.
- `GET /v1/workspaces/{workspaceId}/subscription` returns the plan name, whether usage is blocked, and the Console upgrade URL.
- Every `/v1/apps` route is also available at `/v1/services`, matching what the CLI calls the resource.

## Prisma 8

The release candidate line moved from `rc.1` to `rc.8` this month.

You can now declare `CHECK` constraints in your schema, so validation rules live in one place and travel with your migrations. `@@check` declares one on a model, and `contract infer` picks up constraints that already exist in the database. Enum and list columns get membership and non-null element checks automatically; `@noCheck` opts a column out. Renaming a model renames its constraints in place with a single `ALTER TABLE … RENAME CONSTRAINT`. ([prisma/orm#29892](https://github.com/prisma/orm/pull/29892), [prisma/orm#29894](https://github.com/prisma/orm/pull/29894), [prisma/orm#29928](https://github.com/prisma/orm/pull/29928), [prisma/orm#29972](https://github.com/prisma/orm/pull/29972))

```prisma
model Order {
  id    Int     @id
  total Decimal

  @@check(expression: "(total > (0)::numeric)", map: "positive_total")
}
```

Dates no longer lose information on the way through the ORM. PostgreSQL `date`, `timestamp`, `timestamptz`, and `time` columns read and write as `Temporal.PlainDate`, `Temporal.PlainDateTime`, `Temporal.Instant`, and `Temporal.PlainTime`. If you want the server's own text instead, declare `DateString` or `TimestampString(p)`. JavaScript `Date` no longer appears in the ORM's types. ([prisma/orm#30073](https://github.com/prisma/orm/pull/30073))

Raw SQL gets typed results. `db.raw.sql` runs a whole query from a tagged template; end it with `.returnsRow({ … })` for rows typed from your contract columns, or `.affectedCount()` for a mutation count. A row-typed query exposes `.returns`, so an outer query can reuse its columns in a `WITH` clause. This replaces `$queryRaw` and `$executeRaw`; see the [raw queries reference](https://www.prisma.io/docs/orm/reference/raw-queries). ([prisma/orm#29997](https://github.com/prisma/orm/pull/29997), [prisma/orm#30044](https://github.com/prisma/orm/pull/30044), [prisma/orm#30075](https://github.com/prisma/orm/pull/30075))

Also in this release:

- `count()`, `sum()`, and `avg()` return plain JavaScript numbers, with lossless `bigint` variants alongside. Two new column types let you choose per column: `BigIntNumber` reads as a `number` and throws outside the safe range, and `UnboundedInt` is exact at any size. Count-returning writes such as `updateAndCount()` take the count from the write itself, saving a `SELECT`. ([prisma/orm#29902](https://github.com/prisma/orm/pull/29902), [prisma/orm#29930](https://github.com/prisma/orm/pull/29930), [prisma/orm#29921](https://github.com/prisma/orm/pull/29921))
- The minimum PostgreSQL version is now 15, down from 17, so more existing databases can adopt Prisma 8. ([prisma/orm#29971](https://github.com/prisma/orm/pull/29971))
- `db update` will not run a plan that destroys data until you type the database name. `--yes` does not count; in CI, pass `--no-interactive --confirm <database>`. ([prisma/orm#29986](https://github.com/prisma/orm/pull/29986))
- `migration plan` refuses to plan from an empty database when migrations already exist. It used to generate a full `CREATE TABLE` package that failed against any real database. The `prisma-8` agent skill, now shipped inside the installed packages, teaches coding agents the same rule. See [how migrations work](https://www.prisma.io/docs/orm/migrations/how-migrations-work). ([prisma/orm#30122](https://github.com/prisma/orm/pull/30122), [prisma/orm#30096](https://github.com/prisma/orm/pull/30096), [prisma/orm#30123](https://github.com/prisma/orm/pull/30123))
- A database restart or a pooler dropping an idle connection no longer crashes your app. The PostgreSQL driver now handles pool-level errors, including on clients held open for a transaction. ([prisma/orm#30081](https://github.com/prisma/orm/pull/30081))
- Prisma 7 and 8 can live in the same project during an upgrade: `@prisma/prisma7` provides a `prisma7` binary, Prisma 7 prefers a `prisma7.config.ts` file when one exists, and the Prisma 8 language server only claims `.prisma` files that start with `// use prisma-next`. ([prisma/orm#29949](https://github.com/prisma/orm/pull/29949), [prisma/orm#30020](https://github.com/prisma/orm/pull/30020), [prisma/orm#30140](https://github.com/prisma/orm/pull/30140))

## Prisma Console and MCP server

The Console, docs, blog, and site now carry the new Prisma brand. The docs sidebar is grouped into Start, Build, Deploy, Manage, and Reference, and every CLI command is documented under [/docs/cli](https://www.prisma.io/docs/cli).

Signing in to the [Prisma MCP server](https://www.prisma.io/docs/ai/tools/mcp-server) now works from the Claude apps, which previously failed at registration, and from clients that enforce RFC 8414, such as fx.

## Fixes

**Prisma Compute**

- Repositories that use pnpm now build correctly: the generated deploy workflow installs pnpm and runs Composer under Bun.
- When an app from the catalog fails to deploy, the deploy card shows the error right away instead of spinning forever.

**Prisma Postgres**

- Backup sizes in the Console show the correct unit. A 23 GiB backup used to appear as `23.14 KiB`.

**Prisma 8**

- Queries with self-relation filters nested two or more levels deep, such as "users followed by people I follow", return the right rows. The inner filter used to override the outer one. ([prisma/orm#29900](https://github.com/prisma/orm/pull/29900))
- Counting or summing across a many-to-many relation works. It used to fail with a reference to a foreign key that does not exist. ([prisma/orm#29888](https://github.com/prisma/orm/pull/29888))
- Running the same `upsert` twice on a row keyed by a `Bytes` column succeeds. It used to fail on the second run with `ORM.MUTATION_ROW_MISSING`. ([prisma/orm#29910](https://github.com/prisma/orm/pull/29910))
- A hand-written migration that gives a non-`SERIAL` column an `autoincrement()` default now fails when you write it, with `CONTRACT.DEFAULT_INVALID`, rather than producing a column that silently has no sequence. ([prisma/orm#30040](https://github.com/prisma/orm/pull/30040))
- `upsert({ create })`, `createAll()`, and `createAndCount()` now flag nested relation callbacks as a type error. They were accepted before but never ran, so writes you expected did not happen. ([prisma/orm#30144](https://github.com/prisma/orm/pull/30144))
- On MongoDB, the `_id` you get back from `create()`, `update()`, `delete()`, or `upsert()` now matches what you read back later. ([prisma/orm#29879](https://github.com/prisma/orm/pull/29879))
- Migration error messages point to your actual migrations directory instead of always saying `migrations/`. ([prisma/orm#30041](https://github.com/prisma/orm/pull/30041))
- `migration graph --dot` prints output in the terminal again. ([prisma/orm#30057](https://github.com/prisma/orm/pull/30057))
- `prisma.config.ts` with Windows paths works in the editor. ([prisma/orm#30121](https://github.com/prisma/orm/pull/30121))
- Error messages link to the Prisma 8 error reference instead of the Prisma 7 one. ([prisma/orm#30126](https://github.com/prisma/orm/pull/30126))

**Prisma ORM 7**

- Prisma Migrate now stops you if `shadowDatabaseUrl` points at your main database, with the new error `P3025`. Before this, running `migrate diff --from-migrations` in that setup wiped the real schema and reported no changes. ([prisma/prisma-engines#5851](https://github.com/prisma/prisma-engines/pull/5851))

**Prisma Studio**

- Other websites open in your browser can no longer reach the database connected to Studio. Studio's local server now only accepts requests from Studio itself. ([prisma/orm#29890](https://github.com/prisma/orm/pull/29890))
