Prisma Compute leaves Public Beta with published pricing, a Free plan, and enforced limits. This release also introduces Deploy Buttons and the Prisma apps directory, and makes Prisma 8 available through `prisma@latest`.

## What general availability changes

[Prisma Compute](https://www.prisma.io/docs/compute) runs your TypeScript app next to [Prisma Postgres](https://www.prisma.io/docs/postgres), gives every Git branch its own environment, and scales to zero when idle. Three things changed at GA:

- [Pricing](https://www.prisma.io/docs/compute/pricing) is published and applies from today. Every plan includes a monthly request allowance. The Free plan includes 1 million requests, 360 GB-hours of memory, 4 vCPU-hours, and 10 GB of outbound bandwidth, and is never billed for usage. Paid plans include 5, 20, or 100 million requests and bill the rest per use: `$1` per million requests, `$0.006` per GB-hour of memory, `$0.064` per vCPU-hour, and `$0.025` per GB sent.
- Free plan limits are enforced. A Free workspace that exceeds a Compute limit has its apps stopped, and deployments, promotions, and rollbacks are refused until the next cycle or an upgrade.
- The docs no longer describe Compute as unsuitable for production workloads, and the "what's not in beta" limits are stated as current limits on the [limitations page](https://www.prisma.io/docs/compute/limitations).

The [Prisma Console](https://console.prisma.io) Usage page charts requests, memory, CPU, and bandwidth by day, split by app and by response status. The Workspace Overview shows Compute requests next to Prisma Postgres operations.

## Deploy Buttons and the Prisma apps directory

A Deploy Button lets someone deploy a copy of your public repository to Prisma Compute without cloning it or writing configuration. Put the button in a README or a blog post. Whoever clicks it picks a workspace and a GitHub account; Prisma copies the repository, adds a deploy workflow, and runs it. The workflow provisions whatever the app declares, such as a Prisma Postgres database, and deploys the app. Later pushes to the copy deploy again.

The button is a link to the Console with a repository URL:

```text
https://console.prisma.io/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fowner%2Frepo
```

The [Deploy Button page](https://www.prisma.io/docs/compute/deploy-button) generates the badge and lists what the repository needs: a [Prisma Composer](https://www.prisma.io/docs/composer) config at the root, a build script, and one lockfile.

![The Deploy Button generator in the Prisma docs: a repository URL field, optional destination name and attribution source, and the generated Deploy with Prisma badge.](/changelog/2026-08-28-deploy-button-generator.png)

The [Prisma apps directory](https://www.prisma.io/apps) lists open-source TypeScript starters that deploy the same way. The same catalog is the first option on the Console's New project page.

![The Prisma apps directory listing open-source starters, each with a Use this app button and a link to the source.](/changelog/2026-08-28-prisma-apps-directory.png)

## Prisma 8 through `prisma@latest`

`npm install prisma@latest` installs Prisma 8. Prisma 8 (previously announced as Prisma Next) is published as the `8.0.0` release candidate line under the `latest` tag. Prisma 7 remains fully supported as `prisma@prev`, with docs at [/docs/orm/v7](https://www.prisma.io/docs/orm/v7).

Setup is simpler than during Early Access. An app depends on one ORM package for its database, `@prisma/orm-postgres` or `@prisma/orm-mongo`, plus the `prisma` CLI. The separate `prisma-next` binary is gone: the same `prisma` command runs ORM commands such as `contract emit` and `migrate`, and platform commands such as `deploy`. Both read `prisma.config.ts`.

```ts title="prisma.config.ts"
import "dotenv/config";
import { defineConfig } from "@prisma/cli-engine";
import { defineConfig as ormConfig } from "@prisma/orm-postgres/config";

export default defineConfig({
  orm: ormConfig({
    contract: "./src/prisma/contract.prisma",
    db: { connection: process.env["DATABASE_URL"]! },
  }),
});
```

The [Prisma 8 overview](https://www.prisma.io/docs/orm) explains the model and the new [core concepts](https://www.prisma.io/docs/orm/core-concepts) page defines the vocabulary. To upgrade from Prisma 7, follow the [incremental upgrade guide](https://www.prisma.io/docs/guides/upgrade-prisma-orm/postgresql), which runs both versions side by side against the same database.

## Required actions for existing users

- Prisma 8 projects on an earlier release candidate: install `prisma@latest`, replace `prisma-next` with `prisma` in scripts, move the config into `prisma.config.ts` as shown above, rename `.take()` and `.skip()` to `.limit()` and `.offset()`, and rename `db.sql.raw` to `db.raw.sql`.
- CI steps that run `db verify`, `db sign`, or `migration check`: these commands now exit `4` on findings, not `1`. Update the check.
- REST API clients calling `/v1/apps` routes: the routes still work but are deprecated. Move to the identical `/v1/services` routes.
- Prisma Compute projects that build on the platform when you push: that flow is being replaced by deploys from your own GitHub Actions. Affected projects show a notice in the Console with a one-click switch that opens a setup pull request. Merge it before the cutoff date in the notice.
- Prisma 7 projects: nothing to do. Pin `prisma@prev` or `prisma@7.10.0` anywhere you install with a `latest` tag.

## Breaking changes

All in Prisma 8, on the release candidate line.

- The ORM pagination methods `.take(n)` and `.skip(n)` are renamed to `.limit(n)` and `.offset(n)` on every collection type, including relation refinements, grouped collections, and MongoDB collections. Semantics are unchanged. ([prisma/orm#30112](https://github.com/prisma/orm/pull/30112))
- The `prisma-next` CLI is no longer published. Install `prisma@latest`, rename `prisma-next.config.ts` to `prisma.config.ts` wrapped in `defineConfig({ orm: … })`, and run the same commands under `prisma`. ([prisma/orm#30005](https://github.com/prisma/orm/pull/30005), [prisma/orm#30058](https://github.com/prisma/orm/pull/30058))
- Whole-query raw SQL moves from `db.sql.raw` to `db.raw.sql`. A storage namespace named `raw` is now allowed. ([prisma/orm#30045](https://github.com/prisma/orm/pull/30045))
- `db verify`, `db sign`, and `migration check` exit `4` on findings and `2` when they cannot run. Exit `1` is reserved for CLI bugs. ([prisma/orm#29984](https://github.com/prisma/orm/pull/29984))
- `.aggregate()` and `.groupBy()` now respect `limit`, `offset`, `cursor`, and `distinct` earlier in the chain. Those clauses used to be dropped silently, so an existing chain that combines them returns a different, correct number. Chains without a row scope are unchanged. ([prisma/orm#30067](https://github.com/prisma/orm/pull/30067), [prisma/orm#30092](https://github.com/prisma/orm/pull/30092))

## Deprecations

- REST API: `/v1/apps` routes are deprecated in favor of `/v1/services`, which behave identically with `serviceId` in place of `appId`. Both work during the migration period.
- Prisma Compute: platform builds triggered by a GitHub push (the classic import flow) are deprecated in favor of [deploy on push](https://www.prisma.io/docs/compute/deploy-on-push) from GitHub Actions.

## Prisma Compute

This release also changes how apps are deployed from GitHub. Deploys now run in your repository's own GitHub Actions through `prisma/cloud-deploy-action`. A push to the default branch updates production; any other branch gets an isolated preview environment, and deleting the branch removes it. The workflow needs no stored secret, because it exchanges its GitHub OIDC token for a Prisma workspace token that expires after 30 minutes. The [deploy on push guide](https://www.prisma.io/docs/compute/deploy-on-push) walks through the setup and the [GitHub page](https://www.prisma.io/docs/compute/github) explains what the repository connection does.

In the Console, choosing a repository on the New project page opens a pull request that adds the deploy workflow and the Composer configuration; merge it and the first push deploys. A repository that already has both gets a "Connect repository" action instead. Before writing anything, the Console checks that the repository is within the supported framework boundary and on Prisma 8 or newer, and that the GitHub App has the permissions it needs, linking to the settings page if not.

![The Console's Set up your project page: start from a template, or set up manually with a project name, a region, and a repository to deploy from GitHub.](/changelog/2026-08-28-console-new-project.png)

Other Console changes:

- Project creation is a single screen: name, region, then an app from the catalog, a GitHub repository, or an empty project. After connecting a repository, the project card lists what happens next: push to the default branch, watch the workflow, wait for the first deploy.
- Builds are listed per workspace and per project. A build's detail page names the deployment and database it acted on. A build that never reported back is labeled "Never reported" after thirty minutes instead of showing as pending indefinitely.
- Apps run as an unprivileged user with a read-only bundle. The runtime warns at boot when an app binds only to `localhost` or listens on a port other than the configured one, the two most common reasons a deploy comes up unreachable.

## Prisma Composer

[Prisma Composer](https://www.prisma.io/docs/composer), in Early Access, is what the Deploy Button and the apps directory run on. You can also use it directly for an app made of several services.

You describe the application in TypeScript: each service and what it depends on, such as other services, Prisma Postgres databases, [Object Store buckets](https://www.prisma.io/docs/storage), scheduled jobs, and secrets. `npx prisma@latest deploy module.ts` provisions the services on Prisma Compute and the databases on Prisma Postgres and wires the authenticated connections between them; running it again applies only the difference. `npx prisma@latest dev module.ts` runs the whole app locally against stand-in databases and buckets ([local development](https://www.prisma.io/docs/local-development)).

```ts title="src/storefront/service.ts"
import nextjs from "@prisma/composer/nextjs";
import { rpc } from "@prisma/composer/service-rpc";
import { compute } from "@prisma/composer-prisma-cloud";
import { catalogContract } from "../catalog/contract.ts";

export default compute({
  name: "storefront",
  deps: { catalog: rpc(catalogContract) },
  build: nextjs({ module: import.meta.url, appDir: ".." }),
});
```

The [core concepts](https://www.prisma.io/docs/composer/core-concepts) page defines apps, services, resources, contracts, and modules. The [porting guide](https://www.prisma.io/docs/composer/porting-an-app) brings an existing Node.js, Bun, or Next.js app across by wrapping the server code you already have, and includes a prompt for a coding agent.

## Prisma Postgres

The Free plan now includes 200,000 operations per month, up from 100,000. The [pricing page](https://www.prisma.io/pricing) lists every plan's limits.

## REST API

The Management API is now the [REST API](https://www.prisma.io/docs/rest-api); old links redirect. New endpoints:

- `POST`, `GET`, and `DELETE /v1/workspaces/{workspaceId}/service-tokens` create, list, and revoke workspace service tokens. The token value is returned once, at creation. Until now the Console was the only way to manage them.
- `POST /v1/auth/github-actions/token` exchanges a GitHub Actions OIDC token for a workspace token that expires after 30 minutes.
- `POST /v1/builds` and `PATCH /v1/builds/{buildId}` let any deploy tool report a build and the resources it created, so it appears in the Console like a platform build.
- `GET /v1/deployments/{deploymentId}/logs` returns one page of logs as newline-delimited JSON, ending with a cursor for the next page. The WebSocket tail is unchanged.
- `GET /v1/workspaces/{workspaceId}/subscription` returns the plan name, whether usage is blocked, and the Console upgrade URL.
- Every `/v1/apps` route is also mounted at `/v1/services`, matching what the CLI calls the resource.

## Prisma 8

The release candidate line moved from `rc.1` to `rc.8` this month.

`CHECK` constraints can now be declared in the schema. `@@check` declares one on a model, and `contract infer` adopts constraints that already exist in the database. Enum and list columns get membership and non-null element checks automatically; `@noCheck` opts a column out. Renaming a model renames its constraints in place with a single `ALTER TABLE … RENAME CONSTRAINT`. ([prisma/orm#29892](https://github.com/prisma/orm/pull/29892), [prisma/orm#29894](https://github.com/prisma/orm/pull/29894), [prisma/orm#29928](https://github.com/prisma/orm/pull/29928), [prisma/orm#29972](https://github.com/prisma/orm/pull/29972))

```prisma
model Order {
  id    Int     @id
  total Decimal

  @@check(expression: "(total > (0)::numeric)", map: "positive_total")
}
```

PostgreSQL `date`, `timestamp`, `timestamptz`, and `time` columns read and write as `Temporal.PlainDate`, `Temporal.PlainDateTime`, `Temporal.Instant`, and `Temporal.PlainTime`. Declare `DateString` or `TimestampString(p)` to get the server's own text instead. JavaScript `Date` no longer appears in the ORM's types. ([prisma/orm#30073](https://github.com/prisma/orm/pull/30073))

`db.raw.sql` runs a whole query from a tagged template. End it with `.returnsRow({ … })` for typed rows from contract columns or `.affectedCount()` for a mutation count; a row-typed query exposes `.returns` so an outer query can reuse its columns in a `WITH` clause. This replaces `$queryRaw` and `$executeRaw`; see the [raw queries reference](https://www.prisma.io/docs/orm/reference/raw-queries). ([prisma/orm#29997](https://github.com/prisma/orm/pull/29997), [prisma/orm#30044](https://github.com/prisma/orm/pull/30044), [prisma/orm#30075](https://github.com/prisma/orm/pull/30075))

Smaller changes:

- `count()`, `sum()`, and `avg()` return JavaScript numbers, with lossless `bigint` variants alongside. New column types `BigIntNumber` (reads as a `number`, throws outside the safe range) and `UnboundedInt` (exact at any size) choose the integer representation per column. Count-returning writes such as `updateAndCount()` take the count from the write itself instead of a preceding `SELECT`. ([prisma/orm#29902](https://github.com/prisma/orm/pull/29902), [prisma/orm#29930](https://github.com/prisma/orm/pull/29930), [prisma/orm#29921](https://github.com/prisma/orm/pull/29921))
- The minimum PostgreSQL version is 15, down from 17. ([prisma/orm#29971](https://github.com/prisma/orm/pull/29971))
- `db update` refuses a plan that destroys data until you type the database name; `--yes` does not count, and CI passes `--no-interactive --confirm <database>`. ([prisma/orm#29986](https://github.com/prisma/orm/pull/29986))
- `migration plan` refuses to plan from an empty database when migrations already exist. It used to produce a full `CREATE TABLE` package that failed on any real database. The `prisma-8` agent skill, now shipped inside the installed packages, teaches coding agents the same rule. See [how migrations work](https://www.prisma.io/docs/orm/migrations/how-migrations-work). ([prisma/orm#30122](https://github.com/prisma/orm/pull/30122), [prisma/orm#30096](https://github.com/prisma/orm/pull/30096), [prisma/orm#30123](https://github.com/prisma/orm/pull/30123))
- The PostgreSQL driver attaches pool-level error handlers, including for clients held for a transaction, so a database restart or a pooler dropping an idle connection no longer crashes the app. ([prisma/orm#30081](https://github.com/prisma/orm/pull/30081))
- Prisma 7 and 8 can share a project: `@prisma/prisma7` provides a `prisma7` binary, Prisma 7 prefers a `prisma7.config.ts` file when one exists, and the Prisma 8 language server only claims `.prisma` files that start with `// use prisma-next`. ([prisma/orm#29949](https://github.com/prisma/orm/pull/29949), [prisma/orm#30020](https://github.com/prisma/orm/pull/30020), [prisma/orm#30140](https://github.com/prisma/orm/pull/30140))

## Prisma Console and MCP server

The Console, docs, blog, and site carry the new Prisma brand. The docs sidebar is grouped into Start, Build, Deploy, Manage, and Reference, and every CLI command lives under [/docs/cli](https://www.prisma.io/docs/cli).

Two sign-in fixes for the [Prisma MCP server](https://www.prisma.io/docs/ai/tools/mcp-server): connecting from the Claude apps no longer fails at registration, and clients that enforce RFC 8414, such as fx, can authenticate.

## Fixes

Prisma Compute

- The generated deploy workflow installs pnpm for repositories that use it and runs Composer under Bun.
- The deploy card for an app from the catalog shows the first deploy failure instead of waiting indefinitely.

Prisma Postgres

- Backup sizes on the Console backups page show the correct unit. A 23 GiB backup rendered as `23.14 KiB`.

Prisma 8

- Self-relation predicates nested two or more levels deep, such as `following.some(f => f.following.some(...))`, no longer let the inner scope shadow the outer one. ([prisma/orm#29900](https://github.com/prisma/orm/pull/29900))
- `count()`, `sum()`, and other scalar includes on many-to-many relations go through the junction table instead of referencing a foreign key that does not exist. ([prisma/orm#29888](https://github.com/prisma/orm/pull/29888))
- Repeating an `upsert` keyed on a `Bytes` column no longer fails with `ORM.MUTATION_ROW_MISSING`. ([prisma/orm#29910](https://github.com/prisma/orm/pull/29910))
- A hand-written migration column with an `autoincrement()` default and a non-`SERIAL` type fails at authoring time with `CONTRACT.DEFAULT_INVALID` instead of emitting a column with no sequence. ([prisma/orm#30040](https://github.com/prisma/orm/pull/30040))
- `upsert({ create })`, `createAll()`, and `createAndCount()` reject nested relation callbacks at compile time, since those paths never executed them. ([prisma/orm#30144](https://github.com/prisma/orm/pull/30144))
- MongoDB `create()`, `update()`, `delete()`, and `upsert()` decode their results through the column codecs, so a created `_id` matches the value read back. ([prisma/orm#29879](https://github.com/prisma/orm/pull/29879))
- Migration errors name the configured migrations directory instead of a hardcoded `migrations/`. ([prisma/orm#30041](https://github.com/prisma/orm/pull/30041))
- `migration graph --dot` prints on a terminal again. ([prisma/orm#30057](https://github.com/prisma/orm/pull/30057))
- The language server recognizes Windows paths in `prisma.config.ts`. ([prisma/orm#30121](https://github.com/prisma/orm/pull/30121))
- Structured errors link to `/docs/orm/v8/reference/error-reference`. ([prisma/orm#30126](https://github.com/prisma/orm/pull/30126))

Prisma ORM 7

- Prisma Migrate refuses a `shadowDatabaseUrl` that points at the main database, with the new error `P3025`. Until now `migrate diff --from-migrations` with that configuration reset the real schema and reported an empty diff. ([prisma/prisma-engines#5851](https://github.com/prisma/prisma-engines/pull/5851))

Prisma Studio

- Studio's local server binds to `127.0.0.1` only and rejects browser requests from other origins, so a website open in the same browser can no longer reach the connected database. ([prisma/orm#29890](https://github.com/prisma/orm/pull/29890))
