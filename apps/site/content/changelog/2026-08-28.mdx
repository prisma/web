**You can now run production apps on Prisma Compute.** Pricing is published, the Free plan is generous, and every branch gets its own environment. Two more things ship today: **Deploy Buttons**, which let anyone launch your app from a README in one click, and **Prisma 8 as `prisma@latest`**.

## Prisma Compute is ready for production

[Prisma Compute](https://www.prisma.io/docs/compute) runs your TypeScript app next to your [Prisma Postgres](https://www.prisma.io/docs/postgres) database. Apps scale to zero when idle, so you *only pay for traffic you serve*.

[Pricing](https://www.prisma.io/docs/compute/pricing) applies from today:

- **Free:** 1 million requests, 360 GB-hours of memory, 4 vCPU-hours, and 10 GB of bandwidth a month, *never billed*. Past a limit, apps pause until the next month or an upgrade.
- **Paid:** 5, 20, or 100 million requests a month included, then `$1` per million requests, `$0.006` per GB-hour, `$0.064` per vCPU-hour, and `$0.025` per GB sent.

The [Console](https://console.prisma.io) Usage page shows **where the money goes**: requests, memory, CPU, and bandwidth by day, by app, and by response status.

## Anyone can deploy your app in one click

Add a Deploy Button to your README. Whoever clicks it gets **a running copy of your app, with its own database, in their own workspace**. *No cloning, no configuration.* Every push to their copy deploys again.

The button is a link:

```text
https://console.prisma.io/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fowner%2Frepo
```

The [Deploy Button page](https://www.prisma.io/docs/compute/deploy-button) generates the badge and lists the three things your repository needs: a [Composer](https://www.prisma.io/docs/composer) config, a build script, and a lockfile.

![The Deploy Button generator in the Prisma docs: a repository URL field, optional destination name and attribution source, and the generated Deploy with Prisma badge.](/changelog/2026-08-28-deploy-button-generator.png)

Need a starting point? The [Prisma apps directory](https://www.prisma.io/apps) lists open-source starters that deploy the same way. They are also the first option when you create a project in the Console.

## Prisma 8 is now `prisma@latest`

**`npm install prisma@latest` installs Prisma 8** (previously Prisma Next). Prisma 7 *stays supported* as `prisma@prev` ([docs](https://www.prisma.io/docs/orm/v7)).

**Setup is one config file and one CLI.** Install `@prisma/orm-postgres` or `@prisma/orm-mongo` plus `prisma`. The same `prisma` command handles migrations and deploys, and reads `prisma.config.ts`:

```ts title="prisma.config.ts"
import "dotenv/config";
import { defineConfig } from "@prisma/cli-engine";
import { defineConfig as ormConfig } from "@prisma/orm-postgres/config";

export default defineConfig({
  orm: ormConfig({
    contract: "./src/prisma/contract.prisma",
    db: { connection: process.env["DATABASE_URL"]! },
  }),
});
```

New to Prisma 8? Start with the [overview](https://www.prisma.io/docs/orm) and [core concepts](https://www.prisma.io/docs/orm/core-concepts). On Prisma 7? The [upgrade guide](https://www.prisma.io/docs/guides/upgrade-prisma-orm/postgresql) runs both versions against the same database so you can move one module at a time.

## What you need to do

- **On Prisma 7:** *nothing*. If you install with a `latest` tag anywhere, pin `prisma@prev`.
- **On an earlier Prisma 8 release candidate:** install `prisma@latest`, replace `prisma-next` with `prisma`, move your config to `prisma.config.ts` as above, rename `.take()`/`.skip()` to `.limit()`/`.offset()`, and rename `db.sql.raw` to `db.raw.sql`.
- **CI that runs `db verify`, `db sign`, or `migration check`:** findings now exit `4`, not `1`. *Update the check.*
- **Calling `/v1/apps` in the REST API:** switch to `/v1/services`. Same routes, same behavior, `serviceId` instead of `appId`. See the [REST API reference](https://www.prisma.io/docs/rest-api).
- **Compute projects that build on push:** move to deploys from your own GitHub Actions. The Console shows a notice with a one-click switch that opens a setup pull request. *Merge it before the cutoff in the notice.*

## Breaking changes

All in Prisma 8.

- `.take(n)` and `.skip(n)` are now `.limit(n)` and `.offset(n)` everywhere, including relations, groups, and MongoDB. Same behavior. ([#30112](https://github.com/prisma/orm/pull/30112))
- The `prisma-next` CLI is gone. Use `prisma@latest` and `prisma.config.ts`. ([#30005](https://github.com/prisma/orm/pull/30005), [#30058](https://github.com/prisma/orm/pull/30058))
- Raw SQL moves from `db.sql.raw` to `db.raw.sql` ([reference](https://www.prisma.io/docs/orm/reference/raw-queries#postgresql-raw-sql)). ([#30045](https://github.com/prisma/orm/pull/30045))
- `db verify`, `db sign`, and `migration check` exit `4` on findings and `2` when they cannot run. ([#29984](https://github.com/prisma/orm/pull/29984))
- `.aggregate()` and `.groupBy()` now respect `limit`, `offset`, `cursor`, and `distinct` earlier in the chain. They used to be dropped silently, so those queries now return a *different, correct* number. ([#30067](https://github.com/prisma/orm/pull/30067), [#30092](https://github.com/prisma/orm/pull/30092))

## Deprecations

- **REST API:** `/v1/apps` routes, in favor of `/v1/services`. Both work for now. ([reference](https://www.prisma.io/docs/rest-api))
- **Prisma Compute:** platform builds on GitHub push, in favor of [deploy on push](https://www.prisma.io/docs/compute/deploy-on-push) from GitHub Actions.

## Prisma Compute

**Every branch now gets its own preview environment**, with no extra setup. Deploys run in your repository's GitHub Actions via `prisma/cloud-deploy-action`: the default branch is production, any other branch is a preview, and deleting the branch deletes the preview. *No secrets to store*; the workflow authenticates with GitHub's OIDC token. Setup is in the [deploy on push guide](https://www.prisma.io/docs/compute/deploy-on-push).

From the Console, it is **one pull request**: pick a repository, merge the PR the Console opens, push. The Console checks first that the app is on Prisma 8 and within the supported framework boundary, and that the GitHub App has the permissions it needs.

![The Console's Set up your project page: start from a template, or set up manually with a project name, a region, and a repository to deploy from GitHub.](/changelog/2026-08-28-console-new-project.png)

Also in the Console:

- Creating a project is one screen: name, region, then a starter, a repository, or nothing.
- Every build has a page naming the deployment and database it touched. Builds that never report back are marked as such after 30 minutes instead of staying "pending" forever.
- If your app is unreachable after deploy, the boot log now *tells you why* in the two common cases: bound to `localhost`, or listening on the wrong port.

## Prisma Composer

[Prisma Composer](https://www.prisma.io/docs/composer) (Early Access) deploys an app made of several services with **one command**. It is what the Deploy Button runs on, and you can use it directly.

Describe each service and what it needs in TypeScript: other services, databases, [buckets](https://www.prisma.io/docs/storage), scheduled jobs, secrets. `npx prisma@latest deploy module.ts` provisions all of it and wires the connections; run it again and *only the diff applies*. `npx prisma@latest dev module.ts` runs the whole app [locally](https://www.prisma.io/docs/local-development).

```ts title="src/storefront/service.ts"
import nextjs from "@prisma/composer/nextjs";
import { rpc } from "@prisma/composer/service-rpc";
import { compute } from "@prisma/composer-prisma-cloud";
import { catalogContract } from "../catalog/contract.ts";

export default compute({
  name: "storefront",
  deps: { catalog: rpc(catalogContract) },
  build: nextjs({ module: import.meta.url, appDir: ".." }),
});
```

Read [core concepts](https://www.prisma.io/docs/composer/core-concepts) first. To move an existing Node.js, Bun, or Next.js app over, the [porting guide](https://www.prisma.io/docs/composer/porting-an-app) includes a prompt for your coding agent.

## REST API

The Management API is now the **[REST API]**(https://www.prisma.io/docs/rest-api); old links redirect. New endpoints:

- **Manage service tokens without the Console:** [create](https://www.prisma.io/docs/rest-api/endpoints/service-tokens/post-workspaces-by-workspace-id-service-tokens), [list](https://www.prisma.io/docs/rest-api/endpoints/service-tokens/get-workspaces-by-workspace-id-service-tokens), and [revoke](https://www.prisma.io/docs/rest-api/endpoints/service-tokens/delete-workspaces-by-workspace-id-service-tokens-by-service-token-id) at `/v1/workspaces/{workspaceId}/service-tokens`.
- **CI without long-lived secrets:** `POST /v1/auth/github-actions/token` swaps a GitHub Actions OIDC token for a 30-minute workspace token. See [authentication](https://www.prisma.io/docs/rest-api/authentication).
- **Bring your own deploy tool:** `POST /v1/builds` and `PATCH /v1/builds/{buildId}` report a build so it appears in the Console like any other.
- **Page through logs:** `GET /v1/deployments/{deploymentId}/logs` returns newline-delimited JSON with a cursor.
- **Check a plan from code:** [`GET /v1/workspaces/{workspaceId}/subscription`](https://www.prisma.io/docs/rest-api/endpoints/workspaces/get-workspaces-by-id-subscription) returns the plan, whether usage is blocked, and the upgrade URL.
- Every `/v1/apps` route is also at `/v1/services`.

## Prisma 8

`rc.1` to `rc.8` this month. *Three things stand out.*

**Validation rules live in your schema.** `@@check` declares a `CHECK` constraint on a model, and `contract infer` picks up constraints already in the database. Enum and list columns get checks automatically; `@noCheck` opts out. ([#29892](https://github.com/prisma/orm/pull/29892), [#29894](https://github.com/prisma/orm/pull/29894), [#29928](https://github.com/prisma/orm/pull/29928), [#29972](https://github.com/prisma/orm/pull/29972))

```prisma
model Order {
  id    Int     @id
  total Decimal

  @@check(expression: "(total > (0)::numeric)", map: "positive_total")
}
```

**Dates keep their precision.** PostgreSQL date and time columns map to `Temporal` types instead of JavaScript `Date`. Declare `DateString` or `TimestampString(p)` if you want the server's text as-is. ([#30073](https://github.com/prisma/orm/pull/30073))

**Raw SQL is typed.** `db.raw.sql` runs a tagged-template query; finish with `.returnsRow({ … })` for typed rows or `.affectedCount()` for a count. It replaces `$queryRaw` and `$executeRaw`. See the [raw queries reference](https://www.prisma.io/docs/orm/reference/raw-queries#postgresql-raw-sql). ([#29997](https://github.com/prisma/orm/pull/29997), [#30044](https://github.com/prisma/orm/pull/30044), [#30075](https://github.com/prisma/orm/pull/30075))

Also:

- **A database restart or a dropped idle connection no longer crashes your app.** ([#30081](https://github.com/prisma/orm/pull/30081))
- **PostgreSQL 15 is now supported**, down from 17. ([#29971](https://github.com/prisma/orm/pull/29971))
- `count()`, `sum()`, and `avg()` return plain numbers, with `bigint` variants alongside. New `BigIntNumber` and `UnboundedInt` column types pick the representation per column. ([#29902](https://github.com/prisma/orm/pull/29902), [#29930](https://github.com/prisma/orm/pull/29930), [#29921](https://github.com/prisma/orm/pull/29921))
- `db update` *will not destroy data* until you type the database name. In CI, pass `--no-interactive --confirm <database>`. ([#29986](https://github.com/prisma/orm/pull/29986))
- `migration plan` refuses to start from an empty database when migrations already exist, which used to produce a package that failed everywhere. The bundled `prisma-8` agent skill teaches coding agents the same rule. ([how migrations work](https://www.prisma.io/docs/orm/migrations/how-migrations-work), [#30122](https://github.com/prisma/orm/pull/30122), [#30096](https://github.com/prisma/orm/pull/30096), [#30123](https://github.com/prisma/orm/pull/30123))
- Prisma 7 and 8 can share a project during an upgrade: `@prisma/prisma7` provides a `prisma7` binary and reads `prisma7.config.ts`. ([#29949](https://github.com/prisma/orm/pull/29949), [#30020](https://github.com/prisma/orm/pull/30020), [#30140](https://github.com/prisma/orm/pull/30140))

The Console, docs, blog, and site carry the new Prisma brand. Docs are grouped into Start, Build, Deploy, Manage, and Reference, and every CLI command is under [/docs/cli](https://www.prisma.io/docs/cli).

## Fixes

**Prisma Compute**

- **pnpm repositories deploy.** The generated workflow now installs pnpm.
- A failed deploy from the apps directory shows its error instead of spinning forever.

**Prisma Postgres**

- **Backup sizes show the right unit.** A 23 GiB backup no longer reads `23.14 KiB`.

**Prisma 8**

- **Filters like "users followed by people I follow" return the right rows.** Nested self-relation filters used to override each other. ([#29900](https://github.com/prisma/orm/pull/29900))
- **Counting or summing across a many-to-many relation works.** ([#29888](https://github.com/prisma/orm/pull/29888))
- Running the same `upsert` twice on a `Bytes` key succeeds. ([#29910](https://github.com/prisma/orm/pull/29910))
- A migration that gives a non-`SERIAL` column an `autoincrement()` default fails when you write it, not silently at runtime. ([#30040](https://github.com/prisma/orm/pull/30040))
- Nested relation callbacks in `upsert({ create })`, `createAll()`, and `createAndCount()` are now a type error. They never ran, so *writes you expected were being skipped*. ([#30144](https://github.com/prisma/orm/pull/30144))
- On MongoDB, the `_id` returned from a write matches what you read back. ([#29879](https://github.com/prisma/orm/pull/29879))
- Migration errors name your actual migrations directory. ([#30041](https://github.com/prisma/orm/pull/30041))
- `migration graph --dot` prints in the terminal again. ([#30057](https://github.com/prisma/orm/pull/30057))
- Windows paths work in `prisma.config.ts`. ([#30121](https://github.com/prisma/orm/pull/30121))
- Error messages link to the Prisma 8 error reference. ([#30126](https://github.com/prisma/orm/pull/30126))

**Prisma ORM 7**

- **Migrate now stops you if `shadowDatabaseUrl` points at your real database** (`P3025`). Before, `migrate diff --from-migrations` in that setup wiped your schema and reported nothing. ([prisma-engines#5851](https://github.com/prisma/prisma-engines/pull/5851))

**Prisma Studio**

- **Other websites open in your browser can no longer reach the database connected to Studio.** ([#29890](https://github.com/prisma/orm/pull/29890))
