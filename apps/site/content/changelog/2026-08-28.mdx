Prisma Compute is now generally available. This release also introduces Deploy Buttons and makes Prisma 8 available through `prisma@latest`.

It is the largest release since Prisma Compute entered Public Beta in June. The rest of this entry is ordered by how much it is likely to matter to you: the three headline changes first, then what existing users need to do, then the details by product.

## Three things that matter in this release

### Prisma Compute is generally available

[Prisma Compute](https://www.prisma.io/docs/compute) runs your TypeScript app next to [Prisma Postgres](https://www.prisma.io/docs/postgres), gives every Git branch its own environment, and scales to zero when nobody is using it. With the Public Beta over, it is ready for production workloads, and its [pricing](https://www.prisma.io/docs/compute/pricing) is published and enforced.

Every plan includes a monthly request allowance. The Free plan includes 1 million requests, 360 GB-hours of memory, 4 vCPU-hours, and 10 GB of outbound bandwidth, with no usage billing. Paid plans include 5, 20, or 100 million requests and bill the rest per use: `$1` per million requests, `$0.006` per GB-hour of memory, `$0.064` per vCPU-hour, and `$0.025` per GB sent.

The [Prisma Console](https://console.prisma.io) shows what you are using. The Usage page charts requests, memory, CPU, and bandwidth by day, split by app and by response status, and the Workspace Overview puts Compute requests next to Prisma Postgres operations.

### Deploy Buttons and the Prisma apps directory

A Deploy Button lets someone deploy a copy of your public repository to Prisma Compute without cloning it or writing any configuration. Put the button in a README or a blog post. Whoever clicks it picks a workspace and a GitHub account, and Prisma copies the repository, adds a deploy workflow, and runs it. The workflow provisions whatever the app declares, such as a Prisma Postgres database, and deploys the app. Later pushes to the copy deploy again.

The button is a link to the Console with a repository URL:

```text
https://console.prisma.io/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fowner%2Frepo
```

The [Deploy Button page](https://www.prisma.io/docs/compute/deploy-button) in the docs generates the badge for you and lists what the repository needs: a [Prisma Composer](https://www.prisma.io/docs/composer) config at the root, a build script, and one lockfile.

![The Deploy Button generator in the Prisma docs: a repository URL field, optional destination name and attribution source, and the generated Deploy with Prisma badge.](/changelog/2026-08-28-deploy-button-generator.png)

If you would rather start from something that already works, the new [Prisma apps directory](https://www.prisma.io/apps) lists open-source TypeScript starters that deploy the same way. The same catalog is the first option on the Console's New project page.

### Prisma 8 is available through `prisma@latest`

`npm install prisma@latest` now gives you Prisma 8. Prisma 8 (previously announced as Prisma Next) is published as the `8.0.0` release candidate line under the `latest` tag. Prisma 7 remains fully supported and is available as `prisma@prev`; its docs live at [/docs/orm/v7](https://www.prisma.io/docs/orm/v7).

Setup is simpler than it was during Early Access. Your app depends on one ORM package for its database, `@prisma/orm-postgres` or `@prisma/orm-mongo`, plus the `prisma` CLI. The separate `prisma-next` binary is gone: the same `prisma` command runs ORM commands like `contract emit` and `migrate`, and platform commands like `deploy`. Both read one config file, `prisma.config.ts`.

```ts title="prisma.config.ts"
import "dotenv/config";
import { defineConfig } from "@prisma/cli-engine";
import { defineConfig as ormConfig } from "@prisma/orm-postgres/config";

export default defineConfig({
  orm: ormConfig({
    contract: "./src/prisma/contract.prisma",
    db: { connection: process.env["DATABASE_URL"]! },
  }),
});
```

The [Prisma 8 overview](https://www.prisma.io/docs/orm) explains the model, and the new [core concepts](https://www.prisma.io/docs/orm/core-concepts) page defines the vocabulary. Upgrading from Prisma 7? The [incremental upgrade guide](https://www.prisma.io/docs/guides/upgrade-prisma-orm/postgresql) runs both versions side by side against the same database.

## What existing users need to do

Most people can skip this section. Check it if any of the following describes you.

**You use Prisma 8 from an earlier release candidate.** Install `prisma@latest`, replace `prisma-next` with `prisma` in your scripts, and move your config into `prisma.config.ts` as shown above. Then rename `.take()` and `.skip()` to `.limit()` and `.offset()`, and `db.sql.raw` to `db.raw.sql`. Details are under [breaking changes](#breaking-changes).

**You run `db verify`, `db sign`, or `migration check` in CI.** They now exit `4` when they find problems, not `1`. Update any step that checks for `1`.

**You call the REST API's `/v1/apps` routes.** They still work, but they are deprecated. Switch to the identical `/v1/services` routes when convenient.

**Your Prisma Compute project builds on the platform when you push.** That flow is being replaced by deploys from your own GitHub Actions. Affected projects show a notice in the Console with a one-click switch that opens a setup pull request. Merge it before the cutoff date shown in the notice.

**You use Prisma 7 and want to stay on it.** Nothing to do. Pin `prisma@prev` or `prisma@7.10.0` if you install with a `latest` tag anywhere.

## Breaking changes

All of these are in Prisma 8 and apply to projects on the release candidate line.

> **Breaking:** The ORM pagination methods `.take(n)` and `.skip(n)` are renamed to `.limit(n)` and `.offset(n)` on every collection type, including relation refinements, grouped collections, and MongoDB collections. Semantics are unchanged; rename the calls. ([prisma/orm#30112](https://github.com/prisma/orm/pull/30112))

> **Breaking:** The `prisma-next` CLI is no longer published. Install `prisma@latest`, rename `prisma-next.config.ts` to `prisma.config.ts` wrapped in `defineConfig({ orm: … })`, and run the same commands under `prisma`. ([prisma/orm#30005](https://github.com/prisma/orm/pull/30005), [prisma/orm#30058](https://github.com/prisma/orm/pull/30058))

> **Breaking:** Whole-query raw SQL moves from `db.sql.raw` to `db.raw.sql`. A storage namespace named `raw` is now allowed. ([prisma/orm#30045](https://github.com/prisma/orm/pull/30045))

> **Breaking:** `db verify`, `db sign`, and `migration check` exit `4` on findings and `2` when they cannot run. Exit `1` is reserved for CLI bugs. ([prisma/orm#29984](https://github.com/prisma/orm/pull/29984))

> **Breaking:** `.aggregate()` and `.groupBy()` now respect `limit`, `offset`, `cursor`, and `distinct` earlier in the chain. Until now those clauses were silently dropped and the aggregate covered every matching row, so an existing chain that combines them returns a different, correct number. Chains without a row scope are unchanged. ([prisma/orm#30067](https://github.com/prisma/orm/pull/30067), [prisma/orm#30092](https://github.com/prisma/orm/pull/30092))

## Deprecations

- **REST API:** `/v1/apps` routes are deprecated in favor of `/v1/services`, which behave identically with `serviceId` in place of `appId`. Both work during the migration period.
- **Prisma Compute:** platform builds triggered by a GitHub push (the classic import flow) are deprecated in favor of [deploy on push](https://www.prisma.io/docs/compute/deploy-on-push) from GitHub Actions. See the note above about the Console switch.

## Prisma Compute

Beyond general availability, the month went into how apps get to Prisma Compute from a repository.

**Deploy on push runs in your GitHub Actions.** Connect a repository and add a workflow that uses `prisma/cloud-deploy-action`. A push to the default branch updates production. Any other branch gets an isolated preview environment, and deleting the branch removes it. The workflow needs no stored secret: it exchanges its GitHub OIDC token for a Prisma workspace token that expires after 30 minutes. The [deploy on push guide](https://www.prisma.io/docs/compute/deploy-on-push) walks through it; the [GitHub page](https://www.prisma.io/docs/compute/github) explains what the connection does.

**The Console connects repositories with a pull request.** Choosing a repository on the New project page opens a pull request that adds the deploy workflow and the Composer configuration. Merge it and the first push deploys. A repository that already has both shows a **Connect repository** action instead. Before anything is written, the Console checks that the repository is within the supported framework boundary and uses Prisma 8 or newer, and it checks the GitHub App's permissions and links to the settings page if any are missing.

![The Console's Set up your project page: start from a template, or set up manually with a project name, a region, and a repository to deploy from GitHub.](/changelog/2026-08-28-console-new-project.png)

**Project creation is one screen.** Name the project, pick a region, then choose an app from the catalog, a GitHub repository, or an empty project. The card for a newly connected repository lists what happens next: push to the default branch, watch the workflow, and wait for the first deploy.

**Builds have their own pages.** The Console lists builds per workspace and per project. A build's detail page names the deployment and database it acted on, and a build that never reported back is labeled **Never reported** after thirty minutes instead of spinning forever.

**Free plan limits are enforced.** A Free workspace that exceeds a Compute limit has its apps stopped, and deployments, promotions, and rollbacks are refused until the next cycle or an upgrade. Paid plans are billed for the overage instead.

**Apps run with less privilege.** Every app runs as an unprivileged user with its bundle read-only. The runtime warns at boot when an app binds only to `localhost` or listens on a port other than the configured one, which are the two most common reasons a deploy comes up unreachable.

## Prisma Composer

[Prisma Composer](https://www.prisma.io/docs/composer) is in Early Access. It is how the Deploy Button and the apps directory work under the hood, and you can use it directly for an app made of several services.

You describe the application in TypeScript: each service, and what it depends on, such as other services, Prisma Postgres databases, [Object Store buckets](https://www.prisma.io/docs/storage), scheduled jobs, and secrets. `npx prisma@latest deploy module.ts` provisions the services on Prisma Compute and the databases on Prisma Postgres and wires the authenticated connections between them. Running it again applies only the difference. `npx prisma@latest dev module.ts` runs the whole app locally against stand-in databases and buckets; see [local development](https://www.prisma.io/docs/local-development).

```ts title="src/storefront/service.ts"
import nextjs from "@prisma/composer/nextjs";
import { rpc } from "@prisma/composer/service-rpc";
import { compute } from "@prisma/composer-prisma-cloud";
import { catalogContract } from "../catalog/contract.ts";

export default compute({
  name: "storefront",
  deps: { catalog: rpc(catalogContract) },
  build: nextjs({ module: import.meta.url, appDir: ".." }),
});
```

Two new pages help you get in: [core concepts](https://www.prisma.io/docs/composer/core-concepts) defines apps, services, resources, contracts, and modules, and the [porting guide](https://www.prisma.io/docs/composer/porting-an-app) brings an existing Node.js, Bun, or Next.js app across by wrapping the server code you already have. The porting guide includes a prompt you can hand to a coding agent.

The Free plan now includes 200,000 operations per month, up from 100,000. The [pricing page](https://www.prisma.io/pricing) lists every plan's limits.

## REST API

The Management API is now called the [REST API](https://www.prisma.io/docs/rest-api). Old links redirect. The month added five things, most of them in service of deploying from CI:

- `POST`, `GET`, and `DELETE /v1/workspaces/{workspaceId}/service-tokens` create, list, and revoke workspace service tokens. Until now the Console was the only way. The token value is returned once, at creation.
- `POST /v1/auth/github-actions/token` exchanges a GitHub Actions OIDC token for a workspace token that expires after 30 minutes. This is what lets a deploy workflow run without a stored Prisma secret.
- `POST /v1/builds` and `PATCH /v1/builds/{buildId}` let any deploy tool report a build and the resources it created, so a CI-run deploy shows up in the Console like a platform build.
- `GET /v1/deployments/{deploymentId}/logs` returns one page of logs as newline-delimited JSON and ends with a cursor for the next page. The WebSocket tail is unchanged.
- `GET /v1/workspaces/{workspaceId}/subscription` returns the plan name, whether usage is blocked, and the Console upgrade URL.

Every `/v1/apps` route is also mounted at `/v1/services`, matching what the CLI calls the resource.

## Prisma 8

The release candidate line moved from `rc.1` to `rc.8` during the month. The changes that affect what you can write:

**`CHECK` constraints live in the schema.** `@@check` declares one on a model, and `contract infer` adopts constraints that already exist in the database instead of ignoring them. Enum and list columns get membership and non-null element checks automatically; `@noCheck` opts a column out. Renaming a model renames its constraints in place with a single `ALTER TABLE … RENAME CONSTRAINT` rather than a drop and re-add. ([prisma/orm#29892](https://github.com/prisma/orm/pull/29892), [prisma/orm#29894](https://github.com/prisma/orm/pull/29894), [prisma/orm#29928](https://github.com/prisma/orm/pull/29928), [prisma/orm#29972](https://github.com/prisma/orm/pull/29972))

```prisma
model Order {
  id    Int     @id
  total Decimal

  @@check(expression: "(total > (0)::numeric)", map: "positive_total")
}
```

**Dates are `Temporal` values.** PostgreSQL `date`, `timestamp`, `timestamptz`, and `time` columns read and write as `Temporal.PlainDate`, `Temporal.PlainDateTime`, `Temporal.Instant`, and `Temporal.PlainTime`. If you want the server's own text instead, declare `DateString` or `TimestampString(p)`. JavaScript `Date` no longer appears in the ORM's types. ([prisma/orm#30073](https://github.com/prisma/orm/pull/30073))

**Raw SQL for a whole query.** `db.raw.sql` takes a tagged template. Finish it with `.returnsRow({ … })` to get typed rows from contract columns, or `.affectedCount()` for a mutation count. A row-typed query exposes `.returns`, so an outer query can reuse its columns in a `WITH` clause. This is the replacement for `$queryRaw` and `$executeRaw`; see the [raw queries reference](https://www.prisma.io/docs/orm/reference/raw-queries). ([prisma/orm#29997](https://github.com/prisma/orm/pull/29997), [prisma/orm#30044](https://github.com/prisma/orm/pull/30044), [prisma/orm#30075](https://github.com/prisma/orm/pull/30075))

**Aggregates return numbers.** `count()`, `sum()`, and `avg()` return JavaScript numbers, with lossless `bigint` variants alongside. For columns, `BigIntNumber` reads as a `number` and throws outside the safe range, and `UnboundedInt` round-trips exact values at any size. Count-returning writes such as `updateAndCount()` take the count from the write itself instead of a preceding `SELECT`. ([prisma/orm#29902](https://github.com/prisma/orm/pull/29902), [prisma/orm#29930](https://github.com/prisma/orm/pull/29930), [prisma/orm#29921](https://github.com/prisma/orm/pull/29921))

**PostgreSQL 15 is the floor**, down from 17. ([prisma/orm#29971](https://github.com/prisma/orm/pull/29971))

**Migrations refuse two common mistakes.** `db update` will not apply a plan that destroys data until you type the database name; `--yes` does not count, and CI passes `--no-interactive --confirm <database>`. `migration plan` refuses to plan from an empty database when migrations already exist, which used to produce a full `CREATE TABLE` package that failed on any real database. The `prisma-8` agent skill, which now ships inside the installed packages, teaches coding agents the same model. Read [how migrations work](https://www.prisma.io/docs/orm/migrations/how-migrations-work). ([prisma/orm#29986](https://github.com/prisma/orm/pull/29986), [prisma/orm#30122](https://github.com/prisma/orm/pull/30122), [prisma/orm#30096](https://github.com/prisma/orm/pull/30096), [prisma/orm#30123](https://github.com/prisma/orm/pull/30123))

**Dropped idle connections no longer crash the app.** The PostgreSQL driver attaches pool-level error handlers, including for clients held for a transaction, so a database restart or a pooler dropping an idle connection is survivable. ([prisma/orm#30081](https://github.com/prisma/orm/pull/30081))

**Prisma 7 and 8 coexist in one project.** `@prisma/prisma7` provides a `prisma7` binary, Prisma 7 prefers a `prisma7.config.ts` file when one exists, and the Prisma 8 language server only claims `.prisma` files that start with `// use prisma-next`, so both editor extensions can be installed. ([prisma/orm#29949](https://github.com/prisma/orm/pull/29949), [prisma/orm#30020](https://github.com/prisma/orm/pull/30020), [prisma/orm#30140](https://github.com/prisma/orm/pull/30140))

## Prisma Console and MCP server

The Console, docs, blog, and site carry the new Prisma brand. The docs sidebar is now grouped into Start, Build, Deploy, Manage, and Reference, and every CLI command lives under [/docs/cli](https://www.prisma.io/docs/cli).

Two sign-in fixes for the [Prisma MCP server](https://www.prisma.io/docs/ai/tools/mcp-server): connecting from the Claude apps no longer fails at registration, and clients that enforce RFC 8414, such as fx, can now authenticate.

## Fixes

**Prisma Compute**

- The generated deploy workflow installs pnpm for repositories that use it and runs Composer under Bun.
- The deploy card for an app from the catalog shows the first deploy failure instead of waiting indefinitely.

**Prisma Postgres**

- Backup sizes on the Console backups page show the correct unit. A 23 GiB backup rendered as `23.14 KiB`.

**Prisma 8**

- Self-relation predicates nested two or more levels deep, such as `following.some(f => f.following.some(...))`, no longer let the inner scope shadow the outer one. ([prisma/orm#29900](https://github.com/prisma/orm/pull/29900))
- `count()`, `sum()`, and other scalar includes on many-to-many relations go through the junction table instead of referencing a foreign key that does not exist. ([prisma/orm#29888](https://github.com/prisma/orm/pull/29888))
- Repeating an `upsert` keyed on a `Bytes` column no longer fails with `ORM.MUTATION_ROW_MISSING`. ([prisma/orm#29910](https://github.com/prisma/orm/pull/29910))
- A hand-written migration column with an `autoincrement()` default and a non-`SERIAL` type fails at authoring time with `CONTRACT.DEFAULT_INVALID` instead of emitting a column with no sequence. ([prisma/orm#30040](https://github.com/prisma/orm/pull/30040))
- `upsert({ create })`, `createAll()`, and `createAndCount()` reject nested relation callbacks at compile time, since those paths never executed them. ([prisma/orm#30144](https://github.com/prisma/orm/pull/30144))
- MongoDB `create()`, `update()`, `delete()`, and `upsert()` decode their results through the column codecs, so a created `_id` matches the value read back. ([prisma/orm#29879](https://github.com/prisma/orm/pull/29879))
- Migration errors name the configured migrations directory instead of a hardcoded `migrations/`. ([prisma/orm#30041](https://github.com/prisma/orm/pull/30041))
- `migration graph --dot` prints on a terminal again. ([prisma/orm#30057](https://github.com/prisma/orm/pull/30057))
- The language server recognizes Windows paths in `prisma.config.ts`. ([prisma/orm#30121](https://github.com/prisma/orm/pull/30121))
- Structured errors link to `/docs/orm/v8/reference/error-reference`. ([prisma/orm#30126](https://github.com/prisma/orm/pull/30126))

**Prisma ORM 7**

- Prisma Migrate refuses a `shadowDatabaseUrl` that points at the main database, with the new error `P3025`. Until now `migrate diff --from-migrations` with that configuration reset the real schema and reported an empty diff. ([prisma/prisma-engines#5851](https://github.com/prisma/prisma-engines/pull/5851))

**Prisma Studio**

- Studio's local server binds to `127.0.0.1` only and rejects browser requests from other origins, so a website open in the same browser can no longer reach the connected database. ([prisma/orm#29890](https://github.com/prisma/orm/pull/29890))
