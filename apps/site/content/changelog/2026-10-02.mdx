**Your coding agent can now set up Prisma for you with a credential of its own, and it asks before it touches production.** Prisma ORM 8 runs on **the Prisma 7 schema you already have** and adds Postgres full-text search. The Prisma MCP server can now **promote, roll back, and debug Prisma Compute apps**.

**Two dates need action.** Prisma Postgres Early Access databases are deleted on **November 1, 2026**, and Accelerate is retired on **December 1, 2026**. The steps for both are under "What you need to do".

## Coding agents get their own credential and ask before production changes

Until now, an agent working in Prisma borrowed your CLI session. To Prisma it *was* you: it had all of your access, and the audit log recorded its actions as yours.

**An enrolled agent has its own credential instead.** It can create projects and databases, connect a GitHub repository, and configure deploys through the [REST API](https://www.prisma.io/docs/rest-api). You can pause or revoke it at any time without signing yourself out.

You also decide how far it goes on its own. By default, an agent works freely on [preview branches](https://www.prisma.io/docs/compute/branching). It *asks you first* before it writes to production, deletes anything, or creates a connection string. Every request it makes lands in the audit log under its own name.

![The Agents page in Prisma Console, listing four enrolled agents with their sponsors, permission policies, and statuses, plus two pending approval requests waiting for review.](/changelog/2026-10-02-console-agents.png)

Enrollment takes one pairing code. Open **Settings → Agents** in the [Console](https://console.prisma.io), paste the instructions into your agent's chat, and approve the code it shows you. The [enrollment guide](https://www.prisma.io/docs/prisma-compute/agent-enrollment) explains the policy rules and how an enrolled agent deploys.

## Try Prisma ORM 8 on the schema you already have

**Prisma ORM 8 now reads a Prisma 7 `schema.prisma` directly**, so you can try it without rewriting your schema. The two versions run side by side on the same database, and Prisma ORM 7 keeps running your migrations. ([#30287](https://github.com/prisma/orm/pull/30287), [#30291](https://github.com/prisma/orm/pull/30291))

```bash title="Terminal"
npx prisma@latest orm init --from-prisma7-schema prisma/schema.prisma
```

The command checks that Prisma ORM 8 can read your schema *before it changes anything*. It leaves your `prisma/` directory and your database untouched.

MongoDB projects on Prisma ORM 6 can do the same by setting `contract: prisma6Schema("prisma/schema.prisma")` in their config. ([#30405](https://github.com/prisma/orm/pull/30405))

Once you are ready to move over completely, [`prisma contract print`](https://www.prisma.io/docs/cli/contract-print) converts the old schema to the Prisma ORM 8 schema language. ([#30315](https://github.com/prisma/orm/pull/30315))

## Promote, roll back, and debug Prisma Compute apps from your AI tool

**The [Prisma MCP server](https://www.prisma.io/docs/ai/tools/mcp-server) now covers Prisma Compute**, so the AI tool you already use can operate your apps:

- **Change what is live.** Promote a deployment, roll an app back, or start, stop, and delete deployments.
- **Find out what went wrong.** List apps, builds, and deployments, and read a deployment's runtime logs.
- **Set environment variables** for production, for preview, or for one preview branch. Values are encrypted and *never returned*.
- **See how a Composer project fits together**, with links to each service in the Console.

These tools operate apps that already exist. They do not build or upload your code. The [MCP tools reference](https://www.prisma.io/docs/ai/mcp-tools) lists every tool.

## What you need to do

- **Prisma Postgres Early Access databases:** [move each one to a new database](https://www.prisma.io/docs/postgres/migrate-from-ea-to-ga) before **November 1, 2026 at 00:00 UTC**. Early Access databases are *deleted* on that date. The Console shows a notice on every affected project and database.
- **Prisma Postgres through a `prisma+postgres://accelerate.prisma-data.net` URL:** [switch to pooled TCP or the serverless driver](https://www.prisma.io/docs/postgres/database/switch-from-accelerate) before **December 1, 2026**. Your database, your data, and your plan stay the same. Query caching is *not replaced*, so remove `cacheStrategy` from your queries first.
- **Accelerate with your own database:** remove it before **December 1, 2026**. You can [keep your database and connect without Accelerate](https://www.prisma.io/docs/accelerate/keep-your-database), or [move a PostgreSQL database to Prisma Postgres](https://www.prisma.io/docs/prisma-postgres/import-from-existing-database-postgresql).
- **Prisma ORM 8 release candidates:** follow the upgrade recipe linked from each [release](https://github.com/prisma/orm/releases) before you plan your next migration. The breaking changes below are the ones most apps hit.
- **Prisma ORM 7:** there is *nothing to change*. Prisma ORM 7 gets bug fixes and security updates for 18 months after Prisma ORM 8 becomes generally available. See [release status](https://www.prisma.io/docs/orm/release-status).

## Breaking changes

These apply to Prisma ORM 8 release candidates `8.0.0-rc.9` through `8.0.0-rc.14`.

- **A model without `@@map` now names its table exactly as written.** `model UserProfile` used to map to `"userProfile"`. It now maps to `"UserProfile"`. Run the `add-model-map` script from the upgrade recipe before you plan a migration, so that no table is renamed. ([#30317](https://github.com/prisma/orm/pull/30317))
- **Every schema file needs `// use prisma-8` as its first line.** A file without the header is left out of the contract *without a warning*. ([#30379](https://github.com/prisma/orm/pull/30379))
- **`dbgenerated(...)` is removed.** Write a raw SQL default as a tagged literal instead, as in ``@default(sql`gen_random_uuid()`)``. ([#30380](https://github.com/prisma/orm/pull/30380))
- **A default must be a value its column accepts.** A quoted string no longer works as a JSON, decimal, or float default, so `@default("{}")` becomes ``@default(json`{}`)``. ([#30350](https://github.com/prisma/orm/pull/30350))
- **`prisma.config.ts` must import `definePrismaConfig`.** The `defineConfig` alias is gone. ([#30129](https://github.com/prisma/orm/pull/30129))
- **CLI environment variables lose the `NEXT_` infix.** `PRISMA_NEXT_DEBUG` is now `PRISMA_DEBUG`, and the others follow the same pattern. ([#30262](https://github.com/prisma/orm/pull/30262))
- **A relation field's `?` must agree with its foreign key.** `author User` over a nullable `authorId Int?` now fails `contract emit`. ([#30231](https://github.com/prisma/orm/pull/30231))
- **Serverless `connect()` returns a connection, not a runtime.** Replace `runtime.query(plan)` with `db.runtime().query(plan)`. ([#30482](https://github.com/prisma/orm/pull/30482))
- **MongoDB schemas reject attributes that never had an effect.** Remove `@default`, `@updatedAt`, and `@db.*` from MongoDB schemas. ([#30160](https://github.com/prisma/orm/pull/30160))
- **Projects that install with Yarn must add `temporal-polyfill`.** npm, pnpm, and Bun install it for you. ([#30520](https://github.com/prisma/orm/pull/30520))

## Deprecations

- **Prisma Postgres Early Access databases** are deleted on November 1, 2026 at 00:00 UTC. These are the databases that still run PostgreSQL 16. *Action required:* follow the [migration guide](https://www.prisma.io/docs/postgres/migrate-from-ea-to-ga).
- **Accelerate** is retired on December 1, 2026, including hosted Accelerate connections to Prisma Postgres. The Console no longer offers new Accelerate setups, and existing setups have a **Transition** tab with the guide that matches the database. *Action required:* follow one of the [retirement paths](https://www.prisma.io/docs/accelerate).
- **Prisma ORM 8 on MongoDB:** the scalar names `Int`, `Float`, `Boolean`, and `DateTime` are deprecated in favor of `Int32`, `Double`, `Bool`, and `Date`. The old names still work and report a warning. ([#30396](https://github.com/prisma/orm/pull/30396))
- **Prisma ORM 8:** the `// use prisma-next` schema header is deprecated in favor of `// use prisma-8`. Formatting the file rewrites it for you. ([#30262](https://github.com/prisma/orm/pull/30262))

## Prisma Compute

**You can now change an environment variable in the Console and roll it out without a new build.**

- **Reveal and edit a value in place** on the project's Environment page. Edits are staged, and one **Save changes** saves them all, with separate counts for production and preview.
- **Deploy the change to your live apps** right after saving. The Console redeploys each app's live build with the new variables. There is *no new build and no code upload*.
- **Deploy latest commit** starts a deploy from the app page of any app connected to GitHub. A deploy workflow created before this release needs a `workflow_dispatch` trigger for the button to work.

Connecting a repository takes fewer steps:

- A repository that already has a [Composer](https://www.prisma.io/docs/composer) config starts its first deploy as soon as you connect it.
- Plain Bun servers that call `Bun.serve` now deploy from GitHub.
- When setup fails, **Retry** starts again on the same repository. It used to send you back to the repository picker.
- You can connect a personal GitHub account that already has the Prisma GitHub App installed.

Three smaller changes:

- You can delete a project that still has active deployments. Deleting the project removes them.
- Uploads to [Object Storage](https://www.prisma.io/docs/compute/object-storage) in the Console accept files up to 1 GB, and you can delete a whole folder.
- The docs now state the [request timeout](https://www.prisma.io/docs/compute/request-timeout). Your service has 60 seconds to *start* responding, and a response that has started, such as a stream, is not cut off.

## Prisma ORM

**Prisma ORM 8 adds full-text search on Postgres.** Text columns gain `fullTextMatches`, `fullTextRank`, and `fullTextHeadline`, and `@@fullTextIndex` creates the index those queries use. A search query is built with a helper, and a bare string is a type error, so user input cannot add search operators. See the [reference](https://www.prisma.io/docs/orm/reference/orm-client#full-text-search). ([#30348](https://github.com/prisma/orm/pull/30348), [#30386](https://github.com/prisma/orm/pull/30386))

```ts title="src/search.ts"
import { websearchToTsquery } from "@prisma/orm-postgres/target/full-text";

const q = websearchToTsquery(input);

const posts = await db.orm.public.Post.select("id", "title")
  .where((p) => p.title.fullTextMatches(q))
  .orderBy((p) => p.title.fullTextRank(q).desc())
  .all();
```

Also new in the release candidates:

- **Skip duplicates on bulk inserts** with `createAll(rows, { onConflict: "skip" })`, on Postgres and SQLite. This replaces `skipDuplicates` from Prisma ORM 7. ([docs](https://www.prisma.io/docs/orm/fundamentals/writing-data#write-many-records), [#30365](https://github.com/prisma/orm/pull/30365))
- **Order by related data.** Sort by a related record's column or by the number of related records, and choose where nulls go. ([docs](https://www.prisma.io/docs/orm/reference/orm-client#orderby), [#30402](https://github.com/prisma/orm/pull/30402))
- **Split your schema across files** by pointing `contract` at a pattern such as `./prisma/**/*.prisma`. Your editor reads the files as one project. ([#30379](https://github.com/prisma/orm/pull/30379), [#30456](https://github.com/prisma/orm/pull/30456))
- **Name your model and result types.** The generated contract exports a `Models` namespace, and `Shape` derives a response type from the fields and relations you choose. These replace `Prisma.User` and `UserGetPayload`. ([#30231](https://github.com/prisma/orm/pull/30231))
- **Prepare a query once and run it many times** with `.prepared.all()`, `.prepared.first()`, or `.prepared.aggregate()`. ([docs](https://www.prisma.io/docs/orm/reference/transactions-and-runtime#prepared-statements-postgresql), [#30260](https://github.com/prisma/orm/pull/30260), [#30309](https://github.com/prisma/orm/pull/30309))
- **Write the same code for serverless.** A serverless connection has `db.orm`, `db.transaction`, and `db.prepare`, like a `postgres()` client. ([#30482](https://github.com/prisma/orm/pull/30482))
- **Use JavaScript `Date` values on Postgres** with `TimestamptzJsDate`. No Temporal polyfill is needed. ([#30288](https://github.com/prisma/orm/pull/30288))
- **Store more MongoDB types.** Schemas can declare `Int64`, `Decimal128`, `Binary`, `Json`, and `Bson` fields, and timestamps that fill themselves on create and update. ([#30396](https://github.com/prisma/orm/pull/30396), [#30403](https://github.com/prisma/orm/pull/30403))
- **Get completions in your editor.** It completes attributes and their arguments, and shows signature help as you type. ([#30249](https://github.com/prisma/orm/pull/30249), [#30312](https://github.com/prisma/orm/pull/30312))

**Prisma ORM 8 extensions now have a directory.** The [extension directory](/extensions) lists extensions and middleware from Prisma and from the community, each with its install command. To add yours, submit it from the page, which opens a pull request.

## Prisma Postgres

**You can connect to Prisma Postgres from edge runtimes without Accelerate.** The [Prisma Postgres serverless driver](https://www.prisma.io/docs/postgres/database/serverless-driver) connects over HTTP and WebSockets where a TCP driver cannot run. It is one of the two replacements for a hosted Accelerate connection, and the [switch guide](https://www.prisma.io/docs/postgres/database/switch-from-accelerate) covers both.

Creating a database in the Console is now a single path. Every new database is a Prisma Postgres database, with connection pooling and backups included.

## REST API

- **Tell your resources apart with `logicalId`.** Services, databases, and buckets accept and return an optional `logicalId`. Passing `null` clears it.
- **Update a bucket in place** with [`PATCH /v1/buckets/{bucketId}`](https://www.prisma.io/docs/rest-api/endpoints/buckets/patch-buckets-by-bucket-id), which changes its display name, its `logicalId`, or its branch.
- **Detect a quota failure from code.** A `409` caused by a plan limit now returns `error.code: "quota-exceeded"`, which tells it apart from a resource conflict.
- **`region: "inherit"` follows the project.** A new database takes the project's default region, even when the project has no default database yet.
- **Find the OpenAPI spec where tools look for it**, at [`/openapi.json`](https://www.prisma.io/openapi.json).

## Prisma Console

- **Downgrades between paid plans take effect at the end of the billing period.** You keep your current plan until then.
- **Accelerate charges have their own section on the invoice**, so included Prisma Postgres usage no longer reads as an overage.
- The workspace overview projects Prisma Compute requests to the end of the billing cycle, next to the Prisma Postgres projection.
- New accounts choose between a template, a GitHub repository, and an empty project on the first screen.

## Docs and website

- **One search covers the website, the docs, and the blog.** Filter the results by source from the same dialog everywhere.
- **Agents can read the website as Markdown.** The main product pages answer `Accept: text/markdown`, and the docs Markdown routes open in ChatGPT.
- **Three new pages help you move to Prisma ORM 8:** [Coming from Prisma ORM 7](https://www.prisma.io/docs/orm/coming-from-prisma-orm-7), [release status](https://www.prisma.io/docs/orm/release-status), and a [from-scratch setup](https://www.prisma.io/docs/prisma-orm/from-scratch) that uses no template.

## Fixes

**Prisma Compute**

- **A project connected from GitHub deploys in the region you chose.** The choice was dropped before, and the project deployed in US East.
- The project overview shows builds that ran in GitHub Actions.
- The new-project form preselects a region near you again.

**Prisma Postgres**

- Restoring a database from a backup you pick no longer fails with `No backups found`.
- The [pricing calculator](/pricing) uses the 200,000 operations of the Free plan.

**Prisma ORM 8**

- **`include()` across a composite foreign key returns the right rows.** It matched on the first key column only, which returned related rows that belonged to other parents. ([#30107](https://github.com/prisma/orm/pull/30107))
- **After `db sign`, `migration plan` proposes only your change.** It used to propose recreating every table. ([#30251](https://github.com/prisma/orm/pull/30251))
- **A paused result no longer holds a pooled connection.** Buffered Postgres queries release the connection before rows are read, so a small pool is not blocked. ([#30259](https://github.com/prisma/orm/pull/30259))
- **An edited migration snapshot is detected.** Before, it could make `migration plan` report no changes. ([#30086](https://github.com/prisma/orm/pull/30086))
- `db init`, `db update`, and `migrate` no longer leave the database half-updated when `contract.d.ts` is missing. ([#30293](https://github.com/prisma/orm/pull/30293), [#30298](https://github.com/prisma/orm/pull/30298))
- A migration that removes a column along with a row-level security policy that references it now applies, because the policy is dropped first. ([#30232](https://github.com/prisma/orm/pull/30232))
- The CLI works with date and time defaults on Node 24. ([#30520](https://github.com/prisma/orm/pull/30520))
- `createAndCount` returns the number of rows the database inserted, not the length of the input. ([#30365](https://github.com/prisma/orm/pull/30365))
- `limit()` and `offset()` refuse a value that is not a non-negative integer. ([#30133](https://github.com/prisma/orm/pull/30133))
- Ordering by a native Postgres enum column no longer fails. ([#30191](https://github.com/prisma/orm/pull/30191))
- On MongoDB, a query that combines `select()` with `include()` returns the included relations. ([#30170](https://github.com/prisma/orm/pull/30170))
- On MongoDB, connection strings that list several hosts are accepted, and the CLI masks their credentials. ([#30354](https://github.com/prisma/orm/pull/30354))
- Valid schemas no longer get false errors in the editor. ([#30228](https://github.com/prisma/orm/pull/30228))
