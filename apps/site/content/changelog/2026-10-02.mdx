**You can now enroll a coding agent in Prisma with a credential of its own, and decide which of its actions need your approval.** The Prisma MCP server also **manages Prisma Compute deployments**, and **Prisma ORM 8 reads the Prisma 7 schema you already have** and adds Postgres full-text search. Two retirements need action: Prisma Postgres Early Access databases are deleted on **November 1, 2026**, and Accelerate is retired on **December 1, 2026**.

## Your coding agent gets its own Prisma credential

An enrolled agent can create projects and databases, connect a GitHub repository, and configure deploys through the [REST API](https://www.prisma.io/docs/rest-api), **without borrowing your session**. You can pause or revoke the agent at any time, and your own access is not affected.

Every agent starts with a default policy. It works freely on [preview branches](https://www.prisma.io/docs/compute/branching), and it *asks you first* before it writes to production, deletes anything, or creates a connection string. Every request the agent makes is recorded in the audit log under the agent's name, not yours.

![The Agents page in Prisma Console, listing four enrolled agents with their sponsors, permission policies, and statuses, plus two pending approval requests waiting for review.](/changelog/2026-10-02-console-agents.png)

Enrollment takes one pairing code. In the [Console](https://console.prisma.io), open **Settings → Agents**, copy the instructions into your agent's chat, and approve the code it shows you. The [enrollment guide](https://www.prisma.io/docs/prisma-compute/agent-enrollment) covers the policy rules and how to deploy with an enrolled agent.

## Manage Prisma Compute deployments from your MCP client

The [Prisma MCP server](https://www.prisma.io/docs/ai/tools/mcp-server) now **works with Prisma Compute**, so the AI tool you already use can inspect and operate your apps:

- **See what is running** by listing apps, builds, and deployments, and by reading a deployment's runtime logs.
- **Change what is live** by promoting a deployment, rolling an app back, or starting, stopping, and deleting deployments.
- **Set environment variables** for production, preview, or one preview branch. Values are encrypted and *never returned*.
- **Read a Composer project's topology**, with links to each service in the Console.

These tools manage apps that already exist. They do not build or upload your code. The [MCP tools reference](https://www.prisma.io/docs/ai/mcp-tools) lists every tool.

## Prisma ORM 8 reads the Prisma 7 schema you already have

**You can try Prisma ORM 8 without rewriting your schema.** Point it at your existing `schema.prisma`, and it runs beside Prisma ORM 7 on the same database while Prisma ORM 7 keeps running your migrations. ([#30287](https://github.com/prisma/orm/pull/30287), [#30291](https://github.com/prisma/orm/pull/30291))

```bash title="Terminal"
npx prisma@latest orm init --from-prisma7-schema prisma/schema.prisma
```

The command checks that Prisma ORM 8 can read the schema *before it changes anything*, and it does not touch your `prisma/` directory or your database. A MongoDB project on Prisma ORM 6 can do the same by setting `contract: prisma6Schema("prisma/schema.prisma")` in its config. ([#30405](https://github.com/prisma/orm/pull/30405))

When you are ready to leave the old schema behind, [`prisma contract print`](https://www.prisma.io/docs/cli/contract-print) writes it out in the Prisma ORM 8 schema language. ([#30315](https://github.com/prisma/orm/pull/30315))

## What you need to do

- **Using Accelerate with your own database:** remove it before **December 1, 2026**. Either [keep your database and connect without Accelerate](https://www.prisma.io/docs/accelerate/keep-your-database), or [move a PostgreSQL database to Prisma Postgres](https://www.prisma.io/docs/prisma-postgres/import-from-existing-database-postgresql).
- **Connecting to Prisma Postgres through a `prisma+postgres://accelerate.prisma-data.net` URL:** [switch to pooled TCP or the serverless driver](https://www.prisma.io/docs/postgres/database/switch-from-accelerate) before **December 1, 2026**. Your database, data, and plan stay the same. Query caching is *not replaced*, so remove `cacheStrategy` from your queries first.
- **Running a Prisma Postgres Early Access database:** [move it to a new database](https://www.prisma.io/docs/postgres/migrate-from-ea-to-ga) before **November 1, 2026 at 00:00 UTC**, when Early Access databases are deleted. The Console shows a notice on every affected project and database.
- **On a Prisma ORM 8 release candidate:** follow the upgrade recipe linked from each [release](https://github.com/prisma/orm/releases) before you plan your next migration. The breaking changes below are the ones most apps hit.
- **On Prisma ORM 7:** there is *nothing to change*. Prisma ORM 7 gets bug fixes and security updates for 18 months after Prisma ORM 8 reaches general availability. See [release status](https://www.prisma.io/docs/orm/release-status).

## Breaking changes

These apply to Prisma ORM 8 release candidates `8.0.0-rc.9` through `8.0.0-rc.14`.

- **A model without `@@map` now names its table exactly as written.** `model UserProfile` used to map to `"userProfile"` and now maps to `"UserProfile"`. Run the `add-model-map` script from the upgrade recipe before you plan a migration, so no table is renamed. ([#30317](https://github.com/prisma/orm/pull/30317))
- **Every schema file needs `// use prisma-8` as its first line.** A file without the header is left out of the contract *without a warning*. ([#30379](https://github.com/prisma/orm/pull/30379))
- **`dbgenerated(...)` is removed.** Write a raw SQL default as a tagged literal, as in ``@default(sql`gen_random_uuid()`)``. ([#30380](https://github.com/prisma/orm/pull/30380))
- **A default must be a value its column accepts.** A quoted string no longer works as a JSON, decimal, or float default, so `@default("{}")` becomes ``@default(json`{}`)``. ([#30350](https://github.com/prisma/orm/pull/30350))
- **`prisma.config.ts` must import `definePrismaConfig`.** The `defineConfig` alias is gone. ([#30129](https://github.com/prisma/orm/pull/30129))
- **CLI environment variables lose the `NEXT_` infix.** `PRISMA_NEXT_DEBUG` is now `PRISMA_DEBUG`, and the same rename applies to the rest. ([#30262](https://github.com/prisma/orm/pull/30262))
- **A relation field's `?` must agree with its foreign key.** `author User` over a nullable `authorId Int?` now fails `contract emit`. ([#30231](https://github.com/prisma/orm/pull/30231))
- **Serverless `connect()` returns a connection, not a runtime.** Replace `runtime.query(plan)` with `db.runtime().query(plan)`. ([#30482](https://github.com/prisma/orm/pull/30482))
- **MongoDB schemas reject attributes that never did anything.** Remove `@default`, `@updatedAt`, and `@db.*` from MongoDB schemas. ([#30160](https://github.com/prisma/orm/pull/30160))
- **Projects that install with Yarn must add `temporal-polyfill`.** npm, pnpm, and Bun install it for you. ([#30520](https://github.com/prisma/orm/pull/30520))

## Deprecations

- **Accelerate:** retired on December 1, 2026, including hosted Accelerate connections to Prisma Postgres. New Accelerate setups are no longer available in the Console. Existing setups get a **Transition** tab with the guide that matches the database. *Action required:* follow the [retirement paths](https://www.prisma.io/docs/accelerate) before that date.
- **Prisma Postgres Early Access databases:** deleted on November 1, 2026 at 00:00 UTC. These are the databases that still run PostgreSQL 16. *Action required:* follow the [migration guide](https://www.prisma.io/docs/postgres/migrate-from-ea-to-ga).
- **Prisma ORM 8 on MongoDB:** the scalar names `Int`, `Float`, `Boolean`, and `DateTime` are deprecated in favor of `Int32`, `Double`, `Bool`, and `Date`. The old names still work and report a warning. ([#30396](https://github.com/prisma/orm/pull/30396))
- **Prisma ORM 8:** the `// use prisma-next` schema header is deprecated in favor of `// use prisma-8`. Formatting the file rewrites it for you. ([#30262](https://github.com/prisma/orm/pull/30262))

## Prisma Compute

**You can now read and change environment variables in the Console, then roll them out without a new build.**

- **Reveal and edit a value in place** on the project's Environment page. Edits are staged, and one **Save changes** saves them together, with separate counts for production and preview.
- **Deploy changes to your live apps** after saving. The Console redeploys each app's live build with the new variables, with *no new build and no code upload*.
- **Deploy latest commit** starts a deploy from the app page for apps connected to GitHub. A deploy workflow created before this release needs a `workflow_dispatch` trigger for the button to work.

Connecting a repository got shorter as well:

- A repository that already has a [Composer](https://www.prisma.io/docs/composer) config starts its first deploy as soon as you connect it.
- Plain Bun servers that call `Bun.serve` are now supported when you deploy from GitHub.
- If setup fails, **Retry** starts again on the same repository instead of sending you back to the repository picker.
- You can connect a personal GitHub account that already has the Prisma GitHub App installed.

Three smaller changes:

- You can delete a project that still has active deployments. Deleting the project removes them.
- Uploads to [Object Storage](https://www.prisma.io/docs/compute/object-storage) in the Console accept files up to 1 GB, and you can delete a whole folder.
- The docs now state the [request timeout](https://www.prisma.io/docs/compute/request-timeout): your service has 60 seconds to *start* responding. A response that has started, such as a stream, is not cut off.

## Prisma ORM

**Prisma ORM 8 adds full-text search on Postgres.** Text columns gain `fullTextMatches`, `fullTextRank`, and `fullTextHeadline`, and `@@fullTextIndex` creates the index those queries use. User input cannot add search operators, because a query is built with a helper and a bare string is a type error. See the [reference](https://www.prisma.io/docs/orm/reference/orm-client#full-text-search). ([#30348](https://github.com/prisma/orm/pull/30348), [#30386](https://github.com/prisma/orm/pull/30386))

```ts title="src/search.ts"
import { websearchToTsquery } from "@prisma/orm-postgres/target/full-text";

const q = websearchToTsquery(input);

const posts = await db.orm.public.Post.select("id", "title")
  .where((p) => p.title.fullTextMatches(q))
  .orderBy((p) => p.title.fullTextRank(q).desc())
  .all();
```

More in the release candidates:

- **Skip duplicates on bulk inserts** with `createAll(rows, { onConflict: "skip" })`, on Postgres and SQLite. This replaces `skipDuplicates` from Prisma ORM 7. ([docs](https://www.prisma.io/docs/orm/fundamentals/writing-data#write-many-records), [#30365](https://github.com/prisma/orm/pull/30365))
- **Order by related data**: a related record's column, the number of related records, and where nulls go. ([docs](https://www.prisma.io/docs/orm/reference/orm-client#orderby), [#30402](https://github.com/prisma/orm/pull/30402))
- **Split your schema across files** by pointing `contract` at a pattern such as `./prisma/**/*.prisma`. The editor reads the files as one project. ([#30379](https://github.com/prisma/orm/pull/30379), [#30456](https://github.com/prisma/orm/pull/30456))
- **Name your model and result types.** The generated contract exports a `Models` namespace, and `Shape` derives a response type with chosen fields and relations. These replace `Prisma.User` and `UserGetPayload`. ([#30231](https://github.com/prisma/orm/pull/30231))
- **Prepare an ORM query once and run it many times** with `.prepared.all()`, `.prepared.first()`, or `.prepared.aggregate()`. ([docs](https://www.prisma.io/docs/orm/reference/transactions-and-runtime#prepared-statements-postgresql), [#30260](https://github.com/prisma/orm/pull/30260), [#30309](https://github.com/prisma/orm/pull/30309))
- **Use `db.orm`, `db.transaction`, and `db.prepare` on a serverless connection**, the same as on a `postgres()` client. ([#30482](https://github.com/prisma/orm/pull/30482))
- **Read and write JavaScript `Date` values on Postgres** with `TimestamptzJsDate`, with no Temporal polyfill. ([#30288](https://github.com/prisma/orm/pull/30288))
- **MongoDB schemas** can declare `Int64`, `Decimal128`, `Binary`, `Json`, and `Bson` fields, and timestamps that fill themselves on create and update. ([#30396](https://github.com/prisma/orm/pull/30396), [#30403](https://github.com/prisma/orm/pull/30403))
- **Your editor completes attributes** and their arguments, and shows signature help as you type. ([#30249](https://github.com/prisma/orm/pull/30249), [#30312](https://github.com/prisma/orm/pull/30312))

The [extension directory](/extensions) lists every Prisma ORM 8 extension and middleware package, from Prisma and from the community, each with its install command. To add yours, submit it from the page, which opens a pull request.

## Prisma Postgres

**You can connect to Prisma Postgres from edge runtimes without Accelerate.** The [Prisma Postgres serverless driver](https://www.prisma.io/docs/postgres/database/serverless-driver) connects over HTTP and WebSockets where a TCP driver cannot run. The [switch guide](https://www.prisma.io/docs/postgres/database/switch-from-accelerate) covers it and pooled TCP, the two replacements for a hosted Accelerate connection.

Creating a database in the Console is now a single path: Prisma Postgres, with connection pooling and backups included.

## REST API

- **Tell your resources apart with `logicalId`.** Services, databases, and buckets accept and return an optional `logicalId`, and passing `null` clears it.
- **Update a bucket in place** with [`PATCH /v1/buckets/{bucketId}`](https://www.prisma.io/docs/rest-api/endpoints/buckets/patch-buckets-by-bucket-id), which changes its display name, `logicalId`, or branch.
- **Detect a quota failure from code.** A `409` caused by a plan limit now returns `error.code: "quota-exceeded"`, so you can tell it apart from a resource conflict.
- **`region: "inherit"` follows the project.** A new database takes the project's default region, even when the project has no default database yet.
- The OpenAPI spec is served at [`/openapi.json`](https://www.prisma.io/openapi.json), where API tools and agents look for it.

## Prisma Console

- **Downgrades between paid plans take effect at the end of the billing period.** You keep your current plan until then.
- **Accelerate charges have their own section on the invoice**, so included Prisma Postgres usage no longer reads as an overage.
- The workspace overview projects Prisma Compute requests to the end of the billing cycle, next to the Prisma Postgres projection.
- New accounts choose between a template, a GitHub repository, and an empty project on the first screen.

## Docs and website

- **One search covers the website, the docs, and the blog.** Filter results by source, from the same dialog everywhere.
- **Agents can read the website as Markdown.** The main product pages answer `Accept: text/markdown`, and the docs Markdown routes open in ChatGPT.
- Three pages for people moving to Prisma ORM 8: [Coming from Prisma ORM 7](https://www.prisma.io/docs/orm/coming-from-prisma-orm-7), [release status](https://www.prisma.io/docs/orm/release-status), and a [from-scratch setup](https://www.prisma.io/docs/prisma-orm/from-scratch) with no template.
- Right-click the Prisma logo in any header to copy the logo or download the brand assets.

## Fixes

**Prisma Compute**

- **A project connected from GitHub deploys in the region you chose.** The choice was dropped before, and the project deployed in US East.
- The project overview shows builds that ran in GitHub Actions.
- The new-project form preselects a region near you again.

**Prisma Postgres**

- Restoring a database from a backup you pick no longer fails with `No backups found`.
- The [pricing calculator](/pricing) uses the 200,000 operations of the Free plan.

**Prisma ORM 8**

- **`include()` across a composite foreign key returns the right rows.** It matched on the first key column only, which returned related rows that belonged to other parents. ([#30107](https://github.com/prisma/orm/pull/30107))
- **After `db sign`, `migration plan` proposes only your change** instead of recreating every table. ([#30251](https://github.com/prisma/orm/pull/30251))
- **A paused result no longer holds a pooled connection.** Buffered Postgres queries release the connection before rows are read, so a small pool is not blocked. ([#30259](https://github.com/prisma/orm/pull/30259))
- `db init`, `db update`, and `migrate` no longer leave the database half-updated when `contract.d.ts` is missing. ([#30293](https://github.com/prisma/orm/pull/30293), [#30298](https://github.com/prisma/orm/pull/30298))
- The CLI works with date and time defaults on Node 24. ([#30520](https://github.com/prisma/orm/pull/30520))
- A migration that removes a column and a row-level security policy that references it now applies, because the policy is dropped first. ([#30232](https://github.com/prisma/orm/pull/30232))
- An edited migration snapshot is detected. Before, it could make `migration plan` report no changes. ([#30086](https://github.com/prisma/orm/pull/30086))
- `createAndCount` returns the number of rows the database inserted, not the length of the input. ([#30365](https://github.com/prisma/orm/pull/30365))
- `limit()` and `offset()` refuse a value that is not a non-negative integer. ([#30133](https://github.com/prisma/orm/pull/30133))
- Ordering by a native Postgres enum column no longer fails. ([#30191](https://github.com/prisma/orm/pull/30191))
- On MongoDB, a query that combines `select()` with `include()` returns the included relations. ([#30170](https://github.com/prisma/orm/pull/30170))
- On MongoDB, connection strings that list several hosts are accepted, and the CLI masks their credentials. ([#30354](https://github.com/prisma/orm/pull/30354))
- Valid schemas no longer get false errors in the editor. ([#30228](https://github.com/prisma/orm/pull/30228))
