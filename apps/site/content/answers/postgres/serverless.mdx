Pick serverless Postgres when your traffic is uneven, your code runs in serverless or edge functions, or you need many small databases, such as one per preview branch or agent task. Pick an always-on server you size yourself when the query load is heavy and constant, or when your workload depends on long-lived sessions.

## What makes Postgres serverless?

Serverless Postgres is a PostgreSQL database you reach through a connection string, while the provider runs the servers, scales them and handles connections for you. Three things separate it from a server you run or size yourself:

- **No instance to size.** You don't pick CPU and memory up front, and you don't resize when traffic grows.
- **Pooling in front of the database.** A function can start many copies of itself in a second, and each copy wants a database connection. A pooler lets those copies share a small set of real connections instead of running out of them.
- **Usage billing.** You pay for what you use instead of for a machine that runs all day.

To your app it is ordinary Postgres. Prisma ORM, `node-postgres`, `psql` and other Postgres clients all connect with the same connection string.

## How Prisma Postgres works for serverless and edge apps

[Prisma Postgres](/docs/postgres) is managed PostgreSQL 17 that autoscales, so there is no instance to size or upgrade. It bills by operations and storage, where an [operation](/docs/postgres/faq#what-is-an-operation) is one query, read or write. Every database has a pooled connection string, a direct one, and a serverless driver for runtimes without TCP:

### Connection pooling is built in

Application traffic goes to the pooled host, `pooled.db.prisma.io`. It routes through a tenant-isolated PgBouncer instance in transaction mode: a real database connection is assigned for one transaction, then returned to the pool. Many short-lived functions share those connections instead of opening one each.

Pooled connection limits depend on the plan: 10 on Free, 100 on Starter, 500 on Pro and 1,000 on Business. [How Postgres connection pooling works with serverless apps](/postgres/connection-pooling) covers the pooler in detail.

### Direct connections for migrations and tools

The direct host, `db.prisma.io`, skips the pooler. Use it for migrations, Prisma Studio, `pg_dump` and anything that needs session state, such as `LISTEN` and `NOTIFY`. The [Postgres connection string](/postgres/connection-string) guide breaks down both formats.

### A serverless driver for edge runtimes

Some runtimes can't open a PostgreSQL TCP connection. For those, the [serverless driver](/docs/postgres/database/serverless-driver), `@prisma/ppg`, talks to Prisma Postgres over HTTP and WebSockets. It takes your direct connection string as its credential but never opens a TCP connection:

```ts title="src/query.ts"
import { prismaPostgres, defaultClientConfig } from "@prisma/ppg";

const ppg = prismaPostgres(defaultClientConfig(process.env.DATABASE_URL!));

type User = { id: number; email: string };

const users = await ppg.sql<User>`
  SELECT id, email FROM "User" WHERE email = ${"ada@example.com"}
`.collect();
```

### Regions

You choose one of [six regions](/docs/postgres/faq#what-regions-is-prisma-postgres-available-in) when you create a database: San Francisco, North Virginia, Paris, Frankfurt, Tokyo or Singapore. The region can't be changed later. Every query travels from your function to that region and back, so run your functions in or near it.

## How do I set up serverless Postgres with Prisma?

Here is the whole path: Prisma ORM to model and query, Prisma Postgres to store, and Prisma Compute to deploy. The code uses [Prisma ORM 8](/docs/orm). Any other Postgres client works the same way with the connection string.

### 1. Define your schema

Your models live in a contract file. `npm create prisma@latest` writes one for a new app, and `npx prisma orm init` adds one to an app you already have.

```prisma title="src/prisma/contract.prisma"
// use prisma-8

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
}
```

### 2. Create a database

Run [`create-db`](/docs/postgres/npx-create-db) to get a Prisma Postgres database and its connection string in seconds, with no account. Put the connection string it prints in `.env` as `DATABASE_URL`, then create the tables:

```bash
npx create-db@latest
npx prisma contract emit
npx prisma db init
```

`contract emit` writes the `contract.json` and `contract.d.ts` files your app imports, and `db init` creates the tables in the empty database. The database is deleted after 24 hours unless you open the claim URL from the output and keep it in your workspace.

### 3. Query it from a serverless function

For functions on Node.js or Bun, Prisma ORM has a [serverless client](/docs/orm/reference/transactions-and-runtime#serverless-client-on-postgresql). It holds no connection of its own, so you create it once, outside the handler, and open one connection per request with `connect()`. `await using` closes it when the request ends:

```ts title="src/app/api/users/route.ts"
import postgresServerless from "@prisma/orm-postgres/serverless";
import { contractFromJson } from "@prisma/orm-postgres/static";
import type { Contract } from "../../../prisma/contract.d";
import contractJson from "../../../prisma/contract.json" with { type: "json" };

const postgres = postgresServerless({ contract: contractFromJson<Contract>(contractJson) });

export async function GET() {
  await using db = await postgres.connect({ url: process.env.DATABASE_URL! });
  const users = await db.orm.public.User.all();
  return Response.json(users);
}
```

In production, set `DATABASE_URL` to the pooled connection string from the Console, so every function instance goes through PgBouncer. On a runtime with no TCP support, query with the serverless driver shown above instead.

### 4. Deploy on Prisma Compute

[Prisma Compute](/compute) hosts Node.js, Bun and Next.js apps next to Prisma Postgres, in the same project. Add a [Composer declaration](/docs/prisma-compute/deploy) around your server code, then build and deploy:

```bash
npx prisma auth login
npm run build
npx prisma deploy
```

Store the connection string as a project [environment variable](/docs/compute/environment-variables), scoped to production or preview, with `npx prisma project env add DATABASE_URL=... --role production`. Values are write-only and resolve at the next deploy. You can also let the deploy create the database: a `rawPostgres()` dependency in the Composer module provisions a [Prisma Postgres database](/docs/composer/databases) with the app. Compute scales an idle app to zero and closes idle database connections, so keep your app's pool small and ready to reconnect.

## Can coding agents set up serverless Postgres?

Yes. Coding agents such as Claude Code, Cursor and Codex can create a Prisma Postgres database without a person signing up first. `npx create-db@latest --json` returns the connection string, the claim URL and the deletion time as JSON, and the [Prisma MCP server](/docs/ai/tools/mcp-server) lets an agent create databases, inspect the schema and run SQL with your Prisma sign-in.

```bash
npx create-db@latest --json --region eu-central-1
```

In [Scope's November 2026 benchmark](https://www.tryscope.com/leaderboard/databases) of AI agents signing up for a database and using it, Prisma Postgres ranked first of 18 providers, with an 88.3% success rate.

## When is serverless Postgres the wrong choice?

- **Sustained, heavy query volume.** Billing follows operations, so at a constant high query rate an always-on server can cost less. [Serverless Postgres compared](/blog/serverless-postgres) works through the crossover.
- **Long queries and session state on the pooler.** Pooled connections stop queries after 10 minutes and don't keep session state such as `SET` commands, advisory locks or `LISTEN` and `NOTIFY`. Use the direct connection for those.
- **Custom database roles.** Prisma Postgres doesn't support `CREATE ROLE`, so per-role access rules have to live in your app.
- **Moving between regions.** A database's region is fixed when you create it. Moving means a new database and a copy with `pg_dump` and `pg_restore`.
