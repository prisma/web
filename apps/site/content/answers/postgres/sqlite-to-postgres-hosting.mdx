Before your first customers arrive, you can test a database change without coordinating a live cutover. Use that opportunity to check what the app actually saves, including the identifiers used in links and the meaning of dates, prices and missing values.

We make Prisma Postgres and Prisma Compute. The linked provider and database documentation was checked on October 22, 2026.

## What should decide the host?

Choose the database around the deployed server, the data you need to preserve and the recovery procedure you can operate. A managed service takes care of running PostgreSQL; your team still owns the conversion from SQLite and the application's access rules.

[SQLite's type system](https://www.sqlite.org/datatype3.html) differs from PostgreSQL's. Inspect the actual values, rather than assuming a column declaration describes every stored row. Decide how to translate booleans, dates, JSON, numeric amounts and empty values. Review constraints and case-sensitive comparisons with the application's tests.

Keep the database close to the server that queries it. For a browser app, that is the API or server-rendering region, which can differ from the customer's location. Check [app and database regions](/postgres/nodejs-database-regions) together.

## Which managed Postgres options fit?

These providers expose PostgreSQL connection URLs and are listed alphabetically.

| Provider | Choose it when | Check for this move |
| --- | --- | --- |
| Neon | Your team wants its [database branching workflow](https://neon.com/docs/get-started/workflow-primer). | Rehearse the import in the intended branch and verify the connection role and endpoint. |
| Prisma Postgres | You want managed Postgres with [pooled and direct connections](/docs/postgres/database/connecting-to-your-database), optionally beside a TypeScript app on Compute. | Convert the schema, use the direct URL for migration work and select a suitable backup plan. |
| Supabase | You also want its integrated [Auth, Storage or Realtime services](https://supabase.com/docs/guides/getting-started/architecture). | Decide which surrounding services you actually need and test the database connection mode. |

Prisma Postgres lets you make the database change first. You can keep a working Vercel or Netlify deployment, then adopt Compute when you want the server and database described together through Composer.

## How do I rehearse the migration?

### 1. Prepare a separate target and a conversion plan

Create a development database in [Prisma Console](https://console.prisma.io). Copy its direct PostgreSQL URL from the connection details into your local secret mechanism. Keep credentials out of Git and browser code.

Create PostgreSQL migrations for the real schema using the project's chosen tool. Preserve existing record IDs and relationships. If imported IDs feed an identity sequence, advance the sequence past the imported values before new records can be created. A SQLite SQL dump is not automatically valid PostgreSQL SQL.

### 2. Try one explicit conversion

This fictional example demonstrates converting integer booleans through CSV. Run it in a new empty directory with the SQLite command-line tool installed:

~~~sh
sqlite3 source-demo.sqlite <<'SQL'
CREATE TABLE customers (
  id INTEGER PRIMARY KEY,
  email TEXT NOT NULL,
  active INTEGER NOT NULL CHECK (active IN (0, 1))
);
INSERT INTO customers VALUES
  (7, 'ada@example.test', 1),
  (12, 'sam@example.test', 0);
.headers on
.mode csv
.once customers.csv
SELECT id, email,
       CASE active WHEN 1 THEN 'true' ELSE 'false' END AS active
FROM customers ORDER BY id;
SQL
~~~

With the PostgreSQL client installed and the development database's direct URL available as `DIRECT_DATABASE_URL`, open a session from that directory:

~~~sh
psql "$DIRECT_DATABASE_URL"
~~~

Paste the following into that one session. The [psql `\copy` command](https://www.postgresql.org/docs/17/app-psql.html) reads the CSV from your computer:

~~~sql
CREATE TEMP TABLE sqlite_import_demo (
  id bigint PRIMARY KEY,
  email text NOT NULL,
  active boolean NOT NULL
);
\copy sqlite_import_demo (id, email, active) FROM 'customers.csv' WITH (FORMAT csv, HEADER true)

SELECT count(*) AS rows_imported,
       count(*) FILTER (WHERE active) AS active_rows
FROM sqlite_import_demo;
~~~

The result is `rows_imported = 2` and `active_rows = 1`. The temporary table disappears when the session ends. This checks one conversion; it does not migrate your application or prepare another database.

### 3. Test the application against PostgreSQL

Apply the real schema migrations to the development target and import a copy of the real records. Compare row counts, IDs, relationships, representative totals and dates. Test missing values and duplicate records, then run the app's sign-in, create, update and delete flows.

Switch the server's data-access configuration to PostgreSQL. Use the pooled URL for ordinary TCP application connections. The [Prisma Postgres serverless driver](/docs/postgres/database/serverless-driver) requires the direct URL; migrations and administrative tools also use the direct URL. Test SQL and ORM behavior rather than assuming SQLite-specific expressions work on PostgreSQL.

### 4. Launch from a verified database

For the final copy, stop writes to the source, import and verify the target, then point the app at PostgreSQL before reopening writes. Keep the source copy for reconciliation. This is a planned cutover, not a promise of zero downtime.

If you also move the app to Compute, follow [Port an existing app](/docs/composer/porting-an-app). A Composer-declared database is a separate resource; importing the Console development database does not populate a new deployment database. Prepare each target through its own migration and import workflow before it receives customer traffic.

## When should I choose another setup?

Keep SQLite when local operation or a durable file is central to the app. A managed PostgreSQL connection does not provide offline synchronization.

Check [Compute's runtime requirements](/docs/compute/limitations) before moving the server. Prisma Postgres has [plan-dependent snapshots](/docs/postgres/database/backups) and no point-in-time recovery yet (it is coming in November 2026). If restoring to a specific moment is a launch requirement, choose a database that provides it.
