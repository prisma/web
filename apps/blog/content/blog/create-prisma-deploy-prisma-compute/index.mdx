Starting a new Prisma app should not turn into a setup project.

`create-prisma` now goes beyond scaffolding. For Compute-ready templates, it can create the app, install Prisma Skills and other add-ons, set up Prisma Postgres, generate Compute deploy defaults, and deploy to Prisma Compute.

```bash
bun create prisma@latest
```

The generated project includes `prisma.compute.ts` and a `compute:deploy` script.

## From scaffold to deployed app

`create-prisma` already scaffolds framework starters with Prisma wired in: schema, client helper, seed file, database scripts, and an env file.

For Compute-ready templates, deploy setup adds `prisma.compute.ts`, provisions Prisma Postgres when selected, wires the connection string into the project, and ships the app to Prisma Compute.

## Add-ons for the rest of the workflow

During setup, you can choose add-ons for Prisma Skills, the Prisma MCP server, and the Prisma extension for supported editors.

Choose the Skills add-on when an agent will keep working in the repo after setup. It installs Prisma Agent Skills from [`prisma/skills`](https://github.com/prisma/skills), including the `prisma-compute` skill for deploys, logs, domains, and the Compute workflow.

That gives agents Prisma-specific context for changing and redeploying the app without moving those instructions into the prompt.

## Why deploy belongs in the starter

Deployment in `create-prisma` preserves scaffold decisions: framework, app name, port, env file, database connection, and generated scripts.

For a Hono app, the generated config looks like this:

```typescript
import { defineComputeConfig } from "@prisma/compute-sdk/config";

export default defineComputeConfig({
  app: {
    name: "my-api",
    framework: "hono",
    httpPort: 8080,
    env: ".env",
  },
});
```

The result is a project with aligned build, runtime, and redeploy defaults.

For a closer look at the TypeScript deploy config it generates, including how it scales to monorepos, see [Configure Prisma Compute deploys in TypeScript](/prisma-compute-config-file).

## Redeploying after setup

When you deploy through `create-prisma`, the generated project includes `prisma.compute.ts` and a `compute:deploy` script.

After making changes, redeploy from the project:

```bash
cd my-api
bun run compute:deploy
```

It redeploys your app code using the defaults in `prisma.compute.ts`. Database provisioning and migrations stay outside that redeploy script.

If you need to deploy an existing app that was not created with `create-prisma`, use the Prisma CLI directly:

```bash
bunx @prisma/cli@latest app deploy
```

## Start from one command

`create-prisma` is the new-project path for a Prisma-ready app and, for supported templates, its first Compute deploy.

Start interactively:

```bash
bun create prisma@latest
```

After that, changes redeploy through the generated config and scripts.
