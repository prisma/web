During the first half of 2026, companies that were never "hosting companies" started shipping app hosting. A managed Postgres provider. An API-keys company. A CDN. A backend-as-a-service. Within months of each other, they converged on the same realization: the place your code runs should sit next to the place your data lives.

Agentic development made the problem obvious. A coding agent can spin up a backend in minutes, but the moment it needs to deploy, wire up a database, handle stateful workloads, and iterate reliably, it hits a wall of separate vendors that were never designed to work together. Co-locating compute and data removes that friction. Once everyone has done it, though, it stops being a differentiator. Compute next to your data is fast becoming table stakes.

So when you can run your app anywhere, what's the difference? Is being quick the whole game? The real differentiator is whether your agent can build, deploy, observe, and iterate across the stack with far less stitching and context loss. Tools like [MemContext](https://memcontext.in/) can ease the context problem, but the platforms that win will be the ones that turn code, schema, data, and runtime into one coherent system, something humans and agents can reason about together.

Here's a field guide to who shipped what, and how close each gets to solving it.

## 1. Prisma Compute

**Public beta:** June 2026

<TweetColumns tweetId="2064674357075759281" side="left">

[Prisma Compute](/blog/launching-prisma-compute-public-beta) is TypeScript-focused app hosting that runs on bare metal with near-zero cold starts. It lives in the same regions as [Prisma Postgres](https://www.prisma.io/postgres), so queries return in single-digit milliseconds. It targets the workloads serverless still struggles with: WebSockets, background jobs, cron tasks (first-class in `prisma.config.ts`), and agents that need to stay warm and stateful.

Deployments are versioned with preview URLs. [Prisma Next](/blog/prisma-next-early-access-write-your-contract-prompt-your-agent-ship-your-app) (early access) adds a contract-first ORM with a machine-readable `contract.json`, so the ORM, Postgres, and Compute share one schema.

On the agent side, `SKILL.md` files, agent rules, and native MCP support give the model a clean interface for the full loop: init, schema changes, data access, deploy, logs, and redeploy. pgvector and extensions make feeding structured context easier with less manual ETL.

</TweetColumns>

## 2. Neon Compute

**Launched:** June 2026

<TweetColumns tweetId="2066597406859555017" side="right">

[Neon](https://neon.com/) added Compute alongside Object Storage and an AI Gateway, joining its Postgres and Auth products into what it calls a "complete backend for apps and agents." Every service follows the same instant, branchable, serverless model that made Neon Postgres popular.

[Branching](https://neon.com/branching) is excellent, and a standout for development, previews, and agent experimentation. The focus on agents as first-class citizens is well executed.

The main trade-off is integration depth. Neon's services are strong on their own but stay discrete pieces. There's no native ORM (you bring Prisma ORM, [Kysely](https://kysely.dev/), or another), so moving from a schema change to a deployed app still spans separate tools with no shared source of truth.

</TweetColumns>

## 3. Cloudflare Containers

**Generally available:** 13 April 2026

<TweetColumns tweetId="1937544770752045168" side="left">

[Cloudflare Containers](https://www.cloudflare.com/products/containers/) graduated from beta in April 2026. You define a container, build it with Docker, and `wrangler deploy` it across more than 320 cities worldwide.

You're billed only for actual CPU usage. You get real Linux containers that run any language, with the flexibility of Cloudflare's global edge network. That makes it strong for performance-sensitive or highly custom workloads.

The trade-off is that same flexibility. Language-agnostic and database-agnostic means you choose, connect, and manage your database, ORM, and the surrounding infrastructure yourself. Enormous power, but full assembly required: the opposite of an opinionated, integrated stack.

</TweetColumns>

## 4. Hosting.com

**Launched:** March 2026

<TweetColumns tweetId="2036456606561411501" side="right">

[Hosting.com](https://hosting.com/) launched an AI Application Hosting platform built on Cloudflare Enterprise. It tackles the gap between easy AI-generated code and secure, reliable deployment.

Developers get one-click deploys with Git integration for code from tools like Cursor and Windsurf, while non-technical users can build apps through Nova, their natural-language builder.

The launch shows that the push toward simpler hosting has spread beyond specialized infrastructure startups into the broader hosting market. The main limitation is focus: Hosting.com prioritizes broad accessibility and general-purpose use cases over deep integration and agent-native workflows. It's a wider, more approachable net rather than a stack tuned for developer-led, agent-driven teams.

</TweetColumns>

## 5. Unkey Deploy

**Launched:** April 2026

<TweetColumns tweetId="2046999421771030951" side="left">

[Unkey](https://www.unkey.com/)'s pitch is straightforward: push a Dockerfile and get a production API.

Deploy gives you multi-region rollouts, instant rollbacks, automatic domains, and preview environments. Every request routes through Unkey's auth and rate-limiting layer before it reaches your code. The backstory fits the theme: Unkey [publicly left serverless in late 2025](https://www.unkey.com/blog/serverless-exit) after hitting performance limits, then built Deploy on warm, predictable servers. It works well for straightforward API workloads.

It is, in essence, compute plus an API gateway. There's no database, no ORM, and no deeper stack integration, so you still bring your own database and absorb the context switching for your agent.

</TweetColumns>

## 6. Insforge

**Iterated through 2026 (currently early-stage)**

<TweetColumns tweetId="2062935372703629402" side="left">

[Insforge](https://insforge.dev/) is the purest agent-native entrant: an [open-source](https://github.com/InsForge/InsForge), MCP-driven backend that bundles database, auth, storage, edge functions, an AI gateway, and hosting. It's language-agnostic and bills itself as "the agent-native alternative to AWS," built from the ground up for agents to manage the full stack directly.

The vision is strong; the challenges are too. Being language-agnostic forces a lowest-common-denominator approach that hurts developer experience: generic interfaces, weaker type safety, and more boilerplate than an opinionated stack.

Combined with its broad, Supabase-shaped scope, that leads to shallower features and slower polish. Early-stage plus open-source adds the usual questions around scaling, security, and production maturity. Most teams won't trust it in production yet. Insforge has the boldest long-term vision, and the farthest to go.

</TweetColumns>

## Why is all of this happening at once?

The products look different, but they point the same way. Agents struggle to hold a thought for long, and the harder they try, the more it costs you.

METR's Time Horizon research points in a related direction: the tasks models can complete reliably keep getting longer. But longer tasks only pay off if the agent can hold onto what it learned along the way.

Then there's the money. Frontier models are expensive right now, and getting more so. As recently as 16 June 2026, reports emerged of [Microsoft eyeing DeepSeek for Copilot](https://www.axios.com/2026/06/16/microsoft-copilot-cowork-tokenmaxxing-cowork), with cost cited as a major reason. Models may get cheaper eventually, but not soon. So the efficiency walls are closing in from both sides: wasted tokens cost real money, and wasted context costs success rates.

A unified stack attacks both at once. Keep code, schema, data, and runtime coherent, and the agent (and your finance department) stops paying the re-reading tax on every turn. That's probably one reason this whole crop of hosting providers showed up at the same time.
