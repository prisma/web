If your billing already runs through Stripe, you don't need a new vendor relationship to get a production Postgres database. Stripe Projects lets you add Prisma Postgres to your project with one command — spending limits included, no new bill.

## Why this exists

Here's the situation I keep seeing: you're building on Stripe. Your billing is integrated, your account is verified, your payment setup is done. Then you need a database, and suddenly you're off signing up for another service, verifying another email, adding another card, and managing another bill.

That never made sense to me. You've already done the hard part — Stripe knows who you are and how you pay. So we made Prisma Postgres a provider on Stripe Projects: one command in the Stripe CLI you already use, and you have a database. No browser, no signup form, no new payment method.

The part I like most is the spending limits. The payment credential Stripe hands us carries a monthly spending limit that *you* control from the Stripe side. If a Prisma plan costs more than your limit allows, the upgrade simply doesn't go through. Cost control isn't something you bolt on later — it's there before your first query.

## Getting started

Two commands. From your project directory:

```bash
# Set up Stripe Projects in your repo
stripe projects init

# Add a Prisma Postgres database
stripe projects add prisma/project
```

Behind that second command, a few things happen on our side:

```bash
stripe projects add prisma/project
# ✓ Prisma workspace created for your Stripe account
#   (named stripe-projects-<your-account-id> — yours, dedicated)
# ✓ Project + Prisma Postgres database provisioned on the Free plan
# ✓ Connection string written to your .env

DATABASE_URL="postgres://..."
```

Notice what *didn't* happen: no browser opened, no email verification loop, no credit card form. Stripe has already verified your email, so we trust it and create your Prisma account from it directly in the CLI. If you already have a Prisma account under that email, we link to it — your existing workspaces are untouched.

You start on the Free plan: 100k queries and 0.5 GiB of storage per month. The limits are hard — when you hit them, the database tells you, it doesn't bill you. There is no way to accidentally spend money on the free tier.

## Managing your plan

When the free tier gets tight, upgrade from the same CLI:

```bash
# Upgrade to the Pro plan
stripe projects upgrade prisma-plan pro
# ✓ Spending limit checked against the plan price first
# ✓ Workspace subscription created — billed through Stripe
# ✓ Plan applies immediately
```

Upgrades are immediate. Before anything is charged, we check the plan price against your Stripe spending limit — if the limit doesn't cover it, the upgrade is rejected and nothing changes. There are four plans: `free`, `starter`, `pro`, and `business`, and the plan applies to your whole Stripe Projects workspace, so every database you've added shares it.

Downgrading is the same command pointed at a smaller plan:

```bash
# Downgrade back to the free plan
stripe projects upgrade prisma-plan free
# ✓ Cancellation scheduled for the end of your billing cycle
# ✓ You keep paid entitlements until then — you paid for them
```

One thing to be upfront about: downgrades to free take effect at the end of your billing cycle, not immediately. You've paid for the month, so you keep the paid limits for the month. Moving between paid plans (say `starter` → `pro`) is immediate, with the proration billed right away.

## Day-to-day

Two commands cover most of what you'll reach for:

```bash
# Where do I stand?
stripe projects status

# Take me to my project in the Prisma Console
stripe projects open prisma
```

`status` shows what's provisioned and on which plan. `open` is the one I use constantly — it mints a short-lived link (five minutes, single use) that drops you straight into your workspace dashboard in the Prisma Console, already authenticated as the right account. If you're signed into the Console as someone else, it tells you instead of silently mixing accounts.

## Cleaning up

Tearing down is just as direct:

```bash
# Remove the database
stripe projects remove prisma-database
# ✓ Database deprovisioned immediately
# ✗ Your plan is NOT changed — downgrade separately if you want that

# Disconnect Prisma from this project entirely
stripe projects unlink prisma
```

Removing a database and changing your plan are deliberately decoupled — deleting a database never silently touches your billing. If you're removing your last database and want to stop paying, downgrade the plan too:

```bash
stripe projects upgrade prisma-plan free
```

## What's next

The database is the first piece. Prisma Compute — our TypeScript app hosting, currently in public beta — is coming to Stripe Projects next. Once it lands, the same flow gets you a deployed app *next to* that database: spin something up to show your colleagues, or stand up an ad-hoc revenue app with billing already wired in, because you started from Stripe in the first place.

If your billing already lives in Stripe, try it: `stripe projects add prisma/project` and you're a connection string away from a real Postgres database — with a spending limit you set before we could ever bill you.
