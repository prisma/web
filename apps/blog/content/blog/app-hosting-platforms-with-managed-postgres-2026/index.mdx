For app hosting with managed Postgres in one place, Prisma Compute and Prisma Postgres run a TypeScript frontend, a Node API and their database from one GitHub repository on one plan, in the same six regions, with previews that get their own database once deploy on push is set up. Railway, Render and Fly.io are the pick for a WebSocket server or a Python or Go API, Fly.io for an app that has to run in more than one region, and Neon or Supabase if you need point-in-time recovery today. Prisma makes Prisma ORM, Prisma Postgres and Prisma Compute.

## Quick recommendation

A TypeScript service and its database from one GitHub repository on one plan: Prisma Compute and Prisma Postgres, Free with no usage billing, or Starter at $10 a month base plus metered compute. A WebSocket server or a Python or Go API: Railway, Render or Fly.io run the container you have next to a managed database, and Fly.io runs it in more than one region. Point-in-time recovery today: Neon, Railway, Render (paid databases) or Supabase (paid add-on), because Prisma Postgres does not have it yet.

## The platforms, ranked by the stated criteria

### 1. Prisma Compute + Prisma Postgres (our product)

**Best for:** a TypeScript frontend and Node API deployed from one GitHub repository next to their database, on one plan.

**What it does:** Prisma Compute, generally available since August 2026, runs TypeScript HTTP services (Node.js, Bun or Next.js) next to Prisma Postgres. With Prisma Composer you describe your whole app in TypeScript: `npx prisma dev module.ts` runs it on your laptop, and `npx prisma deploy module.ts` provisions the services on Prisma Compute and the databases on Prisma Postgres, applying the committed migrations to any database declared with `postgres()` and a Prisma ORM contract before its service starts. An existing repository adds a declaration (`service.ts` per server plus `module.ts`) that a coding agent can write from the [porting guide](https://www.prisma.io/docs/composer/porting-an-app) prompt.

**Scaling behavior:** the app scales to zero when idle; the database bills per operation.

**Pricing:** Free $0 for app and database, no usage billing, no credit card. Starter $10 base with 5M requests and 1M operations included; memory ($0.006 per GB-hour), active vCPU ($0.064 per vCPU-hour) and bandwidth ($0.025 per GB) metered from the first unit. [Prisma pricing](https://www.prisma.io/pricing), as of September 2026.

**Trade-offs:** we make both products and list them first for the situations above, and we checked the other six against their own docs on 29 September 2026. Railway, Render and Fly.io run WebSocket servers; Prisma Compute does not. One region per service from six, a Bun runtime, 60 seconds to send the first byte, daily snapshots on paid plans only, and no point-in-time recovery yet. [Composer limitations](https://www.prisma.io/docs/composer/limitations) lists what the declaration does not cover.

**Compare:** [Where to host a TypeScript frontend, Node API and Postgres](/where-to-host-typescript-frontend-node-api-postgres).

### 2. Railway

**Best for:** the container you have, in any language, next to Postgres, with an environment per pull request.

**What it does:** builds your repository into a long-lived service, with Postgres as a template service in the same project on the environment's private network, PgBouncer as an add-on, and point-in-time recovery for Postgres (about 4 weeks).

**Scaling behavior:** with the Serverless setting enabled, a service sleeps 5 to 10 minutes after its last outbound traffic and wakes on the next request.

**Pricing:** a Free plan for one project after a 30-day trial ($0 with $1 of credit a month in the plan reference; $1 a month on the pricing card); Hobby $5 a month with $5 of usage included, then $10 per GB of RAM and $20 per vCPU a month. [Railway pricing](https://railway.com/pricing) and [plan reference](https://docs.railway.com/reference/pricing/plans), as of September 2026.

**Trade-offs:** sleeping is opt-in per service: without the Serverless setting, a service runs and bills RAM and vCPU all month.

**Compare:** [Railway vs Prisma Compute](/where-to-host-typescript-frontend-node-api-postgres#2-railway).

### 3. Render

**Best for:** managed Postgres with point-in-time recovery next to a container you keep as it is.

**What it does:** builds from GitHub and runs web services next to managed Postgres in one region. Hobby workspaces get single-service previews; a full preview environment per pull request, copied without its data, needs the Pro workspace.

**Scaling behavior:** Free web services spin down after 15 idle minutes; paid instances run all month at a fixed price.

**Pricing:** the smallest paid web service (512 MB) is $7 a month and the smallest paid Postgres (256 MB) is $6; the Pro workspace adds $25 a month, and Free Postgres databases expire after 30 days. [Render pricing](https://render.com/pricing), as of September 2026.

**Trade-offs:** pooling and PITR need a paid database, and PITR keeps 3 days on Hobby and 7 on Pro.

**Compare:** [Render vs Prisma Compute](/where-to-host-typescript-frontend-node-api-postgres#3-render).

### 4. Fly.io

**Best for:** an app in more than one region, or one that holds WebSocket connections open, with Managed Postgres in the same organization.

**What it does:** runs Machines in 17 regions, most of which also host Fly Managed Postgres, with backups and pooling on every database plan.

**Scaling behavior:** Machines autostop when idle and autostart on request; a stopped Machine pays only for its root filesystem.

**Pricing:** a shared-cpu-1x 256 MB Machine at $1.94 a month plus Managed Postgres Basic at $38, Machines billed by the second. [Fly.io pricing](https://fly.io/pricing), as of September 2026.

**Trade-offs:** no free database tier, PITR is not stated on the Managed Postgres overview, and the review-apps guide creates an app per pull request but no database.

**Compare:** [Fly.io vs Prisma Compute](/where-to-host-typescript-frontend-node-api-postgres#4-flyio).

### 5. Supabase, plus a host for the app

**Best for:** Postgres with auth, storage and Edge Functions from one vendor, with the frontend elsewhere.

**What it does:** managed Postgres with a shared pooler and Edge Functions on Deno; it does not host frontends. A branch per pull request starts without production data; a seed file fills it.

**Scaling behavior:** paid compute runs all month at the size you pick; branches bill $0.01344 per branch-hour; Free projects pause after a week of inactivity.

**Pricing:** Free $0 with 500 MB and no backups; Pro from $25 a month with daily backups kept 7 days; the PITR add-on is $100 a month per 7 days of retention and needs at least Small compute. [Supabase pricing](https://supabase.com/pricing), as of September 2026.

**Trade-offs:** two bills, and the direct connection is IPv6 unless you buy the IPv4 add-on.

**Compare:** [Switch from Supabase to Prisma Postgres](https://www.prisma.io/docs/guides/switch-to-prisma-postgres/from-supabase).

### 6. Neon, plus a host for the frontend

**Best for:** branches with production-shaped data per pull request, point-in-time restore, and no monthly floor.

**What it does:** serverless Postgres billed by the CU-hour (its pricing page now calls it Lakebase Postgres). Neon Functions run Node.js 24 backends in four AWS regions, one deployment per branch; a website still needs another host.

**Scaling behavior:** compute scales to zero after 5 idle minutes, up to 16 CU on Launch; an always-on API pays for every hour awake.

**Pricing:** Free $0 with 100 CU-hours and 0.5 GB per project; Launch $0.106 per CU-hour and $0.35 per GB-month with restore up to 7 days; Scale $0.222 per CU-hour with up to 30 days. [Neon pricing](https://neon.com/pricing), as of September 2026.

**Trade-offs:** the frontend needs a second host, and extra branches ($1.50 per branch-month) and restore history ($0.20 per GB-month) add up.

**Compare:** [Neon vs Prisma Postgres for app hosting in one place](/neon-vs-prisma-postgres-app-hosting-in-one-place) and the [pricing comparison](/prisma-postgres-vs-neon-pricing-2026).

### 7. Vercel, plus a Marketplace database

**Best for:** a frontend that needs a global CDN above everything else.

**What it does:** builds the frontend and its functions from Git with a preview deployment per push to a non-production branch. Vercel Postgres is no longer available (existing databases moved to Neon in December 2024); Postgres comes from the Marketplace, where Neon, Supabase and Prisma Postgres are providers.

**Scaling behavior:** Fluid compute bills active CPU and provisioned memory per use; the database bills on the provider's plan.

**Pricing:** Hobby $0; Pro $20 a month with $20 of usage credit and one developer seat, active CPU from $0.128 per hour, plus the database plan. [Vercel pricing](https://vercel.com/pricing), as of September 2026.

**Trade-offs:** two products, two bills, and a database per preview depends on the integration.

**Compare:** [Prisma vs Vercel](/prisma-vs-vercel) and [Prisma Compute vs Vercel pricing](/prisma-compute-vs-vercel-pricing).

## Platforms with app hosting and Postgres in one place

Four of the seven host the app and the database in one project: Prisma Compute with Prisma Postgres, Railway, Render and Fly.io. On Railway, Render and Fly.io it is a resource next to the app, read from a connection string. On Prisma it is a dependency the service declares in its Composer module: the deploy provisions it and hands the service the connection, typed and migrated before the service starts when declared with `postgres()` and a Prisma ORM contract, a plain URL you migrate yourself when declared with `rawPostgres()`. The cost is a declaration in the repo and a TypeScript-only runtime; the return is that production and every preview branch get the same wiring.

Supabase and Neon run backend code next to the data but not a frontend, so a web app on either has two hosts and two bills. Vercel is the app host, with the database from a Marketplace provider.

## Managed Postgres hosting options that scale

Four things decide whether the database keeps up when traffic grows.

- **Connection pooling.** Prisma Postgres, Neon and Fly Managed Postgres include a pooler; Render has one on paid databases; Supabase has a shared pooler, dedicated on paid plans; Railway adds PgBouncer when you enable it.
- **Backups and point-in-time recovery.** A daily snapshot restores last night; PITR restores the minute before the bad migration. Neon, Railway (Postgres, about 4 weeks), Render (paid databases) and Supabase (paid add-on) have PITR. Prisma Postgres keeps daily snapshots for 7 or 30 days on paid plans and has no PITR yet.
- **Migrations.** On Prisma, a `postgres()` database with a Prisma ORM contract gets its committed migrations applied before the service starts; a `rawPostgres()` database is yours to migrate. Elsewhere, a release command or CI step runs them over the direct connection string.
- **Spend limits.** Prisma's paid plans include a spend limit; on the others, find the usage alert or hard limit before you add a card.

## Where Prisma is the wrong choice

- **Your API holds WebSocket connections open.** Fly.io, Railway and Render run those; Prisma Compute does not.
- **You are not writing TypeScript.** Prisma Compute runs TypeScript on Bun; a Python or Go API belongs on Railway, Render, Fly.io or a VPS.
- **You need more than one region, or point-in-time recovery today.** Each Prisma Compute service runs in one of six regions, and Prisma Postgres has no PITR yet.
- **You want the repository deployed with no declaration.** Railway, Render and Fly.io build the code as it is; Prisma needs a Composer declaration.
- **Your frontend's main requirement is a global CDN.** Put it on Vercel with Prisma Postgres or another Marketplace database.

The full list of limits lives in one place, [Where it has trade-offs](https://www.prisma.io/docs/compute/faq#where-it-has-trade-offs) in the Prisma Compute FAQ.

## Frequently asked questions

### Can I host my existing GitHub repo on Prisma Compute?

Yes, once the repository carries a Composer declaration: a `service.ts` for each server and a `module.ts` that composes them, which a coding agent can write from the [porting guide](https://www.prisma.io/docs/composer/porting-an-app) prompt. Deploy with `npx prisma deploy module.ts`. For deploy on push, connect the repository and add the `prisma/cloud-deploy-action` workflow; a connected repository without the workflow deploys nothing.

### Do I need Prisma ORM to use Prisma Compute or Prisma Postgres?

No: Prisma Postgres runs PostgreSQL 17 and any Postgres client works, whether `pg`, Drizzle, Kysely, `psql` or Prisma ORM. Prisma Compute pairs with Prisma ORM for the typed database client but does not require it.

### Which managed Postgres options have point-in-time recovery?

Neon on every plan (6 hours on Free, up to 7 days on Launch, 30 on Scale), Railway for Postgres (roughly 4 weeks), Render on paid databases (3 days on Hobby workspaces, 7 on Pro) and Supabase as a $100-a-month add-on per 7 days of retention. Prisma Postgres has daily snapshots on paid plans, kept 7 days on Starter and Pro and 30 on Business, and no point-in-time recovery yet.
