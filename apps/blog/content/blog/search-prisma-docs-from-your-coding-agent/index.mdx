The Prisma MCP server now answers documentation questions. Ask about Prisma ORM, Prisma Postgres, schema design, or migrations from inside your editor and get an answer grounded in the official docs, with links back to the source.

If you already use the Prisma MCP server to spin up databases, you get this for free. No new server to register, no extra auth, no client-side config.

## A docs assistant that lives where you work

Most of the time you hit the docs in the middle of something else: you are wiring up a connection, your agent is mid-task, and you need one specific answer. Switching to a browser, searching, scanning a page, and coming back breaks the loop.

`search_prisma_documentation` closes that loop. It is a single tool that takes a natural-language question and returns a cited answer assembled from Prisma's official docs and knowledge sources. The answer comes back in the same conversation your agent is already working in.

The tool is read-only, so it works even when your client is running in a restricted mode.

## A quick word on our MCP server

If you have not used it yet, the [Prisma MCP server](/about-mcp-servers-and-how-we-built-one-for-prisma) lets AI tools manage Prisma Postgres through a standard interface. From a connected client your agent can list databases, run SQL, and introspect schemas.

Docs search is the newest tool in that set. Same server, same connection, one more thing your agent can do.

## How the integration works

Under the hood, `search_prisma_documentation` proxies [Kapa's hosted MCP server](https://docs.kapa.ai/integrations/mcp/guides/tutorial-proxy-kapa-from-your-mcp). Per call, our server connects to Kapa as a client, forwards your question, and returns the answer. Your client only ever talks to one endpoint, ours, while Kapa does the retrieval behind it.

The Kapa API key stays server-side and never reaches your machine. Calls run through the same auth, rate limiting, and tracing as every other tool.

## How to use it

Connect to the Prisma MCP server as usual. For Claude Code:

```bash
claude mcp add --transport http prisma https://mcp.prisma.io/mcp
```

Then just ask, and your agent picks the tool up on its own:

> Use the Prisma docs search to find out how connection pooling works on Prisma Postgres.

Or call it directly from any MCP client:

```json
{
  "name": "search_prisma_documentation",
  "arguments": { "query": "How do I deploy my project to Prisma Compute" }
}
```

You get back a markdown answer with links to the relevant pages on [prisma.io/docs](https://www.prisma.io/docs).

## While you are here

Docs search is one tool in a bigger platform. If you are reaching for it, two products are worth knowing about:

- **[Prisma Postgres](https://www.prisma.io/postgres)** is fully managed Postgres with no cold starts, free branching, and operation-based pricing with spend caps.
- **[Prisma Compute](https://www.prisma.io/compute)** runs your TypeScript app co-located with that database, so your queries stay in single-digit milliseconds and long-running work like cron and background jobs is supported natively.

Together with the ORM, they are designed to work as one platform, so your agent can build, deploy, and iterate without stitching vendors together. Docs search just means it can stop and ask a question without leaving the editor.
