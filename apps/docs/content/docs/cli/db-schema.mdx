`db schema` reads the live database schema and prints it as a tree, or as the result document with `--json`. The command is always read-only: it never writes a file and never changes the database.

Use it when you need to inspect what Prisma ORM sees in the database before inferring, signing, updating, or debugging drift.

## Usage

```npm
npx prisma db schema --db "$DATABASE_URL"
```

## Options

| Option | What it does |
| --- | --- |
| `--db <url>` | Connects to the database. |
| `--config <path>` | Read this config file instead of `./prisma.config.ts`. |
| `--json` | Prints machine-readable schema output. |

## Examples

```npm
npx prisma db schema --db "$DATABASE_URL"
npx prisma db schema --db "$DATABASE_URL" --json > schema.json
```

## Data lines

`db schema` prints the tree on standard error and nothing on standard output, because the tree's shape depends on the database family. Use `--json` to read the schema in a script. [Global flags](/cli/global-flags#data-lines-of-prisma-orm-commands) lists the data lines of the other commands.

## Column types

On PostgreSQL and SQLite, the tree and the JSON output show each column's type as the database names it. In the JSON output, this text is the column's `typeText`:

```bash
npx prisma db schema --db "$DATABASE_URL" --json | jq 'select(.kind == "result") | .envelope.result.schema.tables[].columns[].typeText'
```

On PostgreSQL, `typeText` is the full type name, such as `integer` or `character varying(20)`, not a short name such as `int4`. An enum is named as your contract names it, such as `My Mood`, or `app.status` for an enum outside the `public` schema. A type from a schema that is not on the search path keeps the schema name, such as `extensions.vector(3)` for a pgvector column.

On SQLite, which Prisma ORM 8 supports as an [experimental package](/orm/supported-databases), `typeText` is the type the column was declared with, in lower case: a column declared `VARCHAR(255)` reads `varchar(255)`.

If a script reads `nativeType` or `resolvedNativeType` from the JSON output, change it to read `typeText`, which has replaced both fields since `8.0.0-rc.19`.
