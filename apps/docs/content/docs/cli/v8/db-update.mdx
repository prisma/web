`db update` compares the live database with the emitted contract and applies the changes that close the gap, whether or not the database was bootstrapped with `db init`.

Use it for direct reconciliation when you do not need a checked-in migration package.

## Usage

```npm
npx @prisma/cli@next db update --db "$DATABASE_URL"
```

## Options

| Option | What it does |
| --- | --- |
| `--db <url>` | Connects to the database. |
| `--dry-run` | Shows planned operations without applying them. |
| `--to <contract>` | Updates to a specific contract (hash, prefix, ref name, migration directory name, or `./path`). |
| `--advance-ref <name>` | Advances the named [ref](/cli/v8/migration-ref) to the post-command contract hash. |
| `--config <path>` | Reads a specific `prisma-next.config.ts` file. |
| `--json` | Prints a machine-readable result. |

## Destructive changes need consent

An operation that would destroy data is applied only with your consent: the command asks you to type the database name. A run with nobody to ask, such as a CI job or a run with `--no-interactive`, takes the consent from `--confirm <database>` instead:

```npm
npx @prisma/cli@next db update --db "$DATABASE_URL" --no-interactive --confirm appdb
```

## Recommended flow

```npm
npx @prisma/cli@next contract emit
npx @prisma/cli@next db update --db "$DATABASE_URL" --dry-run
npx @prisma/cli@next db update --db "$DATABASE_URL"
npx @prisma/cli@next db verify --db "$DATABASE_URL"
```

Use `--dry-run` before applying changes in shared environments.

## When to use migrations instead

For reviewable database changes in version control, use [`migration plan`](/cli/v8/migration-plan) and [`migrate`](/cli/v8/migration-apply).

Use `db update` for local development, preview environments, and workflows where direct reconciliation is acceptable.
