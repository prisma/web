Use `git` commands to manage the GitHub repository connection. Connecting enables the OIDC credential exchange for GitHub Actions deploys and the branch lifecycle automation. See [GitHub integration](/compute/github) and [Deploy on push](/compute/deploy-on-push).

## Usage

```npm
npx prisma git connect
```

Run it from a [linked](/cli/project) project directory, or name the project with `--project <id-or-name>`. Without a URL, it connects the repository of the directory's `origin` remote.

If the Prisma GitHub App does not cover the repository yet, the command opens the browser to install it and waits for the install. That step needs an interactive terminal: in CI, without a terminal, or with `--no-interactive`, it fails with `CLI.INTERACTION_REQUIRED` and prints the install URL. When the app is already installed, the command needs no terminal and runs in scripts.

Connecting from the CLI does not add a deploy workflow to the repository. [Add it yourself](/compute/deploy-on-push#4-add-the-deploy-workflow), or connect through the [Console](https://pris.ly/pdp), which opens a pull request with the workflow.

## Commands

| Command                  | Description                                                      |
| ------------------------ | ----------------------------------------------------------------- |
| `git connect [git-url]`  | Connect the linked project to a GitHub repository. Starts the GitHub App install flow if needed |
| `git disconnect`         | Stop the credential exchange and branch automation. Keeps the project and existing branches |

Both commands take `--project <id-or-name>` to name a project other than the one this directory is linked to.
