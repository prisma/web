Prisma ORM ships with a unified Prisma CLI. One binary contains the ORM commands and the platform commands for [Prisma Composer](/composer), [Prisma Compute](/compute), Prisma Postgres, and object-store buckets.

:::note[Prisma ORM 7 users]

Prisma ORM 8 is a release candidate. Prisma ORM 7 remains fully supported; its docs live at [/orm/v7](/orm/v7) and its setup paths at [/v7/getting-started](/v7/getting-started).

For what release candidate means, when the final release is expected, and how to stay on version 7, see [Release status](/orm/release-status). For the Prisma ORM 8 name of every Prisma ORM 7 API, see [Coming from Prisma ORM 7](/orm/coming-from-prisma-orm-7).

:::

The Prisma ORM CLI ships in the `prisma` package. Run it without installing:

```npm
npx prisma --help
npx prisma contract emit
```

With `prisma` installed in your project, these commands become plain `prisma contract emit` and so on.

For a full app scaffold, follow [Create a new app with PostgreSQL](/prisma-orm/quickstart/postgresql). That path creates the project files and package scripts for you. This CLI reference is for the lower-level commands those scripts call.

## Platform commands

The platform commands manage the services, databases, and buckets your app runs on. With [`deploy`](/cli/deploy) and [`dev`](/cli/dev) you deploy a [Prisma Composer](/composer) app to [Prisma Compute](/compute) and run it locally; with [`service`](/cli/service) and [`git`](/cli/git) you manage services, their versions, logs, and domains, and the repository connection. With [`postgres`](/cli/postgres) you spin up and manage [Prisma Postgres](/postgres) databases. With [`bucket`](/cli/bucket) you create blob-storage buckets and their access keys. [`auth`](/cli/auth), [`project`](/cli/project), and [`branch`](/cli/branch) handle the account, project, and branch plumbing around them. Each command group has its own page in this section. Deployments are created by `deploy`, by a git push once you [set up deploy on push](/compute/deploy-on-push), or from the [Console](https://pris.ly/pdp), and each deploy produces a service **version**.

## Common workflows

Platform users deploy apps, create databases, and provision buckets with the [platform commands](#platform-commands), while ORM users manage their schema, contracts, and migrations with the ORM and migration commands.

### Deploy an app

Sign in, then build and deploy a [Prisma Composer](/composer) app. `deploy` creates the project on its first run, and a new project needs a region, set in the deploy config or as `PRISMA_REGION`; see [`deploy`](/cli/deploy).

```npm
npx prisma auth login
npm run build
npx prisma deploy
```

To deploy on every push, also connect the repository with [`git connect`](/cli/git) and add the deploy workflow; see [Deploy on push](/compute/deploy-on-push).

Follow a deploy with [`service logs`](/cli/service) and manage the result with the [`service` commands](/cli/service).

### Create a database

```npm
npx prisma postgres create mydb
npx prisma postgres connection create mydb
```

`postgres create` prints a one-time connection URL; `postgres connection create` mints another when you need one. See [`postgres`](/cli/postgres).

### Create a bucket

```npm
npx prisma bucket create --name my-bucket
npx prisma bucket key create <bucket-id>
```

`bucket key create` prints the key's one-time credentials. See [`bucket`](/cli/bucket).

### Start in an existing project

```npm
npx prisma@latest orm init --target postgres --authoring psl
npx prisma contract emit
npx prisma db init --db "$DATABASE_URL" --advance-ref db
```

The [ref](/cli/migration-ref) named `db` is a file in your repository, `migrations/app/refs/db.json`, that records which version of your contract your development database has, and [`migration plan`](/cli/migration-plan) starts from that version. When you leave `--db` off and let the connection come from `prisma.config.ts`, `db init` and `db update` point the `db` ref at the state they applied. When you pass `--db`, they leave the ref alone, so add `--advance-ref db` as above. Without it, an existing `db` ref keeps naming an older state, and a later `migration plan` starts from that out-of-date contract. If the ref was never created, `migration plan` refuses with `MIGRATION.PLAN_ORIGIN_UNKNOWN` as soon as migrations exist on disk.

### Adopt an existing database

Use this when the database already has tables and you want Prisma ORM to describe them instead of creating them. Run it in a project that `orm init` set up. `contract infer` reads the tables and writes them as `contract.prisma` in the folder where `contract emit` writes its files, which after `orm init` is `src/prisma/`. That replaces the starter contract that `contract emit` reads, so commit or copy any changes you made to it first.

```npm
npx prisma contract infer --db "$DATABASE_URL"
npx prisma contract emit
npx prisma db sign --db "$DATABASE_URL"
npx prisma db verify --db "$DATABASE_URL"
```

If you pass `--output` to write the file somewhere else, set `contract` in `prisma.config.ts` to the same path, or `contract emit` keeps reading the old file.

`db sign` also sets the `db` ref to the signed contract, so the next `migration plan` starts from the database you adopted. Pass `--no-advance-ref` to sign without changing any ref.

### Use checked-in migrations

```npm
npx prisma contract emit
npx prisma migration plan --name add_users
npx prisma migration status --db "$DATABASE_URL"
npx prisma db migrate --db "$DATABASE_URL" --advance-ref db
npx prisma db verify --db "$DATABASE_URL"
```

`db migrate` changes no ref unless you pass `--advance-ref db`. Pass it in development, so that the next `migration plan` starts from what you just applied instead of planning the same change again. Leave it off in CI and deployments, which should not change the refs in your repository: there, run `npx prisma db migrate`, or `npx prisma db migrate --to <ref>` if you name the state each environment should reach with a ref.

## Agent skills

Prisma packages ship [agent skills](/ai/tools/skills): instructions that teach AI coding agents the installed version's commands and APIs. [`init`](/cli/init) prepares a repository once, and [`skills sync`](/cli/skills) keeps the installed copies matching your package versions. Install after `init`, so the `prisma` dev dependency it adds is in `node_modules`:

```npm
npx prisma@latest init
npm install
npx prisma skills sync
```

## Other commands

A few commands have no page of their own yet. `contract format` formats your `contract.prisma` in place, with the indentation and line endings that [`formatter`](/cli/configuration#schema-formatting) sets. It also formats a Prisma ORM 7 `schema.prisma` that your config reads with `prisma7Schema(...)`. `lsp` starts the Prisma ORM language server, which your editor runs for you, as [Editor support](/orm/contract-authoring/editor-support) describes.

The `migration` group also has commands that only read and change nothing. Run any of them with `--help` for what each option does:

- `migration list` lists the migrations on disk, for each [contract space](/orm/migrations/the-migration-graph#terms-used-on-this-page). Options: `--space`, `--ascii`, `--legend`.
- `migration log` lists the migrations the database has actually applied, and when, from the database's own record of them. Options: `--db`, `--utc`, `--ascii`.
- `migration graph` draws the chain of migrations. Options: `--space`, `--dot` for Graphviz output, `--ascii`, `--legend`.
- `migration check [target]` checks that no `ops.json` or `migration.json` was edited by hand, and that every ref names a contract state that exists. Option: `--space`.
