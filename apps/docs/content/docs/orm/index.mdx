Prisma ORM is the library your TypeScript app uses to read and write its database. You describe your data in a contract, which is the file that holds your models, and Prisma ORM gives you typed queries and migrations for it. If you know Prisma ORM 7, the contract takes the place of `schema.prisma`, and the queries have a new shape, which the example below shows.

Prisma ORM 8 is a release candidate, not yet a final release, and it is what `npm install prisma` gives you today. It supports PostgreSQL. MongoDB is in early access, so some of what works on PostgreSQL is missing on it. SQLite ships as an experimental package, `@prisma/orm-sqlite`. MySQL, SQL Server, and CockroachDB come later, and until then Prisma ORM 7 supports them. [Supported databases](/orm/supported-databases) says what early access and experimental mean, and what works on each database.

Here is a contract with two models, a query that reads them, and what the query prints against a database that holds two users and two posts. The first line of the contract, `// use prisma-8`, is required, and the setup commands write it for you. `db` is exported from `src/prisma/db.ts`, which reads `DATABASE_URL` and creates the client. For a new app, `npm create prisma@latest` writes both files. For an app you already have, `npx prisma@latest orm init` writes them. Run the query file with `npx tsx index.ts`, after a page under "Start here" has created the tables.

```prisma title="src/prisma/contract.prisma"
// use prisma-8

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  posts Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int
}
```

```typescript title="index.ts"
import { db } from "./src/prisma/db";

const users = await db.orm.public.User.include("posts").all();
console.dir(users, { depth: null });

await db.close();
```

```text title="Output" no-copy
[
  {
    email: 'alice@example.com',
    id: 1,
    name: 'Alice',
    posts: [
      { authorId: 1, id: 1, title: 'Hello, world' },
      { authorId: 1, id: 2, title: 'Second post' }
    ]
  },
  { email: 'bob@example.com', id: 2, name: 'Bob', posts: [] }
]
```

Every field in the result is typed from the contract, down to each post's `title`. `db.orm` holds the typed queries for your models, and `public` is the PostgreSQL schema the table is in, which is the default one unless you created another. After you change the contract, run `npx prisma contract emit`. It replaces `prisma generate`, and there is no `@prisma/client` package: your code imports `db` from `src/prisma/db.ts`.

## What you can do with Prisma ORM

- [Model your data](/orm/data-modeling): describe your models, their fields, and how they relate to each other.
- [Read and write data](/orm/fundamentals/reading-data): fetch, filter, sort, and paginate records, then create, update, and delete them.
- [Query relations](/orm/fundamentals/relations-and-joins): read related records in the same query with `.include(...)`.
- [Run transactions](/orm/fundamentals/transactions): make several writes succeed or fail together.
- [Migrate your database](/orm/migrations/how-migrations-work): after you change the contract and run `npx prisma contract emit`, `npx prisma migration plan` writes the migration for you to review. `npx prisma db migrate --advance-ref db` then applies it to your development database and records that it did, so the next plan starts from there. The two commands take the place of `prisma migrate dev`.
- [Add middleware](/orm/middleware/how-middleware-works): run your own code before and after every query, for example to log each query. It takes the place of both `$use` and `$extends`.
- [Use extensions](/orm/extensions/using-extensions): add PostgreSQL features such as vector search, geospatial data, and full-text search. These are database extensions, not the `$extends` of Prisma ORM 7.
- [Use the CLI](/cli): run the `npx prisma` commands for your contract, your database, and your migrations.

## Release status

`npm install prisma` gives you Prisma ORM 8 today. If your app is on Prisma ORM 7 and you want to stay there, lock `prisma` and `@prisma/client` to version 7 in `package.json`, as [Release status](/orm/release-status) shows. That page also has the date of the final release and how long Prisma ORM 7 stays supported after it.
