An extension is an npm package that adds a capability to Prisma ORM. The database packages are extensions, and so are column types such as vectors and geometries, index types, query operations, and the middleware that runs around each query.

You register an extension in two places: in `prisma.config.ts`, so the CLI can emit your contract and plan migrations, and on the client, so your queries can use the new types and operations. [Using extensions](/orm/extensions/using-extensions) walks through both with pgvector. Middleware registers on the client only; see [How middleware works](/orm/middleware/how-middleware-works).

## Publish your own

An extension is a versioned npm package with a `control` entrypoint for the config and a `runtime` entrypoint for the client. The same layout adds a database: `@prisma/orm-postgres` is the reference for a SQL database and `@prisma/orm-mongo` for a document database. The [call for extension authors](https://www.prisma.io/blog/prisma-next-call-for-extension-authors) describes the layout. To write middleware, follow [Authoring custom middleware](/orm/middleware/authoring-custom-middleware).

When the package is on npm, [submit it to the directory](https://www.prisma.io/extensions/submit). The form validates the entry, checks that the package exists on npm, and opens a pull request for a maintainer to review.
