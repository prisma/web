An extension is an npm package that adds something Prisma ORM does not do on its own. The packages that add support for a database are extensions themselves, and so are column types such as vectors and geometries, index types, query operations, and the middleware that runs around each query.

Installing the package is not the whole job, because you also register the extension where it is used. You register it in `prisma.config.ts` so that `prisma contract emit` can write `contract.json` and `contract.d.ts` from your contract and the migration commands can plan your migrations, and you register it again when you create the client so that your queries can use the new types and operations. [Using extensions](/orm/extensions/using-extensions) walks through both registrations with pgvector. Middleware is the exception, because you register it on the client only, and [How middleware works](/orm/middleware/how-middleware-works) covers that.

## Publish your own

An extension you write yourself is usually a versioned npm package with one entrypoint for each of the places it gets registered: a `control` entrypoint for the config and a `runtime` entrypoint for the client. Middleware is again the exception and ships a single entrypoint. Adding a whole database uses that same layout, so if that is what you are writing, `@prisma/orm-postgres` is the one to follow for a SQL database and `@prisma/orm-mongo` for a document database. The [call for extension authors](https://www.prisma.io/blog/prisma-next-call-for-extension-authors) describes the layout. To write middleware, follow [Authoring custom middleware](/orm/middleware/authoring-custom-middleware).

Once your package is on npm, [submit it to the directory](https://www.prisma.io/extensions/submit). The form checks that your entry is valid and that the package really exists on npm, then opens a pull request for a maintainer to review.
