Prisma ORM keeps its core small and exposes it through a public SPI, so everything around the core is an extension: the PostgreSQL, MongoDB, and SQLite packages themselves, column types such as vectors and geometries, index types, query operations, and the middleware that wraps every query. Each extension is a versioned npm package that you register in `prisma.config.ts` and on the client, as [Using extensions](/orm/extensions/using-extensions) shows step by step. Middleware registers on the client only, which [How middleware works](/orm/middleware/how-middleware-works) covers.

The [extension directory](https://www.prisma.io/extensions) has install commands and registration snippets for every entry. The table below is generated from the same registry.

## Publish your own

The layout that ships pgvector is open to you, and it also covers adding a database: `@prisma/orm-postgres` is the reference for a SQL target and `@prisma/orm-mongo` for a document target. An extension pack is a versioned npm package with a `control` entrypoint for the config and a `runtime` entrypoint for the client. The [call for extension authors](https://www.prisma.io/blog/prisma-next-call-for-extension-authors) explains the layout, and the [authoring guide](/orm/middleware/authoring-custom-middleware) builds a middleware step by step.

When your package is on npm, [submit it to the directory](https://www.prisma.io/extensions/submit). The form validates the entry, checks that the package resolves on npm, and opens a pull request against the registry for a maintainer to review.
