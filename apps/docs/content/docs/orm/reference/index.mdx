Prisma ORM gives you three typed ways to write a query. In Prisma ORM 7 you wrote `findMany({ where, include })`. Now each of those arguments is a method you chain: `.where(...).include(...)`. See [Coming from Prisma ORM 7](/orm/coming-from-prisma-orm-7), which maps each argument to its method.

- The **ORM client** is at `db.orm`. It has model methods such as `where()`, `create()`, and `include()`, it works on both PostgreSQL and MongoDB, and it covers everyday reads and writes across your models.
- The **SQL query builder** is at `db.sql`. It has table methods that match SQL, such as `select()`, `innerJoin()`, and `groupBy()`, it is PostgreSQL only, and it returns whatever shape your `select()` asks for, not objects shaped like your models.
- The **pipeline builder** is at `db.query`. It builds MongoDB aggregation pipelines, and it is MongoDB only.

Plus raw SQL and raw commands when none of them fits. See [Raw queries](/orm/reference/raw-queries). For connecting and disconnecting the client, transactions, and prepared statements, see [Transactions and runtime](/orm/reference/transactions-and-runtime).

How a query runs: the ORM client runs when you `await` it. The SQL query builder and the pipeline builder each give you a built query from `.build()`, which you run with `runtime.query(...)`, or with `runtime.execute(...)` for a write that returns no rows. Get `runtime` from `db.runtime()` once and reuse it.

```ts
const runtime = db.runtime();
const admins = await db.orm.public.User.where((u) => u.kind.eq('admin')).all();
const plan = db.sql.public.user.select('id', 'email').where((f, fns) => fns.eq(f.kind, 'admin')).build();
const rows = await runtime.query(plan);
```

`const runtime = db.runtime();` is the PostgreSQL form. On MongoDB the call returns a promise, so there you write `const runtime = await db.runtime();`. The two callbacks differ: the ORM client compares on the column (`u.kind.eq(...)`), and the SQL query builder compares through `fns` (`fns.eq(f.kind, ...)`). `.all()` runs the query and returns every row. It is what replaced `findMany`.

Watch the casing: `User` is the model name and `user` is the table name.

Two different things are both named `query`. `db.query` builds a MongoDB pipeline. `runtime.query(...)` runs a query that has already been built.

## How database differences are documented

Every method on a reference page has the same four parts: Remarks, Options, Return type, and Examples. If a method works differently on PostgreSQL and MongoDB, or exists on only one of them, its Remarks say so.
