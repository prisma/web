This guide helps resolve common issues when working with Prisma Postgres.

## Database unreachable

### Problem

Your application can no longer connect to a database that was working, or queries fail with errors such as `Failed to connect to upstream database`, `Can't reach database server`, or `P6008`.

### Solution

Check these in order:

1. **Status page.** Look for an open incident in your database's region on the [status page](https://www.prisma-status.com). If there is one, the database comes back once the incident is resolved.
2. **Blocks.** Open the workspace in the [Prisma Console](https://console.prisma.io) and look for a banner about the monthly plan limit, the spending limit, or an unpaid invoice. A block stops queries but never deletes data. See [Usage limits and blocks](/console/billing/usage-limits-and-blocks).
3. **Connection limits.** `too many connections` errors or timeouts while acquiring a connection mean your application is over its plan's limit. See [Limits](/postgres/database/limits#connections) and [Connection pooling](/postgres/database/connection-pooling#troubleshooting).

[Availability and maintenance](/postgres/database/availability-and-maintenance) explains each check, what `Failed to connect to upstream database` means, and what to send support if none of them applies.

## The `--db` option is not recognized when running `prisma init`

### Problem

Running the following command fails because the `--db` option is not recognized:

```npm
npx prisma init --db
```

### Cause

This can occur due to npx caching. If you've previously run `npx prisma init`, your machine may be using an outdated cached version that doesn't recognize the `--db` flag because it was only introduced in a later version of Prisma ORM.

### Solution

Explicitly run the Prisma ORM 7 CLI through its `prev` dist-tag:

```npm
npx prisma@prev init --db
```

This runs the latest Prisma ORM 7 CLI, which supports the flag, preventing issues with outdated command syntax.

## Workspace plan limit reached when running `prisma init --db`

### Problem

When running the command:

```npm
npx prisma@prev init --db
```

You may encounter the following error message in your logs:

```
Workspace plan limit reached for feature "Project".
```

### Cause

Your default [workspace](/console/concepts#workspace) project limit has been reached.

### Solution

To resolve this issue, consider the following options:

- Configure a different Workspace as your default, one that has available capacity for additional projects.
- Delete unused projects or databases from your current default Workspace to free up space.
- Ensure that you are logged into the correct account in the Prisma CLI. For more details on authentication and account management, please refer to the [Prisma CLI documentation](/cli/v7/console).
- [Upgrade to a plan](/postgres#billing-and-limits) that supports more projects in your default Workspace.
