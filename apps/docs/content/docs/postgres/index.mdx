[Prisma Postgres](https://www.prisma.io/postgres?utm_source=docs) is managed PostgreSQL 17 with PgBouncer pooling on every plan and daily backups on paid plans, taken only on days the database has activity; host the app next to it on [Prisma Compute](/compute), or connect from any Postgres client.

Prisma Postgres autoscales: there is no instance to size or upgrade, and you pay for operations and storage. Coding agents can create databases, change the schema, run SQL and restore a backup into a new database through the [Prisma MCP server](/ai/tools/mcp-server).

To your application it is a regular PostgreSQL database behind a connection string:

```text no-copy
Your application
      ↓ DATABASE_URL
Prisma Postgres
```

Any PostgreSQL client works: Prisma ORM, `psql`, Kysely, Drizzle, `node-postgres`, or anything else that speaks Postgres.

## Getting started

### 1. Create a database

The fastest way, with no account required:

```npm
npx create-db@latest
```

`create-db` creates a temporary Prisma Postgres database and prints a connection string plus a claim URL. Open the claim URL and claim it with a free Prisma account to keep the database in your workspace. See [create-db](/postgres/npx-create-db) for details. You can also create databases in the [Console](https://console.prisma.io) or with the [Prisma CLI](/cli/postgres) (`npx prisma postgres create`). If your data already lives in a PostgreSQL database on your laptop or another host, [migrate it to Prisma Postgres](/postgres/import-from-existing-database) in three steps: create the database, `pg_dump`, `pg_restore`.

### 2. Copy the connection string

`create-db` prints it once; for an existing database, open it in [Prisma Console](https://console.prisma.io) and click **Connect to your database**. Store it where your app reads configuration:

```text title=".env"
DATABASE_URL="postgres://...@db.prisma.io:5432/postgres?sslmode=require"
```

### Already have a Prisma schema?

If your project already has a `prisma/schema.prisma` file for PostgreSQL (Prisma ORM 7 or earlier), skip the quickstarts and apply your schema to a new database. These steps create the tables, not the rows: to bring existing data from another PostgreSQL database, local or hosted, follow [Import from PostgreSQL](/prisma-postgres/import-from-existing-database-postgresql) instead. Install the project's dependencies first, so `npx prisma` runs the project's Prisma CLI. If `package.json` lists `@prisma/client` but not `prisma`, add `prisma` as a dev dependency at the same version as `@prisma/client`.

1. Create the database and write its connection string to `.env`. `create-db` needs Node.js 20.12 or later; on an older Node.js, create the database in the [Console](https://console.prisma.io) and copy its direct connection string into `.env` instead.

   ```npm
   npx create-db@latest --env .env
   ```

   `--env .env` appends `DATABASE_URL` and `CLAIM_URL` to `.env`. If the file already had either line, delete the older one, so the claim URL you open belongs to the new database. In a Prisma ORM 6 project, also remove `DATABASE_URL` from `prisma/.env` if that file sets it: Prisma ORM 6 stops with an error when both files set the same variable. The connection string uses the direct host, `db.prisma.io`, which is the one migrations need.

2. Point the Prisma CLI at the new database before you run a migration:
   - If the config or the schema's `datasource` block reads another variable for migrations, such as `DIRECT_URL`, set it to the same connection string.
   - If your shell already sets `DATABASE_URL` or that variable, unset it: a value set in the shell is used instead of the one in `.env`.
   - If the project has a `prisma.config.ts` (every Prisma ORM 7 project does), it loads `.env` only when it starts with `import "dotenv/config"`, with `dotenv` installed. Add the line if it is missing ([Prisma Config reference](/orm/v7/reference/prisma-config-reference)).

3. Apply the schema:

   ```npm
   npx prisma migrate deploy
   ```

   `migrate deploy` applies the migrations in the project's migrations folder that the database has not run yet: `prisma/migrations`, unless `prisma.config.ts` sets another `migrations.path`. It applies nothing else, so if the schema has changes that no migration contains yet, create that migration first with `npx prisma migrate dev` against a development database. If the project has never used Prisma Migrate and has no migrations folder, `npx prisma db push` creates the tables from the schema instead.

Before the database serves production traffic:

- Open `CLAIM_URL` and claim the database with a free Prisma account. Unclaimed databases are deleted after 24 hours.
- Give the app the pooled connection string in `DATABASE_URL`, and put the direct one in a separate variable, such as `DIRECT_URL`, that the Prisma CLI reads for migrations. Migrations through the pooler can fail with lock or prepared-statement errors ([Recommended setups](/postgres/database/connecting-to-your-database#recommended-setups)).
- Pick a plan with backups: daily backups are kept for 7 days on Starter and Pro and for 30 days on Business. The Free plan has no backups.

## What's included

Each Prisma Postgres database includes the following, with no extra services to configure:

- **Connection pooling**: a dedicated PgBouncer instance runs alongside your database, with nothing to set up or manage. It also works for serverless and edge deployments. See [Connection pooling](/postgres/database/connection-pooling).
- **Edge and serverless support**: connect from Cloudflare Workers, Vercel Functions on the Edge runtime, and other edge runtimes via the [serverless driver](/postgres/database/serverless-driver), which uses HTTP instead of TCP.
- **Automated backups** (Starter, Pro, and Business plans): daily snapshots, taken only on days the database has activity, kept for 7 or 30 days depending on the plan. The Console restores one in place, keeping the connection strings, or into a new database; the Prisma CLI and the REST API's restore endpoint restore in place, and the REST API and the MCP server can also restore into a new database. Point-in-time recovery is coming in November 2026. See [Backups](/postgres/database/backups).

## Use with the rest of Prisma

Each integration is optional, and Prisma Postgres works with any PostgreSQL client.

- If you use [Prisma ORM](/prisma-orm), the quickstart provisions a database and connects it to your data contract.
- If you deploy on [Prisma Compute](/compute), each branch of a Compute project can have its own Prisma Postgres database; pass the connection string through [environment variables](/compute/environment-variables).
- For a multi-service application, [Prisma Composer](/composer/databases) declares a database as a service dependency and injects the connection at runtime.

## Technical details

Prisma Postgres is based on **PostgreSQL v17** and uses a unikernel-based architecture.

Learn more: [Prisma Postgres: Building a modern PostgreSQL service](https://pris.ly/ppg-early-access?utm_source=docs).
