Prisma Postgres supports standard [PostgreSQL extensions](https://www.postgresql.org/docs/current/sql-createextension.html). Extensions add functionality such as vector search, full-text search, fuzzy matching, and cryptographic functions to your database.

## Enabling an extension

Enable any [supported extension](#supported-extensions) using standard SQL:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

This works from any PostgreSQL client: `psql`, a GUI like TablePlus, a migration file, or a raw SQL query from your application.

The `plpgsql` extension is enabled by default on all Prisma Postgres instances.

## Using extensions with Prisma ORM

Prisma ORM doesn't natively support all extension types yet. For extensions that introduce custom types (like `vector` from pgvector), you can use [customized migrations](/orm/v7/prisma-migrate/workflows/customizing-migrations) and [raw SQL](/orm/v7/prisma-client/using-raw-sql) or [TypedSQL](/orm/v7/prisma-client/using-raw-sql/typedsql) to work with them.

The following walkthrough uses pgvector as an example.

### 1. Create an empty migration

```npm
npx prisma migrate dev --name add-pgvector --create-only
```

The `--create-only` flag creates the migration file without applying it, so you can add custom SQL first.

### 2. Add the extension and table to your migration

Edit the generated migration file to enable the extension and create your table:

```sql
-- prisma/migrations/<timestamp>-add-pgvector/migration.sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE "Document" (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  embedding VECTOR(4) -- dimensions depend on your embedding model
);
```

### 3. Apply the migration

```npm
npx prisma migrate deploy
```

### 4. Pull the table into your Prisma schema

Introspect your database to update your Prisma schema with the new table:

```npm
npx prisma db pull
```

Because Prisma ORM doesn't natively support the `VECTOR` type, it will be represented as [`Unsupported`](/orm/v7/prisma-schema/data-model/models#unsupported-types):

```prisma
model Document {
  id        Int                    @id @default(autoincrement())
  title     String
  embedding Unsupported("vector")?
}
```

### 5. Query with raw SQL

Use `$executeRaw` or `$queryRaw` to interact with extension-specific types:

```ts
await prisma.$executeRaw`
  INSERT INTO "Document" (title, embedding)
  VALUES ('My Title', '[1,22,1,42]'::vector)
`;
```

You can also use [TypedSQL](/orm/v7/prisma-client/using-raw-sql/typedsql) for type-safe queries.

## PostGIS is not supported

Prisma Postgres does not support PostGIS, and `CREATE EXTENSION postgis` fails. There is no release date for PostGIS support yet.

For distance and radius queries on latitude and longitude, use the supported [`cube`](https://www.postgresql.org/docs/current/cube.html) and [`earthdistance`](https://www.postgresql.org/docs/current/earthdistance.html) extensions instead. Enable both, since `earthdistance` depends on `cube`:

```sql
CREATE EXTENSION IF NOT EXISTS cube;
CREATE EXTENSION IF NOT EXISTS earthdistance;
```

This example finds places within 5 km of a point. It assumes a `"Place"` table with `latitude` and `longitude` columns of type `double precision`:

```ts
const lat = 48.8566;
const lng = 2.3522;
const radiusInMeters = 5000;

const places = await prisma.$queryRaw`
  SELECT id, name
  FROM "Place"
  WHERE earth_box(ll_to_earth(${lat}, ${lng}), ${radiusInMeters}) @> ll_to_earth(latitude, longitude)
    AND earth_distance(ll_to_earth(${lat}, ${lng}), ll_to_earth(latitude, longitude)) < ${radiusInMeters}
`;
```

`earth_box` narrows the search with a bounding box, and `earth_distance` keeps only the rows inside the exact radius. To make the bounding-box check fast on large tables, add an index:

```sql
CREATE INDEX place_location_idx ON "Place" USING gist (ll_to_earth(latitude, longitude));
```

`earthdistance` treats the Earth as a perfect sphere, so distances are approximate. It doesn't cover polygons, geometry types, or spatial joins, which need PostGIS.

## Limitations

- **Prisma Studio** does not support tables that use custom types from extensions (e.g., `VECTOR`). Queries against those tables will return a deserialization error.
- **Prisma ORM** does not natively support all extension types. Custom types are represented as [`Unsupported`](/orm/v7/prisma-schema/data-model/models#unsupported-types) in your schema and must be queried with [raw SQL](/orm/v7/prisma-client/using-raw-sql).
