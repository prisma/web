Prisma is one stack for data-backed TypeScript applications. [Prisma Next](/next) is the data layer, the next major version of Prisma ORM in Early Access that becomes Prisma 8 at general availability. [Prisma Postgres](/postgres) is the managed database. [Prisma Compute](/compute) is the hosting that runs your app next to that database. Each piece works on its own, but they are built as one journey:

1. **Scaffold with [Prisma Next](/next)**, picking a framework template.
2. **Create or connect [Prisma Postgres](/postgres)** at the database prompt.
3. **Deploy with [Prisma Compute](/compute)**, currently in Public Beta, and get a live URL.

:::note

Building for production on the current generally available release? [Prisma 7](#using-prisma-7) is below. `npx prisma@latest init` installs Prisma 7.

:::

## Quick setup

About 5 minutes. One command scaffolds the app, wires the data layer, and can provision Prisma Postgres for you:

```npm
npx create-prisma@next
```

Pick a framework template, then pick Prisma Postgres at the database prompt or paste your own connection string. From the generated project directory:

```npm
npm run db:init
npm run db:seed
npm run dev
```

:::note

If `db:seed` fails with `Cannot read properties of undefined (reading 'where')`, the template generated the older unqualified query form. Change `db.orm.User` to `db.orm.public.User` in the files under `src/prisma/` and in the app routes, then rerun.

:::

When the app runs locally, put it on a live URL. The `--env .env` flag passes your `DATABASE_URL` to the deployment. If you picked the Next.js template, set `output: "standalone"` in `next.config.ts` first:

```npm
npx @prisma/cli@latest app deploy --env .env
```

## Use with your agent

Prefer to delegate? Copy this prompt, replace the placeholders, and hand it to your coding agent. The scaffold installs [Prisma Next skills](/ai/tools/skills) into `.claude/skills/` and `.agents/skills/`, so your agent has current, project-level guidance from the first step.

```text
Create a new [framework] application with Prisma Next, seed it, and run it locally.

1. Scaffold the app: `npx create-prisma@next create my-app --template [next|hono|nuxt|astro|nest|svelte|tanstack-start|elysia] --provider postgres --prisma-postgres --yes`. The `--prisma-postgres` flag provisions a Prisma Postgres database. If I give you a connection string, pass `--database-url "<url>"` instead of `--prisma-postgres`.
2. From the project directory, apply the starter contract and seed: `npm run db:init`, then `npm run db:seed`. If seeding fails with `Cannot read properties of undefined (reading 'where')`, change `db.orm.User` to `db.orm.public.User` everywhere under `src/` and rerun.
3. Edit the starter contract under `src/prisma/` into a small schema for my use case, then plan and apply the migration: `npx prisma-next migration plan`, then `npx prisma-next migrate`.
4. Update the seed script and the app routes to query the new schema, run `npm run dev`, and verify with a request against the running app.
5. Deploy with Prisma Compute. For the Next.js template, first set `output: "standalone"` in `next.config.ts` (without it the deployed app returns 504s). Check `npx @prisma/cli@latest auth whoami`. If I am not signed in, stop and ask me to run `npx @prisma/cli@latest auth login`, because that step opens a browser. Then run `npx @prisma/cli@latest app deploy --env .env` so DATABASE_URL reaches the deployment, and confirm the deployed URL responds.

Use the installed Prisma Next skills and the current Prisma docs: https://www.prisma.io/docs/llms.txt (append `.md` to any docs URL for a markdown version).
```

## More setup paths

Each path has a guide to follow and a prompt to hand to your agent.

<Accordions>

<Accordion title="Add Prisma to an existing project">

Follow the guide: [Add Prisma Next to an existing PostgreSQL project](/next/add-to-existing-project/postgresql) (or [MongoDB](/next/add-to-existing-project/mongodb)).

Or hand it to your agent:

```text
Add Prisma Next to this existing project.

1. Run `npx prisma-next@latest init`. It writes `prisma-next.config.ts`, a starter contract and `db.ts` under `src/prisma/`, and installs Prisma Next skills for you.
2. Set `DATABASE_URL` in `.env` to my database. If I did not give you one, create a Prisma Postgres database with `npx create-db@latest` and use its connection string.
3. If the database already has tables, infer the contract from it: `npx prisma-next contract infer`, then `npx prisma-next contract emit`, then sign it with `npx prisma-next db sign`. If the database is empty, keep the starter contract and run `npx prisma-next db init`.
4. Write one query with the generated `db` client in an existing code path and verify it runs.

Follow https://www.prisma.io/docs/next/add-to-existing-project/postgresql.md and the installed Prisma Next skills.
```

</Accordion>

<Accordion title="Use your own PostgreSQL database">

Prisma Next works with any PostgreSQL database, not only Prisma Postgres. Follow the [PostgreSQL quickstart](/next/quickstart/postgresql) and paste your connection string at the database prompt.

Or hand it to your agent:

```text
Create a new [framework] application with Prisma Next against my existing PostgreSQL database.

1. Scaffold: `npx create-prisma@next create my-app --template [framework] --provider postgres --database-url "<my connection string>" --yes`.
2. From the project directory: `npm run db:init`, then `npm run db:seed`, then `npm run dev`, and verify the sample query returns data. If seeding fails with `Cannot read properties of undefined (reading 'where')`, change `db.orm.User` to `db.orm.public.User` everywhere under `src/` and rerun.
3. Evolve the starter contract under `src/prisma/` into my schema, then `npx prisma-next migration plan` and `npx prisma-next migrate`.

Do not provision any hosted database. Use the installed Prisma Next skills and https://www.prisma.io/docs/llms.txt for current docs.
```

</Accordion>

<Accordion title="Prisma ORM only">

Use Prisma ORM without the rest of the stack. For the generally available version, follow the [Prisma 7 quickstart](/prisma-orm/quickstart/prisma-postgres); for the Early Access version, follow the [Prisma Next quickstart](/next/quickstart/postgresql).

Or hand it to your agent (Prisma 7, the command below installs Prisma 7, not Prisma Next):

```text
Add Prisma ORM 7 to this project with my existing database.

1. Run `npx prisma@latest init` (Prisma 7). For an existing database, set DATABASE_URL in `.env` and introspect it with `npx prisma db pull`; for a new schema, define models in `prisma/schema.prisma` and run `npx prisma migrate dev --name init`.
2. Generate the client with `npx prisma generate` and write one query in an existing code path.
3. Verify the query runs, then show me the schema and the query you added.

Current docs: https://www.prisma.io/docs/orm.md and https://www.prisma.io/docs/llms.txt.
```

</Accordion>

<Accordion title="Prisma Postgres only">

Prisma Postgres works with any ORM or driver. Follow the [database quickstarts](/prisma-postgres/quickstart/prisma-orm) for Prisma ORM, Kysely, Drizzle, or TypeORM.

Or hand it to your agent:

```text
Create a Prisma Postgres database for this project.

1. Run `npx create-db@latest`. It creates a temporary Prisma Postgres database without an account and prints a connection string plus a claim URL.
2. Put the connection string in `.env` as DATABASE_URL and wire it into my existing setup ([Prisma ORM|Kysely|Drizzle|TypeORM|node-postgres]).
3. Remind me to open the claim URL to keep the database in my Prisma workspace.

Current docs: https://www.prisma.io/docs/postgres.md.
```

</Accordion>

<Accordion title="Prisma Compute only">

Deploy an app you already have, with or without a database. Follow [Deploy your first app](/prisma-compute/deploy).

Or hand it to your agent (sign in first with `npx @prisma/cli@latest auth login`):

```text
Deploy this app to Prisma Compute using `npx @prisma/cli@latest`.

1. Confirm I am signed in with `npx @prisma/cli@latest auth whoami`; if not, stop and ask me to run `npx @prisma/cli@latest auth login`.
2. Run `npx @prisma/cli@latest app deploy` from the project directory. Add `--db` if the app needs a database; Compute provisions Prisma Postgres and wires the connection string.
3. Open the deployed URL and confirm the app responds. Use `npx @prisma/cli@latest app logs` if it does not.

Current docs: https://www.prisma.io/docs/prisma-compute/deploy.md.
```

</Accordion>

</Accordions>
