## Use with your agent

If you are creating a new app, you can hand the work to your coding agent instead. Copy this prompt and give it to your agent. You can replace `[framework]` with one of the template names listed in the prompt, or leave it, and the agent asks you which one you want. The prompt uses PostgreSQL:

<AgentPrompt>

```text
Create a new [framework] application with Prisma ORM, seed it, and run it locally.

If I have not told you which framework, stop and ask before scaffolding. Valid --template values: minimal (the default), next, hono, nuxt, astro, nest, svelte, tanstack-start, elysia, turborepo (a monorepo: the server is in apps/server, and the contract, seed and database client are in packages/database/src).

Check the Node.js version first: `node --version` must print 22.18 or newer on the 22 line, 24.11 or newer on the 24 line, or 26 or newer. For the nuxt template, it must print 22.22.3 or newer on the 22 line, 24.15 or newer on the 24 line, or 26 or newer, because Nuxt requires it. The npm that ships with your Node.js release works; on Node.js 22 that is npm 10.

1. Scaffold the app: `npm create prisma@latest -- my-app --template [framework] --provider postgres --yes`.
2. Get a database connection string: use the one I give you, or create a Prisma Postgres database with `npx create-db@latest` and show me the claim URL it prints. Export it as `DATABASE_URL` in the shell: in a project created with `npm create prisma`, the Prisma CLI scripts in package.json read the environment variable, not `.env`.
3. From the project directory, apply the starter contract: `npm run db:init`. The app seeds sample users on its first query, from `src/prisma/seed.ts` (`packages/database/src/seed.ts` for turborepo); there is no seed command to run.
4. Edit the starter contract under `src/prisma/` (`packages/database/src/` for turborepo) into a small schema for my use case, then run `npm run contract:emit` and plan and apply the migration: `npx prisma migration plan --name <name>`, then `npx prisma db migrate --yes`. Migration planning diffs the emitted contract, so the emit step is required. `db migrate` also points the `db` ref at the state you applied, so that the next `migration plan` starts from there. If it prints `MIGRATION.REF_NOT_ADVANCED_IN_CI`, the CLI found a CI variable such as `CI` in your environment and left the ref unchanged: run the command that the notice prints for a development machine, which adds `--advance-ref db`, before you plan again.
5. Update `src/prisma/seed.ts` (`packages/database/src/seed.ts` for turborepo) and the app routes to query the new schema, start `npm run dev` in the background (with `DATABASE_URL` exported), and verify with a request against the running app. For the `nest` template, if routes return 500s with `reading 'findAll'` in the logs, add explicit `@Inject()` tokens as shown in https://www.prisma.io/docs/guides/frameworks/nestjs.md.

Use the installed Prisma ORM skills and the current Prisma docs: https://www.prisma.io/docs/llms.txt (append `.md` to any docs URL for a markdown version).
```

</AgentPrompt>
