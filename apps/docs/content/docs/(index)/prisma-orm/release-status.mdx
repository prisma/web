Prisma ORM 8 is a **release candidate**. You can install it and build with it today. Until the final release, some details of the API may still change, so code you write now may need small edits later. Each release candidate fixes bugs found in the previous one.

## When the final release is expected

General availability is expected in October 2026.

## What happens to Prisma ORM 7

Prisma ORM 7 keeps receiving bug fixes and security updates for 18 months from the day Prisma ORM 8 reaches general availability. Its documentation stays at [/orm/v7](/orm/v7).

## What you get when you install today

Prisma ORM 8 is two packages: the command-line tool, and a library your app imports that is named for your database.

```npm
npm install --save-dev prisma
npm install @prisma/orm-postgres
```

For MongoDB the library is `@prisma/orm-mongo`, and for SQLite it is `@prisma/orm-sqlite`. MySQL is not supported yet.

The two packages have different version numbers, and that is normal: they are released separately, and the command-line tool gets more frequent releases.

| Package | Version today |
| --- | --- |
| `prisma` (the command-line tool) | `8.0.0-rc.13` |
| `@prisma/orm-postgres` (the library) | `8.0.0-rc.9` |

Versions were checked on 11 September 2026; run `npm view prisma version` for today's.

`@prisma/client`, the library that Prisma ORM 7 apps import, stays at `7.10.0`. It belongs to Prisma ORM 7 and is not part of Prisma ORM 8.

:::warning[If you have a Prisma ORM 7 project]

`npm install prisma` and `npx prisma` now give you the Prisma ORM 8 command-line tool. It does not read `schema.prisma` and has no `generate`, `migrate dev`, or `db push` commands. If your project is on Prisma ORM 7, lock the version as shown below. If you have already installed version 8 by accident, lock the version in `package.json` and run `npm install` again; that puts version 7 back.

:::

## How to stay on Prisma ORM 7

Lock both packages to version 7 in `package.json`:

```json title="package.json"
{
  "devDependencies": {
    "prisma": "^7"
  },
  "dependencies": {
    "@prisma/client": "^7"
  }
}
```

Anywhere you run the tool without a locked version, for example in CI or in a one-off command, write `npx prisma@7` instead of `npx prisma`.

The Prisma ORM 7 documentation is at [/orm/v7](/orm/v7), its setup guides at [/v7/getting-started](/v7/getting-started), and its command reference at [/cli/v7](/cli/v7).

## How to try Prisma ORM 8 in an existing app

You do not have to switch all at once. You can keep `@prisma/client` (version 7) and add `@prisma/orm-postgres` (version 8) to the same project, pointed at the same database. Code you have not touched keeps using the version 7 client; code you move uses the version 8 one.

- [Migrate from Prisma ORM 7 to 8](/guides/upgrade-prisma-orm/postgresql) walks through that step by step on PostgreSQL.
- [Coming from Prisma ORM 7](/orm/coming-from-prisma-orm-7) shows what each Prisma ORM 7 command and query is called now, and which features are not available yet.
