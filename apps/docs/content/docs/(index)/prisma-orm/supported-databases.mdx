Prisma ORM 8 ships one library per database. Today there are two you can build on.

| Database | Status | Library |
| --- | --- | --- |
| PostgreSQL, including Prisma Postgres | Release candidate | `@prisma/orm-postgres` |
| MongoDB | Early access | `@prisma/orm-mongo` |
| MySQL | Coming soon | |
| MariaDB | Coming soon | |
| SQLite | Coming soon | |
| Microsoft SQL Server | Coming soon | |
| CockroachDB | Coming soon | |

## What the labels mean

**Release candidate.** Install it and build with it today. Until the final release, some details of the API may still change, so code you write now may need small edits later. Each release candidate fixes bugs found in the last one. [Release status](/prisma-orm/release-status) has the dates and what `npm install` gives you.

**Early access.** The library works and you can build with it, but some of what the PostgreSQL library does is not there yet. The reference pages say on each method whether it works on MongoDB, and [what is not available yet](/orm/coming-from-prisma-orm-7#not-available-yet) lists the gaps. Report what you hit on [GitHub](https://github.com/prisma/orm/issues).

**Coming soon.** There is no Prisma ORM 8 library for the database yet. Prisma ORM 7 supports it, and Prisma ORM 7 keeps receiving bug fixes and security updates for 18 months after Prisma ORM 8 reaches general availability. [How to stay on Prisma ORM 7](/prisma-orm/release-status#how-to-stay-on-prisma-orm-7) shows how to lock the version.

## How to ask for a database

Add a 👍 to the GitHub issue for the database you need, or open one if there is none. The number of reactions is one of the inputs to what gets built next. Organizations that need a database sooner can talk to [Prisma enterprise support](https://www.prisma.io/enterprise).
