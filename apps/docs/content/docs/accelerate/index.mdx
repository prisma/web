## Accelerate retirement: your options [#retirement-options]

Prisma Accelerate in front of your own database, PostgreSQL or not, will be retired on December 1, 2026. If your database can move to PostgreSQL, we recommend moving it to Prisma Postgres: it pools connections on every plan, so one service replaces Accelerate's pooling and runs the database. Hosted Accelerate connections for Prisma Postgres keep working after that date, so you have more time to move off them. We'll give at least 30 days' notice before a new cutoff, and you can switch now. Accelerate did two jobs: it pooled database connections and it cached query results. The table below shows how to move, by where your database runs today. The caching has no drop-in replacement: Prisma Postgres has no query cache, and query caching is not on our immediate roadmap. Each migration guide in the table removes the Accelerate extension and its caching APIs, such as `cacheStrategy`, from your app.

| Your database today | What replaces Accelerate | Should you move to Prisma Postgres? |
| --- | --- | --- |
| Prisma Postgres, through a `prisma+postgres://accelerate.prisma-data.net` URL | A pooled TCP connection to the same database, or the [serverless driver](/postgres/database/serverless-driver) on edge runtimes | You are already on it. Your data stays where it is, and you change how the app connects: [Connect to Prisma Postgres without Accelerate](/postgres/database/switch-from-accelerate) |
| PostgreSQL on a host that pools connections on every plan, such as Neon or Supabase | Prisma Postgres, or your host's pooled connection string | Yes, we recommend it. Prisma Postgres pools connections on every plan, and an app on [Prisma Compute](/compute) can run next to it in one project, on one bill. Move [from Neon](/guides/switch-to-prisma-postgres/from-neon) or [from Supabase](/guides/switch-to-prisma-postgres/from-supabase). To stay where you are, use your host's pooled connection string: [keep your database](/accelerate/keep-your-database) |
| PostgreSQL with no pooler, such as a self-hosted server | Prisma Postgres, which includes PgBouncer pooling on every plan, or a pooler you add in front of your database | Yes, we recommend it. [Import from PostgreSQL](/prisma-postgres/import-from-existing-database-postgresql) moves a database on PostgreSQL 9.5 to 17 with `pg_dump` and `pg_restore`, then removes Accelerate from your app; it does not cover PostgreSQL 18. To stay, add a pooler in front of your database or, for a long-running server that stays within the database's connection limit, [connect directly](/accelerate/keep-your-database#1-choose-how-your-application-will-connect) |
| MySQL, MariaDB, MongoDB or CockroachDB | Prisma Postgres if you can move to PostgreSQL, or a direct or pooled connection string from your provider | If you can move to PostgreSQL, yes. With writes to MySQL stopped until your app points at Prisma Postgres, [Import from MySQL](/v7/prisma-postgres/import-from-existing-database-mysql) moves the data with `pgloader`. Then follow steps 1 to 4 of [Keep your database](/accelerate/keep-your-database#1-choose-how-your-application-will-connect) with your Prisma Postgres connection strings, choosing the PostgreSQL driver adapter in step 3. MariaDB, MongoDB and CockroachDB have no import guide. Otherwise, [keep your database](/accelerate/keep-your-database) |

If you use Accelerate with your own database and it can move to PostgreSQL, we recommend moving to Prisma Postgres.

The Prisma Postgres Free plan includes 2 GB of storage per workspace and needs no credit card; daily backups start on the Starter plan. Prisma ORM 8 does not use hosted Accelerate, so a project on Prisma ORM 8 has nothing to switch. Neon and Supabase details checked on 2026-11-26.

## How Accelerate works

[Prisma Accelerate](https://www.prisma.io/accelerate) is a managed connection pool and global cache for your database. It works with Prisma ORM and supports PostgreSQL, MySQL, MongoDB, and more.

Prisma ORM supports connection pooling and query caching through Accelerate, so you don't need a separate pooler or caching layer. [Prisma Postgres](/postgres) includes connection pooling. Query caching is not supported by Prisma Postgres and is not on our immediate roadmap.

**Connection pooling.** Accelerate manages a global connection pool across 15+ regions. This matters most in serverless and edge environments, where connection exhaustion is a real failure mode. Prisma ORM routes through the pool automatically once you swap in the Accelerate connection string.

**Query caching.** Add a `cacheStrategy` to any Prisma ORM query to cache results at the edge using TTL or stale-while-revalidate. Results are served from 300+ cache locations, so you don't need Redis, Memcached, or a separate caching service.

```typescript title="src/lib/posts.ts"
const posts = await prisma.post.findMany({
  cacheStrategy: { ttl: 60, swr: 10 }, // serve from cache for 60s (TTL); after TTL expires, serve stale for up to 10s while revalidating in the background (SWR)
})
```

## Supported databases

Accelerate works with the database you already have, whether it is publicly accessible, or via an IP allowlist.

- PostgreSQL
- MySQL
- MariaDB
- PlanetScale
- CockroachDB
- MongoDB
