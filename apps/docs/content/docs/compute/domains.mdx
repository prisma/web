Configure custom domains for apps on [production, preview, or staging branches](/compute/branching). Each domain routes to the live deployment of the app on the selected branch.

## Before you start

You'll need:

- A [linked project](/compute/getting-started).
- An app with a [promoted, running deployment](/compute/deployments).
- Access to edit DNS records within your DNS provider.

Domain commands default to the production branch. To manage domains on another branch, pass `--branch <name>` to each command. See the [`service domain` reference](/cli/service#service-domain) for selectors and flags.

## Add a custom domain

### 1. Add a domain

```npm
npx prisma service domain add shop.acme.com --service web
```

For a staging branch, use:

```npm
npx prisma service domain add staging.acme.com --service web --branch staging
npx prisma service domain wait staging.acme.com --service web --branch staging
```

In Console, select the branch and open the app's **Domains** page. Choose **Add domain**, enter the hostname, and continue to see the CNAME and workspace TXT records.

Registration verifies ownership before creating a domain or requesting a certificate. If the TXT record is missing, the CLI returns `SERVICE.DOMAIN_OWNERSHIP_REQUIRED` and prints the exact record name and value. Create it, then rerun the suggested command. Re-running `add` for a hostname that's already attached is safe: it shows the existing domain without requiring a new verification step.

### 2. Add the TXT and CNAME records

Add the TXT record shown by Console or the CLI. Its value belongs to your workspace. Use the exact value provided; the example below is a placeholder.

Also add the routing CNAME, which points at `switchboard.{region}.prisma.build`. If it is not configured yet, `add` returns a DNS error with the CNAME instructions after ownership verification succeeds.

| Type | Name | Value | TTL |
| --- | --- | --- | --- |
| TXT | `_prisma-verification.shop.acme.com` | `prisma-verification=<your-workspace-token>` | 300 |
| CNAME | `shop.acme.com` | `switchboard.cdg.prisma.build` | 300 |

If your provider expects names relative to the `acme.com` zone, use `_prisma-verification.shop` for TXT and `shop` for CNAME. Keep the TXT record: it lets this workspace reconnect the hostname after an app or branch is recreated. Another workspace needs a different value.

:::note[Cloudflare DNS]

Set the hostname's **Proxy status** to **DNS only** (gray cloud) while connecting
the domain. A proxied record returns Cloudflare's IP addresses, which prevents
Prisma from verifying the routing target. If Prisma detects this, Console and the
CLI show instructions to turn the proxy off and retry.

After Prisma shows the domain as **Active**, you can turn **Proxied** (orange
cloud) back on to use Cloudflare's CDN. Keep the CNAME target and TXT proof in
place, and use **Full (strict)** SSL/TLS mode.

Prisma renews certificates through HTTP validation. Ensure requests to
`/.well-known/acme-challenge/*` reach Prisma without caching, security challenges,
or rules that rewrite the response. If you reconnect the domain after removing
it or recreating a branch, switch back to **DNS only** for verification. Manual
provisioning retries also check DNS again.

See Cloudflare's [proxy status](https://developers.cloudflare.com/dns/proxy-status/)
and [Full (strict) TLS](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/)
documentation for these settings.

:::

:::note[What is switchboard?]

Switchboard is the routing layer that sits in front of your Compute app. Switchboard verifies the domain, provisions and terminates TLS, then forwards traffic to your app.

:::

### 3. Re-run `add`, then wait for provisioning

Once both DNS records have propagated, choose **Verify and connect** in Console or rerun the same `service domain add` command, including its branch selector. Registration then starts TLS provisioning. Track it with:

```npm
npx prisma service domain wait shop.acme.com --service web
```

`wait` polls until the domain is active, up to 15 minutes. For a single status check, use `--timeout 0`:

```npm
npx prisma service domain wait shop.acme.com --service web --timeout 0 --json
```

A single check exits non-zero with `DOMAIN_VERIFICATION_TIMEOUT` while the domain is still provisioning, so automation should read the status event rather than the exit code. In `--json` mode, `wait` streams newline-delimited status events, so an agent can track provisioning as it progresses.

## Remove a domain

```npm
npx prisma service domain delete shop.acme.com --service web
```

Removing detaches the domain from the app. For a non-interactive run, pass `--confirm shop.acme.com`. Prisma cannot change your DNS. Keep the TXT record if you plan to reconnect the hostname in this workspace; remove both DNS records once you no longer need them.

Existing connected domains keep serving without adding TXT immediately. A new attachment after removal or branch deletion requires the workspace proof, even when the old CNAME still points at Prisma.

## States

A domain moves through these states:

| Status             | Meaning                                                         |
| ------------------ | --------------------------------------------------------------- |
| `pending_dns`      | The domain is registered; TLS provisioning hasn't started yet   |
| `provisioning_tls` | The TLS certificate is being issued                             |
| `active`           | The domain is fully provisioned and routing traffic to your app |
| `failed`           | Registration or provisioning failed; see the failure reason     |

## Limits

- Routing uses a CNAME, and new attachments require a workspace TXT proof. Apex domains need a DNS provider that supports CNAME-like records (ALIAS, ANAME, or CNAME flattening) at the apex.
- Wildcard hostnames such as `*.acme.com` are rejected.
- Up to 3 custom domains per app. Adding more returns `DOMAIN_QUOTA_EXCEEDED`.
- There's no workspace-wide domain list in the CLI.

## Troubleshooting

```npm
npx prisma service domain show shop.acme.com --service web
npx prisma service domain retry shop.acme.com --service web
```

`show` prints the exact state, certificate details, and any DNS hints. `retry` restarts stuck provisioning. If a domain isn't in a retryable state, it returns `DOMAIN_RETRY_NOT_ELIGIBLE`.
