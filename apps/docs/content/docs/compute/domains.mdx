Configure custom domains that point to your [production app](/compute/branching). You can't configure custom domains for preview apps.

A domain serves your app once three things are true: your workspace has proved it owns the domain, the domain's DNS points at Prisma, and a TLS certificate has been issued. You do the first two by publishing DNS records. The platform does the third.

## Before you start

You'll need:

- A [linked project](/compute/getting-started).
- A production app. You can add a domain before the app has a [promoted, running deployment](/compute/deployments); the domain starts serving once it has one.
- Access to edit DNS records within your DNS provider.

Domain commands target the [production branch](/compute/branching). Pointing them at any other branch fails with a `BRANCH_NOT_DEPLOYABLE` error. Every domain subcommand also accepts `--project` and `--branch` flags.

## Add a custom domain

### 1. Add the domain

```npm
npx prisma service domain add shop.acme.com --service web
```

The command succeeds before any DNS is set up. It prints the domain's state, what it is waiting on, and the DNS records to publish:

```text
hostname    shop.acme.com
status      pending
state       not_verified
waiting on  Proof in DNS that this workspace owns the domain.
dns TXT     _prisma-verification.shop.acme.com -> prisma-verification=3f9a… (ttl 300)
dns CNAME   shop.acme.com -> switchboard.cdg.prisma.build (ttl 300)
```

Re-running `add` for a domain the app already has is safe: it shows the existing domain with its current state.

### 2. Publish the DNS records

Add both records at your DNS provider.

| Type  | Name                                 | Value                          | TTL | What it does                               |
| ----- | ------------------------------------ | ------------------------------ | --- | ------------------------------------------ |
| TXT   | `_prisma-verification.shop.acme.com` | `prisma-verification=3f9a…`    | 300 | Proves your workspace owns the domain      |
| CNAME | `shop.acme.com`                      | `switchboard.cdg.prisma.build` | 300 | Points the domain at `switchboard.{region}.prisma.build` |

The CLI prints each record name as a full hostname. If your DNS provider expects a relative name, enter just the labels before your domain (`shop` and `_prisma-verification.shop`).

The TXT value is the same for every domain in your workspace. Keep the TXT record in place after the domain is live: if it disappears, the domain keeps serving for about 30 days and then stops.

:::note[What is switchboard?]

Switchboard is the routing layer that sits in front of your Compute app. Switchboard terminates TLS, then forwards traffic to your app.

:::

### 3. Wait until the domain serves

```npm
npx prisma service domain wait shop.acme.com --service web
```

`wait` blocks until the domain's state is `active`, up to 15 minutes (`--timeout` changes that). While the domain is waiting for your DNS records, `wait` asks the platform to look them up again every 30 seconds, so you can start it before the records have propagated.

For a single read of the state, use `--timeout 0`:

```npm
npx prisma service domain wait shop.acme.com --service web --timeout 0 --json
```

A single read exits non-zero with `SERVICE.DOMAIN_VERIFICATION_TIMEOUT` while the domain is not yet active, so automation should read the status event rather than the exit code. In `--json` mode, `wait` streams newline-delimited status events, one per change of state, so an agent can track the domain as it progresses.

## Check a domain

```npm
npx prisma service domain show shop.acme.com --service web
npx prisma service domain retry shop.acme.com --service web
```

`show` prints the domain's state, what it is waiting on, the DNS records still to publish, and the certificate's expiry.

The platform looks your DNS up when you add a domain and when you ask it to, not on a timer. `retry` asks it to check now: it looks the DNS records up again, and if the last certificate failed, it orders a new one. A workspace can order a limited number of new certificates per hour; when that limit is reached, `retry` fails with `SERVICE.DOMAIN_RETRY_RATE_LIMITED` and says when to run it again.

## Remove a domain

```npm
npx prisma service domain delete shop.acme.com --service web
```

Deleting detaches the domain from the app. The command asks you to type the hostname to confirm; pass `--confirm shop.acme.com` to run it without a prompt. Prisma can't touch your DNS, so the records stay behind. Delete the CNAME at your provider once you no longer need it.

## States

A domain reports two fields. `status` is `pending` until the domain has gone live once, then `active`. `state` says what the domain is doing right now:

| State                      | Meaning                                              | What to do                                     |
| -------------------------- | ---------------------------------------------------- | ---------------------------------------------- |
| `not_verified`             | Your workspace has not proved it owns the domain     | Publish the TXT record                         |
| `waiting_for_dns`          | The domain's DNS does not point at Prisma            | Publish the CNAME record                       |
| `no_live_deployment`       | The app has no live deployment                       | Deploy the app, or promote a deployment        |
| `no_service`               | The app the domain pointed at was deleted            | Delete the domain, then add it to another app  |
| `in_use_elsewhere`         | Another app holds the domain                         | Delete the domain from that app                |
| `provisioning_certificate` | The TLS certificate is being issued                  | Nothing                                        |
| `updating`                 | The platform is bringing the domain up to date       | Nothing                                        |
| `certificate_failed`       | The certificate could not be issued                  | Read the platform's reason, then run `retry`   |
| `update_failed`            | The platform's last update failed and is being retried | Nothing, or run `retry` to try again now     |
| `active`                   | The domain serves your app                           | Nothing                                        |

## When a domain fails

When a certificate cannot be issued, the CLI prints the reason the platform reported, exactly as it was given:

```text
failure  Provisioning failed. The platform reported: acme: CAA record for acme.com prevents issuance
```

When the platform gave no reason a user can act on, the CLI says that provisioning failed for reasons it is not sure about, and that you can try again or contact support.

## Limits

- Custom domains are only available on production apps.
- Routing uses CNAME records only. Apex domains need a DNS provider that supports CNAME-like records (ALIAS, ANAME, or CNAME flattening) at the apex.
- Wildcard hostnames such as `*.acme.com` are rejected.
- Up to 3 custom domains per app. Adding more returns `SERVICE.DOMAIN_QUOTA_EXCEEDED`.
- There's no workspace-wide domain list in the CLI.
